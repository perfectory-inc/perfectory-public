## Context

## Decision

1. **자기 작업이 없는 브이월드 파일 데이터셋은 모두 매일 훑기가 받는다.** 엔드포인트 카탈로그의 열네 개
   (`boundary_sido`, `boundary_sigungu`, `boundary_census_emd`, `boundary_census_sido`, `boundary_census_sigungu`,
   `land_ownership`, `land_use_zone`, `real_estate_broker`, `sandan_location`, `sandan_profile`,
   `sandan_facility_land_use`, `sandan_land_use_zone`, `sandan_permitted_industry`, `sandan_parcel`)에
   `"daily_collection": "source_sweep"` 을 단다. 새 장치는 없다 — ADR-0168 의 목록 자리에 줄을 더할 뿐이다. 자기 작업이 받는
   연속지적도(30563)·필지고유번호변동연혁(30527)은 여전히 빠진다(시험 `test_a_dataset_with_its_own_collection_job_is_not_swept_twice`).
   그래서 `vworld_dataset` 25개 중 23개를 훑기가 받는다. 병합되면 켜진 채로 돈다(작업 `source_sweep` 은 이미 `enabled`).
2. **500MB 를 넘는 파일은 RAON 레인 몫이고, 그 예산은 0 그대로다.** 용도지역지구 달마다 3개, 토지소유 도형 판마다 6개가 그렇다.
   ADR-0170 은 감독 실행이 레인을 잰 PR 이 예산을 정한다고 했다. 이 ADR 은 그 측정을 대신하지 않는다 — 운영자 단계로 남긴다
   (Consequences).
3. **토지대장 API(`land_register`)는 수집하지 않는다.** 이 API 는 PNU 하나를 묻는다(`ladfrlList?pnu=`). 전국 필지 약
   3,900만 개를 하나씩 묻는 것은 원천 파일이 있는 한 맞지 않는다(벌크 파일 먼저 — 수집 원칙). 응답의 사실은 이미 파일로 온다:
   지목·면적은 토지특성(D195), 소유구분·공유인수·소유권변동은 토지소유(D161), 이동 사건은 토지이동이력(D157). 그래서 원천 그룹
   상태를 `planned` 에서 `disabled` 로 바꾸고 이유를 적는다. 엔드포인트와 수집기 코드(`vworld_land_register_ingest.rs`)는 남긴다 —
   한 필지를 그 자리에서 확인하는 운영 도구로 쓸 수 있고, 지우는 것은 이 결정의 몫이 아니다.
4. **D154 도형과 D150 DBF 는 Bronze 에 남는다(받기는 계속, Silver 는 없다).**
   - D154 는 D155 행을 필지마다 쉼표로 이은 것 + 필지 경계다. 행은 `silver.land_use_plan` 이, 도형은 필지 경계가 이미 가진다.
     세 번째 사본을 두면 같은 사실이 두 곳에 산다. 지도 위 **규제 경계**는 D154 가 아니라 용도지역지구 도형(NA/24)에서
     온다 — 필지에 맞춰 자른 것이 아니라 고시된 구역 그 자체이기 때문이다(ADR-0362).
   - D150 의 `A0`–`A15` 는 D151 과 같다. `A16`–`A19` 는 제공자가 이름을 지운 숫자이고, 명세 없이 이름을 지어 붙이지 않는다.
     제공자 명세가 그 넷을 이름 지으면 그때 다시 본다.
5. **건물 도형은 이 가족에서 받지 않는다.** 이 카탈로그의 26개 중 건물 도형은 없다. 건물 외곽선의 정본은
   주소정보 전자지도(도로명주소 건물, 원천 가족 C)다 — 브이월드 GIS건물통합정보를 더하면 같은 건물이 두 도형을 갖고, 둘을 맞추는
   일이 생긴다(`the-same-fact-in-two-places-cannot-be-fixed`).
6. **Silver 로 잇는 순서.** 토지소유(ADR-0360 → 0361)와 용도지역지구 도형(ADR-0362)을 먼저 잇는다. 산업단지 시설용지·유치업종·
   용도지역·필지(23–26)는 받기만 하고 Silver 는 후속이다 — 단지 코드로 산업단지 카탈로그에 붙는 일이라 필지 by-PNU 레인과 다른
   길이고, 단지 하나의 행 수가 작아 지금 늦춰도 잃는 것이 없다.

## Consequences

- 다음 매일 훑기가 새 열네 데이터셋 목록을 읽고, Bronze 가 갖지 않은 파일을 전부 받는다(ADR-0172). 계산(측정 아님):
  용도지역지구 7–10월 네 판 약 21GB 중 RAON 몫 12개를 뺀 약 13GB, 토지소유는 원장에 없는 판만, 경계·산업단지·중개사는 1GB 미만.
- **비용(계산, R2 공시가 $0.015/GB-월, 1달러 1,400원).** 이 가족의 지금 Bronze 는 약 309GB = 월 약 6,500원(이미 내고 있다).
  새로 쌓이는 양: 용도지역지구 달마다 약 5.3GB, 토지소유 반년마다 약 10GB(달 평균 약 1.7GB), 나머지 1GB 미만 → 달마다 약 7GB.
  한 해 뒤 월 약 1,800원이 더해진다. 쓰기 요청은 파일 하나에 몇 번이라 무시할 만하다. 원천 하나가 월 5만 원에 한참 못 미친다.
- 토지대장 API 는 쿼터·약관 검토가 필요 없어진다(부르지 않는다).
- **운영자 단계(사장).** RAON 레인의 첫 감독 실행 — 용도지역지구 큰 레이어 3개와 토지소유 도형 6개를 포함해 측정하고 그 PR 이
  `selection_archive_new_bytes_budget` 을 정한다(런북 `provider-acquisition-fargate.md`, ADR-0170). 그 전까지 큰 파일은
  매일 "몇 개·몇 바이트 보류" 로 보고만 된다.
- 지도(`docs/data-pipeline-map.md`)는 그래프에서 다시 그린다. 토지대장 API 는 "예정" 에서 "수집 비활성" 으로 바뀐다.
