# ADR 0009: 한글 정본 문서와 다국어 확장 준비

## 상태

제안. 문서 개편 설계 검토 후 채택한다.

## 배경

모노레포에는 루트·플랫폼·제품·서비스·크레이트에 README와 설계·운영 문서가 흩어져
있다. 같은 기술 설명이 여러 위치에 반복되고, 문서마다 언어·상태·소유자 표시가 달라
현재 구조와 기록을 찾기 어렵다. 먼저 한글을 정본 언어로 통일하되, 이후 다국어 번역을
추가할 때 정본과 번역본의 관계가 깨지지 않아야 한다.

## 결정

### 문서의 역할

- 루트 README는 프로젝트 전체 지도만 제공한다.
- 영역·서비스·독립 패키지 README는 해당 코드의 책임과 진입점만 제공한다.
- 깊은 설명은 `docs/` 또는 해당 영역의 `docs/`에 정본으로 둔다.
- README에는 설계·운영 절차·기술 버전 표를 복사하지 않고 정본 링크를 둔다.

### 문서 분류

- `adr/`: 왜 결정했는지
- `architecture/`: 현재 구조와 경계
- `reference/`, `catalog/`: 조회용 정본과 레지스트리
- `contracts/`, `openapi/`, `schemas/`: 기계가 소비하는 계약
- `guides/`: 개발·기여 방법
- `runbooks/`: 실행·장애·복구 절차
- `records/`: 조사·실행·사고·릴리스의 시간순 사실 기록

ADR은 설계 이유를, architecture는 현재 상태를, guide/runbook은 행동 절차를 소유한다.
`records/`는 이 문서들을 대신하지 않으며 현재 정책의 정본이 아니다.

### 언어

- 사람이 읽는 설명 문서의 정본은 한글(`ko-KR`)로 작성한다.
- 명령어, 코드 블록, API·이벤트 필드, 데이터베이스 컬럼, 패키지명, 환경변수명은
  원래 표기를 유지한다.
- `LICENSE`와 외부 라이선스 전문처럼 법률 원문인 파일은 임의로 번역·삭제하지 않는다.
  같은 위치에 한글 안내를 둘 수 있다.
- 다국어가 필요해지면 `docs/i18n/<locale>/`에 정본과 일대일 대응하는 번역본을 추가한다.
  번역본은 `source`와 `source_revision`으로 정본 버전을 가리킨다.

### 문서 상태와 소유권

정본 문서는 다음 메타데이터를 가진다.

```yaml
status: current | proposed | deprecated | archived
owner: foundation | identity | intelligence | gongzzang | repository-maintainers
doc_type: guide | runbook | architecture | adr | reference | record | catalog
last_reviewed: YYYY-MM-DD
```

`archived` 문서는 역사 보존용이며 현재 동작이나 정책을 설명하는 링크의 목적지가 될 수
없다. 외부 계약·fixture·법률·감사·사고 기록은 참조를 확인하지 않고 삭제하지 않는다.

### 기록

- 설계 결정을 바꾸는 내용은 ADR 또는 RFC로 남긴다.
- 조사·실행 결과는 날짜·범위·결론·근거·후속 작업을 포함해 `records/`에 남긴다.
- 장애 기록은 영향·탐지·완화·근본 원인·재발 방지를 포함한다.
- 릴리스 기록은 버전·변경·검증·롤백 경로를 포함한다.
- 기록은 현재 정본을 복사하지 않고 정본 문서에 링크한다.

## 이행 순서

1. 추적된 문서를 영역·유형·언어·상태·참조 여부로 목록화한다.
2. 정본 경로를 지정하고 중복·고립·폐기 후보를 분류한다.
3. 루트와 영역 지도를 먼저 한글 정본으로 정리한다.
4. architecture·reference·guide·runbook을 번역하고 중복 내용을 링크로 치환한다.
5. 조사·실행·장애·릴리스 기록을 정해진 형식으로 추가한다.
6. 메타데이터·링크·색인·번역 관계를 CI에서 검사한다.

## 완료 기준

- 사람이 읽는 문서마다 소유자·유형·상태·최종 검토일이 있다.
- 정책·구조·절차·기술 기준마다 정본이 정확히 하나다.
- 루트와 각 영역 README에서 정본까지 링크로 도달할 수 있다.
- 상대 링크·자동 색인·메타데이터·번역 원문 연결이 CI에서 검증된다.
- 남은 영어 설명문은 코드·식별자·법률 원문으로 분류되어 있다.
