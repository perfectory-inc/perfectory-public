# ADR 0480: 필지 원천은 서빙 지적판이 가진 코드 형태로 놓이고, 코드 없는 공매는 물건명의 주소로 놓인다

## Context

사장 질문(2026-11-11): "공매 미해결이 법정동 코드표 때문인가?" 운영 Trino 를 읽기 전용으로 재서 원인을 나눴다
(현재 행 기준).

| 원천 | 현재 행 | 해석 | 코드 있는데 미해결 | 코드·주소 없음 |
|---|---:|---:|---:|---:|
| 공매 물건 | 63,812 | 34,042 (53.3%) | 7,109 | 22,661 |
| 경매 물건 | 64,059 | 56,713 (88.5%) | 7,116 | 286 (주소만) |
| 경매 매각결과 | 22,856 | 21,126 (92.4%) | — | 1,098 (주소만) |

1. **가장 큰 원인은 코드표가 아니라 우리 해석기였다.** 서빙 지적판은 아직 `202606` 이다(2026-07-01
   전남광주·인천 개편 전). 해석기(`place_identity_resolver.resolve`)는 원천 코드를 **현재 코드**로 옮긴 뒤
   그 형태(`1211010100…`)만 서빙 필지에서 찾는다. 그러나 서빙 지적판은 같은 땅을 **옛 코드**
   (`4611010100…`)로 들고 있다. 그래서 코드 변경 쌍은 있는데도 땅을 못 찾았다.
   - 경매 물건: 미해결 7,116 중 **6,020** 은 원천이 준 옛 코드 그대로 서빙 필지에 있다.
   - 공매: 7,109 중 **4,122** 는 서빙판이 가진 앞선 코드 형태로 찾아진다. 대개 원천이 이미 새 12·28 코드를 준 경우다.
   - 경매 매각결과: 1,098 중 **1,072** 는 주소를 현재 코드로 읽었으나, 그 형태가 202609 에만 있다.
   - Gold 도 같았다. Gold 는 매 빌드 현재 코드로 옮기고(ADR-0383) 서빙 필지에 놓는다. 그래서 같은 행이 `lineage_missing` 로 남았다.
     필지 계보는 판 사이의 앞→뒤만 잇는다. 뒤 코드→앞 판을 잇지 않는다.
2. **공매 22,661 행은 원천이 코드를 아예 주지 않는다.** `ltnoPnu`·`rdnmPnu` 가 모두 null 이다. 대부분 신탁사가 파는
   기타일반재산이다. 그런데 물건명이 전체 주소다(`○○도 ○○시 ○○읍 ○○리 999-9, 999호 …`). 경매가 이미 쓰는
   주소 문법(`address_pnu`, ADR-0280 §4)을 로컬에서 같은 행에 돌렸다.
   - **지번으로 읽힘 18,194** → 서빙 필지 **18,020**(현재 형태 16,254 + 앞선 형태 1,766).
   - 도로명 2,196(서로 다른 키 92개: 건물 하나 66 · 여럿 3 · 없음 23).
   - 못 읽음 1,568(블록·로트 문장) · 법정동 없음 703.
   - 공매 적재에는 주소 경로가 없었다.
3. 남은 것은 우리 몫이 아니거나 아직 아니다.
   - 202609 에만 있는 새 필지: 공매 3,794 중 대부분이 앞선 형태로 찾아지고, 나머지는 202609 승격 때 풀린다.
   - 본번 0000(블록·문장): 공매 2,827.
   - 쌍 없는 폐지 코드: 공매 30, 경매 278.
   - 부번 없음 소수.

## Decision

1. **서빙 지적판의 코드 형태.** 해석기는 현재 형태가 서빙 필지에 없을 때, 그 코드의 **앞선 형태**로 찾는다.
   - `served_forms`: 순위 1 = 원천이 준 코드 자신(옛 코드일 때), 순위 2 = 같은 현재 코드로 가는 다른 옛 코드
     (원천이 새 코드를 줌, 또는 통합의 형제).
   - 낮은 순위 하나가 서빙 필지에 있으면 그 PNU 에 놓는다. 등급은 `code_served_edition`(쌍이 같은 땅이라 말한다).
     같은 순위에 둘 이상 있으면(통합된 두 옛 동이 같은 지번) 놓지 않는다. 이유는 `code_subdivision_ambiguous`.
   - 같은 탐색(`held_forms`)을 쓰는 곳:
     - 주소 경로의 지번 확인(`address_pnu.resolve(…, remap)`)
     - Gold 배치(`served_form_candidates`: 계보 후보와 같은 틀, path `code_served_edition`)
   - 해석기는 하나다(ADR-0288 §1). 필지 읽기는 물을 형태만 묻는다(`candidate_pnus`, ADR-0390).
   - 서빙판이 202609 로 바뀌면 현재 형태가 먼저 잡힌다. 그래서 같은 행이 다음 빌드에서 저절로 새 코드로 옮겨진다.
     적재 때 한 번 정하고 끝내지 않는다(사장 규칙 10-31). Gold 는 매 빌드 다시 놓는다.
2. **코드 없는 공매는 물건명의 주소로 놓는다. 공식 경로가 먼저다.**
   - 순서: 원천 코드(`ltnoPnu`) → 지번 주소 → 도로명 주소.
     - 지번 주소: 시도·시군구·읍면동·리 이름을 현재 법정동 코드표로 읽고, 산·본번·부번을 더한다. 앞선 형태 포함.
     - 도로명 주소: 건축물대장 표제부의 도로명 주소와 맞춘다.
   - 경매와 같은 joins(`address_pnu`)를 쓴다. 해석기를 하나 더 두지 않는다.
   - `silver.onbid_real_estate_item` 에 `pnu_basis`(놓은 단계)와 `pnu_unresolved_reason`(못 놓은 이유) 열을 더한다.
     값은 경매의 말이다: `legal_dong_code`·`legal_dong_code_superseded`·`legal_dong_code_served_edition`·`jibun_address`·`road_address`.
     계약 품질 문구: "pnu is set exactly when pnu_basis is set and pnu_unresolved_reason is not".
   - 표제부는 물건명이 묻는 도로명만 남기고 읽는다(ADR-0390).
3. **부분 처리.** 다시 놓는 일은 원천이 다시 보여 주는 행에서 일어난다. 공매는 3시간마다 열린 물건 전수를,
   경매는 매일 진행 물건을 다시 읽는다. 내용 비교(`release_changes`)가 놓임이 바뀐 행만 덧붙인다(append-only).
   새 일괄 잡도, 전량 재처리도 없다. 닫혀 다시 보이지 않는 행은 Gold 가 매 빌드 §1 로 놓는다.
4. 사장 지시의 셋째 방법(지오코딩·점-다각형, `추정` 등급)은 이 ADR 에 넣지 않는다. 남은 행의 대부분은 블록·로트
   문장이라 좌표도 없다. 도로명 공식 DB(juso, [ADR-0475](./0475-the-juso-electronic-map-is-collected-every-day-from-the-official-daily-change-linkage-with-one-approval-key.md))는 키가 놓이면 도로명 단계의 원장으로 붙인다.

## Consequences

- 계산(2026-11-11 운영 읽기, 이 결정의 규칙 그대로):

  | 원천 | 전 | 후 |
  |---|---:|---:|
  | 공매 물건 | 34,042 / 63,812 (53.3%) | 약 56,184 (88.0%) |
  | 경매 물건 | 56,713 / 64,059 (88.5%) | 약 62,733 (97.9%) |

  - 공매 후 = 앞선 형태 +4,122, 지번 주소 +18,020, 도로명 주소는 따로 센다.
  - 경매 물건 후 = 앞선 형태 +6,020.
  - 경매 매각결과는 주소의 앞선 형태로 대부분 풀린다(1,072 중 실측은 배포 뒤).
  - 실제 값은 배포 뒤 적재 요약의 `resolved_by_grade` 와 ADR-0288 §6 해석률 검사가 낸다.
- 비용(계산): 공매 적재 run 마다 법정동 코드표 5.3만 행과 변경쌍 3.5천 행을 읽는다. 표제부는 도로명으로
  걸러 한 번 훑는다(열 둘). 경매는 이미 같은 입력을 읽는다. 자체 서버, 추가 과금 없음.
- 위험: `attached_via = code_served_edition` 인 Gold 회차는 "자기 PNU 아님"으로 센다(계보 후보와 같다).
- 남은 일: ADR-0288 4·6단계의 나머지(필지 단위 place_id 발행, 원천 Gold 의 place_id 열, 조인 가드, 하나의 스튜어드 큐,
  실거래 본번 묶음 place_id)는 별도 PR 로 잇는다.
