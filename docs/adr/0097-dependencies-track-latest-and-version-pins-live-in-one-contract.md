# ADR 0097: 의존성은 최신을 추종하고 버전 핀은 계약 한 곳에 산다

- Status: Accepted
- Date: 2026-09-09

## Context

2026-09-09 하루 동안 버전에 관한 사고가 세 번 겹쳤다.

1. 프론트엔드 npm 권고 7건(next RCE 2건 포함)이 공개되며 저장소의 모든 PR 병합이 막혔다
   (ADR-0028 OSV 래칫). 전부 "핀을 오래 두는" 관성이 데리고 있던 낡은 판이었다.
2. 낡은 vite 6.4.2는 열린 권고 2건을 기준선에 사유와 함께 앉혀 두고 있었고, 새 서비스의
   lockfile이 그 판을 물려받자 래칫이 확산을 거부했다. 최신 패치(6.4.3)가 이미 두 권고를
   닫고 있었다 — 낡음 자체가 빚이었다.
3. 그 vite 하나를 옮기는 데 파일 다섯 개(매니페스트 2, 가드, 기준표 문서, ADR 각주)를
   고쳤다. 버전이라는 한 사실이 여러 곳에 사본으로 살았기 때문이다. 같은 날 측정한
   pnpm outdated 는 마이너 승급 대기 약 35개, 메이저 대기 약 12개를 보였다
   (pnpm 9↔12, TypeScript 5.9↔7.0, vite 6↔8).

저장소에는 이미 반대편 모범이 있다. R2 서빙 키 문법은
`platforms/foundation-platform/config/r2-connections.contract.json` 한 곳에 살고 Rust 와
Worker 가 그것을 읽으며, OSV 스캐너 핀은 `tools/osv-scanner.env` 한 곳에 산다. 버전 핀만
그 모양이 아니었다.

## Decision

1. **의존성의 기본값은 "최신 안정판을 언제 올리나"이지 "올리나 마나"가 아니다.** 새
   의존성은 최신 안정판으로 들어오고, 기존 의존성은 파도(패치·마이너 일괄 → 메이저 개별 →
   툴체인·런타임 전환) 단위로 최신을 따라간다. ADR-0008 의 수동 원칙은 유지한다 — 자동
   보안 PR 을 켜는 것이 아니라, 사람이 자주 올린다.
2. **버전 핀의 SSOT 는 `tools/technology-versions.contract.json` 하나다.** 매니페스트가
   정확히 고정해야 하는 JS 핀 전부가 이 파일의 `manifest_exact_pins` 에 산다.
   `scripts/guard/technology-version-consistency.sh` 는 핀 값을 하드코딩하지 않고 이
   계약을 읽어 모든 `package.json` 과 대조한다. 이 가드가 막는 실제 사고: 한 매니페스트만
   올라가고 다른 매니페스트·문서가 낡은 값으로 남아 로컬과 CI 가 다른 판을 검증하는 일 —
   2026-09-09 vite 가 정확히 그 직전까지 갔다.
3. **다른 사본은 값을 다시 적지 않고 계약을 가리킨다.** `docs/technology-stack.md` 의
   버전 셀과 ADR 개정 각주는 전이(왜 올렸나)만 남기고, 현재 값의 정본은 계약 파일이다.
4. **OSV 기준선의 "별도 보수로 남긴다" 행은 밀린 숙제로 취급한다.** 파도가 지나갈 때마다
   해당 행을 실제 승급으로 닫고, 래칫이 낡은 행을 거부하는 성질(ADR-0028 §3)을 감소 증명으로
   쓴다.

## Consequences

- 이후 버전 승급은 계약 파일 + 매니페스트(+lockfile)로 끝난다. 가드·문서를 따라 고치는
  왕복이 사라진다.
- 최신 추종은 회귀 위험을 사 온다. 그 값은 파도마다 전체 테스트 재검증으로 치르고, 메이저는
  하나씩 초록을 확인하며 올린다. 실패한 승급은 되돌리고 기준선/각주에 이유를 남긴다.
- 첫 적용 파도: ① 이 ADR 과 함께 계약 파일·가드 전환 ② JS 패치·마이너 일괄 ③ vite 8·
  vitest 5 등 메이저 개별 ④ TypeScript 7·pnpm 12·Node LTS·Rust 부채(jsonwebtoken 10 등)·
  인프라(Postgres 18, Spark/Iceberg)는 각자 검증과 함께 후속 파도로 진행한다.
