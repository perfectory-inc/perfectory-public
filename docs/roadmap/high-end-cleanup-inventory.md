# 하이엔드 정리 인벤토리

[ADR-0410](../adr/0410-the-repository-is-held-to-five-testable-cleanup-rules-and-every-artifact-comes-from-one-declared-definition.md)
의 전수 목록과 실행 순서다. 결정(규칙 다섯 개·목표 구조·범주마다 0 을 지키는 가드)은 ADR 이 정본이고, 이 문서는
**무엇이 남았고 어떤 순서로 지우는가**만 가진다. 항목을 끝내는 PR 은 이 표의 행을 지우거나 `끝남(#PR)` 으로 바꾼다.

- 기준: origin/main `5ec54b93`(2026-11-04). 표본이 아니라 저장소 전체(`git ls-files` 전부, Rust·Python·셸·TS·SQL·JSON·YAML·md)를 훑었다.
- 줄 수(LOC): `git grep -c '' origin/main -- <path>` 의 합. `~` 는 큰 파일 안의 줄 범위, "약" 은 범위 합산의 추정이다.
- 경로: `platforms/foundation-platform/` 아래 경로는 영역 기준 상대 경로(`crates/…`, `scripts/…`, `infra/…`)로 적었다.
- 열: **구조 의존** — 구조 전환(Dagster 자산 + ODCS 단일 정의, ADR-0410 §2)에 `없음`/`일부`/`선행`. **병렬** — 진행 중 PR 과
  겹치지 않고 지금 시작할 수 있는가. **크기** — 바꿀 양 S < 300줄, M 300~2,000줄, L > 2,000줄.
- 근거 열의 grep·파일:줄은 위 기준 커밋에서 다시 돌릴 수 있다. 조사 도구는 읽기 전용이었고 운영 호스트는 보지 않았다.
- 경로는 기준 커밋의 스냅숏이라 백틱 없이 적는다. 지울 대상을 가리키는 목록이므로, 항목을 지우는 PR 이 죽은 경로 래칫 때문에 이 문서를 고칠 필요가 없게 한다. 행의 상태는 끝낸 PR 번호(`끝남(#N)`)로 적는다.

#### 메모

- 브리핑은 "TS/web 쪽 MVT 디코더 3개"를 예상했으나, origin/main 에서 `git grep -i varint` 및 `readTile`/`@mapbox/vector-tile`/`pbf` 검색(`*.ts`, `*.tsx`, `*.js`, `*.mjs`)으로는 TS MVT 디코더가 나오지 않음; 유일한 TS 적중은 A-O09 의 PMTiles 테스트 헬퍼. 남은 MVT 디코딩은 전부 Rust(A-O09).
- 브리핑은 아웃박스 릴레이 4개를 예상했으나 실제는 5개: gongzzang, foundation catalog, identity, intelligence normalization, 그리고 같은 워커의 foundation-outbox-publisher 레인. Postgres 잡 큐 2개는 A-O18 에 있음.
- gongzzang web 은 대부분 이미 OSS(ky, zod, es-toolkit, oauth4webapi, iron-session, tanstack-query) 기반. 손수 짠 debounce/throttle/groupBy/chunk/clamp 등은 `git grep` 로도 안 나옴. 남은 문제는 복붙 fetcher(A-O14)와 손수 DTO(B-O11) 뿐.
- 기능 플래그: 범위 내에서 발견 안 됨. 캐시: A-O03 의 JWKS 캐시뿐.

## 조사 범위와 확인 못 한 것

- 재발명(A-F): `pmtiles`·`iceberg-rust`·`rc-zip` 의 현행 판이 우리 코드가 필요한 기능(항목 열거, 동등 삭제, 꼬리 읽기)을 정말 덮는지는 교체 PR 이 확인한다. scripts/catalog/render-data-contracts.py 는 보지 않았다.
- 다른 영역(A-O·B-O): 14,000줄 넘는 `gongzzang-persistence`·`gongzzang-api` 파일은 줄 단위로 읽지 않았다. 파일 일부만 해당하는 항목도 파일 전체 줄 수를 셌다.
- 코드 중복(B-F): 일부 줄 수는 범위·추정("약")이다. TS 게이트웨이 시험은 설정 시험만 봤고 Airflow DAG 파일은 다 읽지 않았다.
- 죽은 코드(D): 호출자는 정확한 문자열과 동적 `${UNIT}`·`${LANE}` 모양으로 찾았다. 다른 방식으로 조립한 이름은 잘못 분류될 수 있다. 모듈 안의 미사용 Rust 항목은 보지 않았다. D01·D15·D22 를 지우기 전에 공짱 앵커 가져오기가 AWS 에 배포돼 있지 않은지 확인한다.
- 가드(E): 계약 시험 약 110개 중 정책 검사가 분명한 약 20개만 표에 넣었다. 분류는 파일 머리말과 코드 훑기로 정했으니 지우기 전에 한 번 더 본다.
- 문서(C):
  - 스캔은 `git ls-files "*.md"` 704개 전체에 python 정규식으로 했다(Git Bash 의 경로 변환 때문에 `/opt/…` 같은 패턴은 git grep 을 쓰지 않았다). 같은 줄 중복은 정규화한 70자 이상 줄로 비교: 2개 이상 문서가 공유하는 비ADR 줄 34개. 대부분의 중복은 문장이 아니라 의미가 겹치는 것이라 C01–C07·C14–C18 은 주제별로 직접 판정했다.
  - 고아 엄격 기준은 감사 도구의 "유입 링크" 열(경로를 해석한 마크다운 링크)이다. 백틱 언급은 링크로 세지 않는다.
  - 확인하지 않은 것: 런북 명령이 실제로 도는지, ADR 본문이 서로 다시 적은 부분(ADR 사이 중복은 범위 밖), 영역 ADR 의 상태 형식.
