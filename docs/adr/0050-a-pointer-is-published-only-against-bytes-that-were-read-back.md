# ADR 0050: 포인터는 읽어 본 바이트에 대해서만 발행된다

- Status: Accepted
- Date: 2026-08-23
- 관련: [ADR-0046 수집된 파일에서 온 발행은 그 수집 기록을 이름한다](./0046-a-publication-names-the-object-it-was-collected-from.md), [ADR-0040 아무도 채우지 않는 컬럼은 필수일 수 없다](./0040-a-column-no-producer-fills-cannot-be-required.md), [ADR-0006 기준 데이터는 객체 저장소 우선](./0006-object-storage-first-serving.md)

## Context

`catalog.industrial_complex_gold_pointer` 는 자기가 들고 있지 않은 물건을 설명한다.
`profile_object_key` 가 R2 의 객체를 가리키고, `profile_checksum_sha256` · `profile_size_bytes` ·
`current_version` 이 그 객체가 무엇인지를 **주장**한다.

2026-08-23 이전까지 그 주장들은 전부 환경변수로 도착했다. 운영자가 내보내기 요약(JSON)을 열어
눈으로 읽고 손으로 옮겨 적는 값이었고, **그것을 객체와 대조하는 코드는 없었다.** 결과적으로 다음
셋이 전부 통과했다.

1. 존재하지 않는 객체를 가리키는 포인터 — 발행 성공, 조회하면 404 를 부르는 주소를 응답에 실음
2. 실재하는 객체를 가리키면서 **다른 객체를 설명**하는 포인터 — 체크섬·크기가 틀려도 저장됨
3. 단지 A 의 요약 줄을 단지 B 의 포인터로 발행 — 손으로 옮겨 적을 때 나는 바로 그 사고

여기에 규모가 곱해진다. 정본은 1,442행이고, 단건 커맨드
(`publish-industrial-complex-gold-pointer`)만 있었으므로 표를 채우려면 열세 개 값을 손으로 옮기는
일을 1,442번 반복해야 했다. 루트 ADR-0036 ⑦ 이 내보내기 요약을 발행의 입력으로 정해 두었지만
**그 요약을 읽는 코드가 없었다.** 즉 이 저장소가 세 겹으로 막는 "지어낸 계보"를, 우리 자신의
운영 절차가 생산하도록 되어 있었다.

## Decision

1. **포인터의 아티팩트 주장은 객체를 읽어 확인한 뒤에만 저장된다.**
   `VerifiedGoldProfileArtifact` 는 필드가 비공개이고 생성자가 `verify` 하나뿐이며, 그 생성자는
   저장된 바이트를 읽는다. `PublishIndustrialComplexGoldPointerInput` 은 오직 그 타입에서만
   만들어진다 — 이 서비스 안에 검증되지 않은 포인터를 발행하는 표현식은 존재하지 않는다.
2. **확인 대상은 넷이다.** 바이트의 SHA-256, 바이트 길이, 문서가 스스로 밝힌 `artifact_id`,
   문서가 스스로 밝힌 `complex_id`. 앞의 둘은 "이 물건이 맞나", 뒤의 둘은 "이 물건이 **이 단지의**
   것이 맞나"를 묻는다. 뒤의 둘이 없으면 위 Context 의 사고 3이 그대로 통과한다.
3. **키가 정본 배치가 아니면 읽기 전에 거부한다.** 레이크하우스 버킷에는 Bronze 원본과 Iceberg
   표도 같이 있다(루트 ADR-0039 ④).
4. **전량 발행은 요약을 읽는다.** `publish-industrial-complex-gold-pointers` 가 내보내기 요약을
   입력으로 받아 각 줄을 ①의 검증에 태운다. 사람이 옮겨 적는 자리를 없애는 것이 목적이므로,
   계보 값(`source_snapshot_id` · `iceberg_snapshot_id` · `published_at_utc`)은 요약이 적은 것을
   그대로 쓰고 운영자가 덮어쓸 수 없다.
5. **재실행은 안전하다.** 이미 그 버전에 가 있는 단지는 세고 건너뛴다 — 아티팩트 id 가 스냅샷과
   단지의 순수 함수(루트 ADR-0036 ⑤)이므로 "그 버전에 있다"는 것이 곧 "발행이 일어났다"이다.
   다른 버전에 있으면 그 버전을 expected 로 넘겨 동시 발행을 덮어쓰지 않고 충돌로 보고한다.
6. **드라이버와 버킷이 요약과 다르면 실행하지 않는다.** 다른 버킷을 읽으면 발행되지 않을 객체를
   검증하게 된다. 요약이 자기가 쓴 버킷을 기록하는 이유가 이것이다(루트 ADR-0039 ⑤).

이 검사가 실패해서 막는 진짜 사고: **응답에 실려 나가는 주소가 가리키는 물건이, 그 응답이
설명하는 물건이 아닌 상태.** 소비자는 CDN 에서 바이트를 읽으므로 API 를 다시 물어 확인할 수 없다.

## Consequences

- `publish-industrial-complex-gold-pointer` 는 이제 프로필 저장소를 **필수** 입력으로 받는다.
  기본값이 없다: 발행은 운영 행위이고 추측할 만한 저장소는 없다.
- 내보내기와 발행이 같은 저장소 정의(`industrial_complex_gold_profile_store`)를 공유한다.
  "쓴 곳"과 "확인한 곳"이 구조적으로 같은 곳이 된다 — 편집되기 전까지만 일치하는 두 개의 enum 이
  아니라.
- 검증 비용은 단지당 GET 한 번이다. 1,442행 전량 발행이 1,442 GET 을 더 부른다. 발행이 드물고
  (스냅샷마다 한 번) 잘못 실린 주소는 소비자 쪽에서 조용히 틀리므로, 그 값을 치를 만하다.
- 무력화 확인은 테스트 여섯 개가 거절 쪽으로 적혀 있다
  (`industrial_complex_gold_pointer_publish/artifact_verification/tests.rs`): 체크섬 불일치·크기
  불일치·객체 부재·다른 단지·다른 버전·비정본 키. 통과만 관찰한 검사는 관찰되지 않은 검사다.
- 남은 일: 이 커맨드들은 아직 **한 번도 실행되지 않았다.** 표는 0행이고 R2 에 프로필 객체는 없다.
  실제 내보내기·발행은 운영 승인 아래 별도로 이루어진다.
