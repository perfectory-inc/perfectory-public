# ADR 0623: AWS 의 일은 때가 되고 진행 중인 run 이 없을 때 시작하고, 레이크하우스에는 레인마다 짧게 발급한 자격으로만 닿으며, 제 시간 수를 지니지 않는다

- Status: Accepted (사장 결정 2026-11-26, 브레인스토밍 `concepts_brief.aws-jobs-and-credentials.md` §8 의 끝 상태)
- Date: 2026-11-26
- 다루는 것: AWS 에서 도는 모든 일(수집기, Silver, Gold)의 시작 조건, 레이크하우스 자격, 멈춤 규칙, 건강 신호.
- 고치는 곳: [ADR-0616](./0616-data-jobs-run-as-dagster-assets-on-aws-ecs-and-the-host-job-layer-is-not-ported.md) §1·§2-3·§2-8·§2-9·§4·§8·§10 의
  해당 문장(그 자리에는 이 ADR 을 가리키는 한 줄만 남는다).
- 그대로: [ADR-0476](./0476-production-shape-ledgers-are-published-by-the-host-and-ci-reads-them-with-no-copy.md) 은 호스트 레인이 물러날 때까지
  호스트의 방식이다(run 마다 20 분 임시 열쇠). 이 ADR 은 AWS 레인만 다룬다.

## Context

A2 의 첫 수집기 초안(#1758)은 손으로 정한 수 하나(40 분)에 세 가지 일을 시켰다. 그 수는 run 을 끊었고, 열쇠의 수명을 정했고,
드러나지 않게 두 run 의 겹침도 막았다(40 < 60 분 간격). 사장은 2026-11-26 에 둘을 고쳤다. 첫째, 자격은 고정 시간이 아니라 일이 사는 동안이다.
둘째, 고정 시계(`35 * * * *`)는 손으로 정한 예약이다.

확인한 사실:
- R2 임시 자격 증명(`POST /accounts/{id}/r2/temp-access-credentials`).
  - `ttlSeconds` 는 0 ~ 604,800 이고 기본값이 없다.
  - 권한은 object 또는 admin 이고, 접두사나 객체로 좁힐 수 있다. 부모 토큰을 넘지 못한다.
  - 한 자격을 일찍 철회하는 길은 문서에 없다. 부모 토큰을 철회하면 이미 발급된 것이 죽는지도 확인되지 않았다.
  - 그래서 접근의 끝으로 보장되는 것은 만료뿐이다.
- R2 Data Catalog 는 API 토큰만 받고, 버킷 단위 저장소 읽기를 요구한다. 그 토큰을 쥔 일은 버킷 전체를 읽는다(법원경매 Bronze 의 사람 이름도).
- 발행기의 R2 클라이언트는 지금 고정 자격을 만든다. AWS SDK for Rust 는 만료를 함께 받은 자격을 만료 전에 스스로 다시 얻는다
  (`credential_process`, `aws-config`).
- ILIS 수집기의 원천 계약에는 진척과 실패에 따른 멈춤 규칙이 이미 있다(`stall_minutes`, `stop_after_consecutive_failures`, `retry_after_hours`).
  원천은 정해진 날 없이 올리고, 작업의 약속은 하루다(`landed_within_hours` 24).
- 다른 플랫폼의 같은 문제(기억이고, 그 문서와 대조하지 않았다): 한 일의 수명만큼 사는 열쇠는 어디에도 없다.
  AWS STS·ECS 역할, GCP, Unity Catalog, Lake Formation 은 모두 짧은 열쇠를 살아 있는 동안 다시 받는다.

## Decision

### 1. 시작 조건

1. 수집기는 `AutomationCondition.cron_tick_passed(<신선도 박자>).since_last_handled() & ~AutomationCondition.in_progress()` 로 시작한다.
   - 틱은 처리될 때까지 남는다(`since_last_handled`). 그래서 run 이 도는 동안 지난 틱은 버려지지 않고, 그 run 이 끝난 뒤에 처리된다.
   - 박자는 그 원천의 신선도 약속에서 나온다. 모든 수집기는 하루 한 번 새로 받는다(사장 결정 2026-11-26). 온비드는 코디네이터의 확인 뒤에 정한다.
   - 하루 박자의 시각은 원천 계약이 그 까닭과 함께 적는 값이다(ILIS 는 `full_walk_hour_utc`).
2. Silver·Gold 는 `eager()` 다(ADR-0616 §4 그대로).
3. AWS 에는 평범한 `ScheduleDefinition` 이 없다. 겹침은 `~in_progress()` 가 막는다. 시계를 지우는 변경이 그 막음을 함께 들인다.
4. 앞 run 이 끝나면 곧바로 다시 도는 고리는 쓰지 않는다. 원천에 가장 무례하고, 하루 약속에 얻는 것이 없다.
   원천이 싼 변경 신호를 주면 그것으로 시작한다(ILIS 는 없다).

### 2. 레이크하우스 자격

1. **길은 하나다: 발급 창구.** Lake Formation·Unity Catalog 처럼 범위를 정한 자격을 나눠 주는 표준 방식이다.
   - 창구는 함수 `perfectory-platform-r2-vend` 이고, Cloudflare 토큰 둘(민팅, 카탈로그 읽기)은 그 함수만 읽는다.
   - 어떤 일도 토큰을 쥐지 않고, 카탈로그에 묻지 않는다.
2. **레인은 부르는 쪽에 묶인다.** 레인마다 태스크 역할 하나와 창구의 alias 하나가 있다. 그 역할은 제 alias 만 부를 수 있다.
   창구는 레인을 요청 본문이 아니라 alias 에서 안다.
3. **범위가 비면 거부한다.** 빈 접두사 목록은 버킷 전체이기 때문이다. 쓰기 접두사가 없는 레인도 거부한다.
4. **두 부름.**
   - 핀: 레인이 읽는 표마다 현재 스냅숏(`metadata_location`, manifest list, snapshot id, 시각)과 읽기 범위다. run 마다 한 번이다.
   - 자격: 쓰기 임시 자격(레인의 쓰기 접두사)과 읽기 임시 자격(그 표들의 위치만), 그리고 `Expiration`.
     유효 시간은 플랫폼 상수 하나이고, `aws-platform.contract.json` 에 한 번 적는다.
   - 자격을 다시 받아도 핀은 움직이지 않는다.
5. **갱신.**
   - 발행기는 `credential_process` 프로필로 자격을 읽고, SDK 가 만료 전에 스스로 다시 받는다.
   - 1단계는 멈춰도 되고 읽는 대로 커밋하는 수집기(ILIS)이고, 갱신 없이 간다. 유효 시간에 닿은 run 은 마지막 요청 하나만 잃고, 다음 틱이 잇는다.
   - 2단계는 Silver·Gold·DuckDB 같은 멈추면 안 되는 일보다 먼저 온다. 거기서 갱신을 들인다. 갱신을 넘는 multipart 올리기를 실제 R2 에서 시험한다
     (올리기 시작 → 열쇠 만료 → 다시 받기 → 다음 조각 → 마침).
   - 두 단계 사이에는 고정 열쇠도 받는다. ai-server 가 겹쳐 도는 동안 그 길을 쓴다.
6. **접근이 끝나는 때는 태스크가 끝나고 한 유효 시간 안이다.** 철회는 약속하지 않는다(R2 가 문서로 두지 않았다).
   비상시에는 부모 토큰을 돌린다(런북). 그것이 이미 발급된 자격을 죽이는지는 확인되지 않았다고 런북에 적는다.
7. **창구의 기록.** 레인, Dagster 의 run id, 만료를 남긴다. 값은 남기지 않는다.
8. **DuckDB 단계(A4·A5)도 같은 핀으로 읽는다.**
   - 표마다 `metadata_location` 을 `iceberg_scan` 으로 읽고, 읽기 자격을 S3 비밀로 쓴다.
   - 카탈로그를 `ATTACH` 하지 않는다.
   - 발행기의 손으로 쓴 읽기는 같은 핀의 manifest list 를 쓴다(카탈로그 제공자 `vended`).
9. **노출의 천장.** 오케스트레이터는 모든 레인의 역할을 넘겨야 한다. 그래서 그것이 뚫리면 레인 범위의 합에 닿는다. 토큰에도 버킷 전체에도 닿지 않는다.
10. **아직 정하지 않은 것.** Silver·Gold 가 Iceberg 에 커밋하는 길이다. 카탈로그 쓰기 토큰도 버킷 전체다.
    창구가 레인의 표에 커밋을 대신하거나, 카탈로그가 범위 자격을 스스로 줄 때까지 기다린다. AWS 의 첫 Silver·Gold 커밋 전에 정한다.
11. 민팅 코드는 한 벌이다(창구의 모듈). 호스트의 shape-ledger 스크립트도 그것을 가져다 쓴다.

### 3. 멈춤

1. run 안의 속도와 멈춤은 원천이 정한다. 원천의 신호(429, Retry-After)와 원천 계약의 원천마다 규칙(`stall_minutes`,
   `stop_after_consecutive_failures`, `retry_after_hours`)이다. 4xx 규칙도 원천마다다: ILIS 는 내린 공고에 늘 400 으로 답한다.
2. run 의 상한은 플랫폼 하나다: 신선도 약속(하루, 86,400 초). 그보다 긴 run 은 이미 약속을 어겼다.
3. AWS 레인은 제 시간 수(`time_limit_minutes`, 작업마다의 `max_runtime`)를 지니지 않는다.

### 4. 건강

1. AWS 코드 위치는 호스트 레인이 쓰는 신선도 검사(`source_read_checks`)를 싣는다.
2. 조용한 run(`unchanged`·`waiting`·`skipped`)은 통과하는 검사를 낸다. 하루 박자에서는 그것이 "돌았고 새것이 없다"의 유일한 신호다.
   토큰이 아직 없는 창구(inert)는 실패하는 검사로 보인다.
3. 하루 박자에서 한 번 실패하면 하루 약속을 놓친다. 받아들인다. 신선도 검사가 알리고 다음 틱이 다시 한다.

### 5. 레인의 정의

레인은 범위만 적는다: 쓰기 접두사와 읽는 표. 시간 수는 적지 않는다.
유효 시간과 run 상한은 플랫폼의 값이고, 박자는 신선도 약속, 시각은 원천 계약의 값이다.

## Consequences

- #1758 의 시계(`35 * * * *`), 40 분, `ttl_margin_seconds`, 작업 목록에서 TTL 을 끌어내는 일, `dagster/max_runtime` 태그를 지운다.
  갱신이 들어오면 발행기에 주던 열쇠 환경 변수 여섯과 창구의 일회성 답도 지운다.
- ILIS 는 AWS 에서 하루 한 번이다. ai-server 의 같은 작업은 넘기는 PR 까지 시간마다 그대로다(ADR-0616 §7 의 사흘 겹침).
- 레인마다 역할 하나와 alias 하나가 늘어난다(비용 없음). 창구는 Lambda 의 무료 등급 안이다.
- 순서: 이 ADR → 창구와 기반(범위 거부, 레인 역할·alias, 두 부름, 만료, 기록, 민팅 한 벌) → ILIS 레인 → 2단계(갱신, multipart 시험).
- 열린 것: Silver·Gold 의 커밋 길(§2-10), 부모 토큰 철회의 효과, Cloudflare 민팅의 속도 한도, 갱신을 넘는 multipart.

## 기각한 대안

| 대안 | 왜 |
|---|---|
| 유효 시간 = 작업의 시간 한도 | 손의 수 하나가 세 뜻을 다시 진다. 긴 run 은 도중에 실패한다 |
| 긴 유효 시간 하나 | 새면 며칠 동안 산다 |
| 끝날 때 철회 | R2 에 없다. 죽은 태스크(Spot, 메모리 초과)에서는 돌지도 않는다 |
| 끝나면 곧바로 다시 | 원천에 가장 무례하다 |
| 시간마다 | 하루 약속에 24 배를 묻는다 |
| 크기 등급마다 실측한 시간 상한 | 아직 잰 run 이 없다(`measured_run_seconds` 가 비었다). 진척 감시와 약속에서 나온 상한으로 충분하다. 비용 근거가 생기면 그때 |
