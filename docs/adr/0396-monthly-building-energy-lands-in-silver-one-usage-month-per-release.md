# ADR 0396: 월별 건물 전기·가스는 객체 하나를 사용 월 하나의 판으로, 그 달만 비교해 Silver 에 쌓는다

- Status: Accepted
- Date: 2026-11-04
- Builds on: ADR-0355(연결 순서 4순위), ADR-0356·ADR-0357·ADR-0397(같은 엔진), ADR-0169, ADR-0318, ADR-0328, ADR-0288, ADR-0329

## Context

공장 매수인·임차인이 가장 먼저 묻는 것 하나는 "이 공장이 지금 돌고 있나" 다. 건물의 월별 전기·가스 사용량이 그 답의 공개 신호다.
사용량이 0 으로 떨어지거나 몇 달 사이에 급히 줄면 휴업·공실을 뜻하고, 꾸준하면 가동 중이다. ADR-0355 는 이것을 지금 연결 4순위로 두었다.
그리고 "열쇠가 관리번호가 아니라 (PNU, 사용 월)이므로 엔진의 열쇠 칸을 넓힌다" 고 남겼다.

**측정 (2026-11-04, 운영 장부 읽기 전용, 객체를 R2 읽기 전용 키로 받아 끝까지 읽음).**

- **장부.** 전기(`hubgokr__building_energy_monthly_electricity`)와 가스(`..._gas`)는 장부 월마다 객체가 하나씩이고, 객체 하나가 사용 월 하나다.
  장부 2026-06 이 202602 사용분, 07 이 202603, 08 이 202604, 09 가 202605 이다. **2026-10 에는 두 객체가 있다.** 202606 사용분과,
  다시 실린 202605 사용분이다. 두 객체 모두 `provider_updated_at` 이 비어 있다. 지금의 판 고르기(장부 월의 가장 새 객체 하나,
  ADR-0169 §2)는 이 달을 "고를 수 없음" 으로 거부한다. 그렇게 넘어가도 앞 사용 월 넷은 영영 적재되지 않는다(`newer_release_loaded`).
- **파일.** 2026-10 의 202606 전기 ZIP 은 21,167,230 바이트다. 멤버 이름은 `eais_elcty_202606.txt`(170,343,713 바이트)로, 사용 월이 이름에 든다.
  1,462,015 행, 모든 행 17칸, PNU 입력 100% 다. 가스 202606 은 392,467 행이고, 칸 배치는 전기와 같다.
- **키.** (사용 월, 지번, 칸 1 순번)은 판 안에서 행마다 고유하다. 그러나 순번은 판 사이에 같은 건물을 가리키지 않는다.
  202605 사용분을 2026-09 판과 2026-10 판에서 비교하면 행은 1,461,326 → 1,464,190 이다. 사용량이 바뀐 행이 399,708,
  같은 (지번·순번)의 도로명이 바뀐 행이 64,356 이다. 다시 싣는 판은 그 달의 정정본이다.
- **필지 연결률(표본 2,000 행, 대응표 없는 단순 조합, `silver.parcel_boundaries`).** 전기 96.6%, 가스 97.75%.

### 실사례

- 시계열 원장을 "달 단위 파티션의 교체" 로 다루는 것은 데이터 웨어하우스의 표준이다. dbt 의 `insert_overwrite` 증분 전략(BigQuery·Spark),
  Delta Lake 의 `replaceWhere`, Iceberg 의 파티션 단위 덮어쓰기가 그렇다. 늦게 온 정정은 그 파티션만 다시 쓰고, 다른 파티션은 읽지도 않는다.
  우리는 append-only 이므로 덮어쓰지 않는다. 그 대신 그 달의 키만 비교해 바뀐 행과 삭제 표시를 덧붙인다(ADR-0318). 결과는 같고, 이력이 남는다.
- 미국 EIA·유틸리티의 AMI(스마트미터) 적재도 "검침 월 + 계량 위치" 를 키로 두고, 정정 검침을 같은 키의 새 판으로 받는다.

## Decision

1. **표 둘, 모양 하나.** `silver.building_energy_monthly_electricity` 와 `silver.building_energy_monthly_gas` 다. 제공자 원천이 둘이고 판의 흐름도 따로라서 표를 나눈다.
   이름 붙인 칸은 사용년월, PNU 입력 5개, 사용량이다. 17칸 전부를 `raw_columns` 에 남긴다. 사용량의 단위는 제공자 명세로 확인한 화면 PR 이 적는다.
2. **키는 (사용 월, 지번)이고, 한 지번의 그 달 행 묶음이 한 판이다.** 엔진 계약의 `row_key` 에 `joined_columns` 를 더한다(ADR-0397 의 `sha256_of_row` 옆).
   `mgmt_key` 는 `사용년월|시군구|법정동|대지구분|번|지` 다. 순번은 키에 넣지 않는다. 한 지번의 여러 행은 `keep_ties` 묶음이다(ADR-0328).
   묶음은 순번까지 `raw_columns` 로 비교된다.
3. **멤버 이름은 사용 월 자리를 가진다.** `inner_file` 의 `{YYYYMM}` 은 여섯 자리 숫자다(`eais_elcty_{YYYYMM}.txt`). 그 밖의 이름은 지금처럼 정확히 같아야 한다.
4. **객체 하나가 판 하나다(`silver_refresh.release_unit: "object"`).** 갱신 run 은 장부 월, 객체 키 순으로 아직 표에 모든 부분이 없는
   첫 객체를 적재한다. 모든 객체가 있으면 `unchanged` 다. 이 레인에서는 "더 새 판이 있다" 를 건너뛸 이유로 삼지 않는다.
   vintage 는 장부 월(ZIP 이름의 OPN 날짜)이다. 그래서 다시 실린 사용 월이 앞 판보다 앞서고(ADR-0328), 판의 판수(edition)가 뒤로 가지 않는다.
   **run 당 상한은 판 하나다.** 한 달은 140만 행으로, 다른 HUB 부분 레인의 월 적재와 같은 크기다. 첫 적재는 장부의 여섯 객체를
   하루 한 run(또는 수집이 시작한 run)마다 하나씩 받는다.
5. **compare 는 그 판의 달만 본다(`compare.bucket_scope: "release"`).** 묶음은 키 앞 여섯 자리, 곧 사용 월이다. 묶음 목록은 그 판이 가진 묶음뿐이다.
   main 에만 있는 다른 달은 비교하지도, 지우지도 않는다. 객체 레인은 이 범위 없이는 계약 검사를 통과하지 못한다(`lane.rs`). 사용 월이 없는
   한 묶음(`bucket_prefix_length` 0)과 함께 쓰는 것도 Spark 작업이 거부한다.
6. **PNU 는 적재 때 한 번 정하고 멈추지 않는다.** Silver 의 `pnu` 는 다른 HUB 레인처럼 Rust 내보내기가 만든다(ADR-0145). 필지에 붙이는 소비자가
   place-identity 해석기로 옛 법정동 코드를 지금 코드로 옮긴다. 그 Gold 는 `views.changed_codes` 를 따라 바뀐 코드 아래 PNU 만 다시 만든다(ADR-0288 §1, ADR-0329 §3).
7. **소비자는 다음 PR 이다.** 그래프에서 표는 `contract_only`, 엣지는 `partial` 이다. 필지 패널에는 "전기 사용량"·"가스 사용량" 으로
   최근 12개월 월별 합계를 지번 단위로 보인다. 사용량이 0 인 달과 비어 있는 달은 구별한다.

## Consequences

- **비용(계산).** 사용 월 하나가 전기 21 MB·가스 6 MB(ZIP)다. 원문은 170 MB·46 MB, Parquet 로 수십 MB 다. 한 해 12개월에 정정 판까지 더해도
  1 GB 아래이고, R2 저장은 월 20원 아래다. 정정 판은 그 달의 바뀐 지번만 더한다. 202605 정정은 30% 쯤이다.
- 실패가 막는 사고 두 가지. 첫째, `provider_updated_at` 없는 두 객체가 한 장부 월에 있으면 판 고르기가 레인을 멈춘다(2026-10 실물).
  `every_object_of_an_object_lane_is_a_release_in_publication_order` 가 지킨다. 둘째, 한 달 판을 표 전체와 비교하면 다른 달 수천만 행에
  삭제 표시가 붙는다. `an_object_lane_compares_only_the_buckets_its_release_holds` 와 `test_a_release_scope_needs_buckets` 가 지킨다.
- 이 PR 은 #1018(ADR-0397, `row_key`) 위에 쌓였다. 그것이 먼저 병합되어야 한다.
