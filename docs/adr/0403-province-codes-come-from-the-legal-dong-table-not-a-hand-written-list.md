# ADR 0403: 주소의 시도 코드는 법정동 표와 기록된 쌍에서 온다 — 손으로 쓴 시도 목록을 두지 않는다

- Status: Accepted
- Date: 2026-11-04
- Builds on: ADR-0103 §2(코드→지역 상수 금지), ADR-0145(코드 변경 기록 하나), ADR-0280 §4(주소로 PNU),
  ADR-0329(기록된 쌍의 view), ADR-0372(통합 전 시도 코드는 기록된 쌍으로 읽는다)

## Context

주소로 PNU 를 찾는 단계(`address_pnu.py`)는 주소 첫 낱말(전라남도, 광주광역시)을 시도 코드로 바꾼다. 그 대응표가
등록공장 원천 계약(`data-go-kr-registered-factory.contract.json` 의 `sido_prefixes`)에 손으로 적혀 있었고, 법원경매
계약이 같은 표를 가리켰다. 2026-07-01 광주(29)와 전남(46)이 전남광주통합특별시(12)로 합쳐졌다. 법정동 표(`reference.legal_dong_code_snapshot`)는
29·46 을 폐지로, 12 를 현존으로 바꿨고 코드 변경 기록(`reference.legal_dong_code_change`)은 29→12 208쌍, 46→12 2,997쌍을 적었다.
손으로 쓴 표만 그대로였다.

**측정 (2026-11-04, 운영 Trino 읽기 전용).**

| | 광주·전남 행 | 연결 | 지번 단계 | 도로명 단계 |
|---|---:|---:|---:|---:|
| 법원경매 물건(`silver.court_auction_item`, 현재 행) | 4,774 | **3** | 0 | 3 |
| 등록공장(`silver.registered_factory`) | 13,214 | 10,801 | **0** | 10,801 |

전국 법원경매 연결률은 86% 다. 광주·전남은 0.06% 였다. 지번 주소는 폐지된 코드(29·46)로 법정동을 찾았고 그 이름은 현재
코드 아래에만 있어 `no_legal_dong` 이 됐다. 이름이 이미 "전남광주통합특별시" 인 357행은 표에 없는 낱말이라 읽히지도 않았다.

같은 모양의 손 목록이 저장소에 두 개 더 있다. 더니어 산업단지 화면의 `SIDO_LABEL` 과 공짱 웹의 `SIDO_CODES`(+`ko.json`
의 이름)다. 둘 다 12 가 없고 29·46 이 있다. 이 둘은 `catalog.industrial_complex.sido_code` 와 같은 값을 보여야 하는데, 그 칸이
아직 29(19개)·46(116개)을 싣는다(운영 2026-11-04). 산업단지 표도 코드 변경을 따라가지 않는다는 뜻이다.

### 실사례

- **참조 데이터는 마스터에서 파생한다.** Google 의 libaddressinput 은 국가·행정구역 이름을 코드에 적지 않고 주소 데이터
  서비스의 메타데이터에서 읽는다. Uber H3·Overture Maps 의 행정 경계 이름도 원천 판(release)에서 온다. 우리 마스터는 법정동 표다.
- **손 목록을 가드로 막는 것은 흔한 방식이다.** Kubernetes 의 `hack/verify-*` 스크립트와 Chromium 의 PRESUBMIT 는 "생성되거나
  한 곳에서 와야 할 값이 손으로 적힌" 모양을 찾아 거부하고, 남은 예외는 줄어들기만 하는 목록에 둔다.

## Decision

1. **시도 접두어는 계산한다**(`address_pnu.sido_prefixes`, Spark 에서는 `lakehouse_sido_prefixes`). 입력은 둘이다.
   - 법정동 표의 가장 새 스냅숏 전부(현존·폐지). 코드 앞 두 자리와 전체 이름의 첫 낱말이 시도 이름이다.
   - 기록된 시도 쌍(`legal_dong_code_change_views.region_pairs(rows, 2)`, 대체된 쌍은 빠진다, ADR-0329).
   시도 이름마다 주소가 쓸 수 있는 낱말을 이름의 규칙으로 만든다: 이름 그대로, 끝말(특별자치시·특별자치도·특별시·광역시·직할시·도)을
   뗀 줄기, 세 음절 줄기의 첫째·셋째 음절(충청북→충북). 코드 목록이 아니라 이름의 규칙이다.
   - 현존 코드가 있는 시도는 자기 자신이다.
   - 폐지된 시도는 기록된 쌍이 이끄는 현재 시도다(29·46 → 12).
   - 기록이 시작되기 전의 번호 바꾸기(강원 42→51, 전북 45→52, 제주 49→50, 직할시→광역시)는 쌍이 없다. 이때는 줄기가 같은 현재
     시도 하나다(강원도 ↔ 강원특별자치도, 전라북도의 '전북' ↔ 전북특별자치도).
   - 한 낱말이 두 현재 시도를 가리키면 그 낱말은 쓰지 않는다. 고를 규칙이 없기 때문이다.
2. **원천 계약은 시도 코드를 적지 않는다.** 등록공장 계약의 `sido_prefixes` 와 법원경매 계약의 `sido_prefixes_from` 을 지운다.
   두 적재(`data_go_kr_registered_factory.py`, `courtauction_go_kr.py`)는 적재마다 계산된 표를 읽는다. 다음 시도 변경도 코드
   변경 기록에 쌍이 생기는 순간 따라간다. 2026-11-04 운영 데이터로 계산한 표는 옛 손 목록의 낱말 23개 중 20개가 같고, 다른
   셋(광주·전남·전라남)은 29·46 대신 12 를 가리킨다.
3. **가드**(`scripts/guard/sido-codes-come-from-the-legal-dong-table.sh`, 자체 시험 `-self-test.sh`). 추적되는 원천 파일이
   두 자리 코드 8개 이상을 한글 낱말과 짝지은 표(`"11": "서울"` 이나 그 반대)나 `sido` 라는 이름의 두 자리 코드 8개 이상
   목록을 가지면 거부한다. 가드 스스로는 코드 목록을 갖지 않는다(모양만 본다). ADR-0001: 막는 사고는 위의 측정이다.
   손 목록이 시도 통합을 넉 달 놓쳐 광주·전남 법원경매 4,771행과 등록공장의 지번 주소가 필지를 잃었다.
4. **남은 손 목록 셋은 줄어들기만 하는 목록에 둔다**(`tools/ci/hardcoded-sido-codes.baseline.json`, 이유·지울 조건 포함).
   더니어 `catalogLabels.ts`, 공짱 `lib/complexes/sido.ts`·`lib/i18n/ko.json` 이다. 지우는 PR 은 둘을 함께 한다.
   - `catalog.industrial_complex.sido_code` 가 법정동 코드 변경(`views.changed_codes`)을 따라간다.
   - 필터가 시도 선택지와 이름을 API(법정동 표)에서 읽는다.
   화면만 먼저 12 로 바꾸면 필터가 29·46 에 남은 135개 단지를 못 찾으므로 이 PR 에서 바꾸지 않는다.
5. **이미 쌓인 행.** 법원경매는 적재마다 검색에 나온 물건을 다시 풀어 바뀐 행만 덧붙인다. 그래서 진행 중인 물건은 다음 적재에서
   12 로 이어진다. 등록공장은 판 전체를 한 번 쌓는 표라(읽는 쪽은 가장 새 판) 다음 판에서 이어진다. 둘 다 코드 변경이 닿는
   행만 다시 푸는 단위(`views.changed_codes`)가 없다. 그 단위는 data.go.kr 파일 적재 묶음(ADR-0401)이 등록공장을 옮겨 가며 갖고,
   법원경매는 같은 단위를 따로 받는다. 이 ADR 은 해석기만 고친다.

## Consequences

- **고친 뒤(계산, 2026-11-04 운영 행에 새 표를 적용하고 후보 PNU 를 `silver.parcel_boundaries` 와 Trino 로 맞춤).**
  - 법원경매: 4,774 행 가운데 4,769 행이 지번 PNU 를 내고 4,758 행이 필지에 있다. 연결은 **3 → 4,761** 이다.
  - 등록공장: 지번 주소 968 행이 PNU 를 내고 829 행이 필지에 있다. 연결은 **10,801 → 11,630 이상**이다(하한: 도로명 단계는 다시
    계산하지 않았다).
  - 필지 확인은 서빙 판이 아닌 `silver.parcel_boundaries` 전체로 했으므로 실제 적재보다 조금 클 수 있다.
- 비용: 적재마다 법정동 스냅숏 한 판(약 5만 행)과 코드 변경 기록(약 3,500 행)을 한 번 읽는다. 1초 안팎이다.
- 따라오는 일: 산업단지 `sido_code` 의 코드 변경 따라가기와 화면 필터의 API 화(위 4), 법원경매·등록공장 기존 행의 코드 변경 다시 풀기(위 5).
