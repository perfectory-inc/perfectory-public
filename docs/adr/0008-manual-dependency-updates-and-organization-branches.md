# ADR-0008 — 수동 의존성 업데이트와 조직 작업 브랜치

| | |
|---|---|
| 작성일 | 2026-07-28 |
| 상태 | Accepted |
| 대체 | ADR-0001 §12, ADR-0007의 포크/Dependabot 운영 절차 |

## 결정

- GitHub Dependabot과 자동 보안 수정 PR을 사용하지 않는다. 루트 `.github/dependabot.yml`은
  제거하며, 의존성 업데이트는 사람이 검토한 조직 레포 PR로만 수행한다.
- `main`은 계속 보호한다. 병합은 PR과 squash merge만 허용한다.
- 유지보수자는 개인 포크가 아니라 조직 레포의 이름 있는 작업 브랜치를 만들고 PR을 연다.
- 비-main 브랜치 생성/업데이트는 지정된 조직 유지보수자만 우회할 수 있다. 태그 생성 차단과
  `main` 보호는 그대로 유지한다.

## 이유

현재 규모에서는 자동 PR이 실제 변경보다 많은 운영 잡음을 만들고, 업데이트 시점과 범위를
사람이 통제하는 편이 낫다. 보안 스캔, `cargo-deny`, CI 필수 검사는 계속 실행되므로 자동 bot을
끄는 것이 의존성 검증 자체를 끄는 것은 아니다.

## 운영 규칙

- 월 1회 의존성 업데이트 창에서 Cargo, npm, Python, GitHub Actions 버전을 한 번에 검토한다.
- critical 보안 공지는 수동으로 즉시 PR을 만든다.
- 다시 자동화를 도입할 때는 별도 ADR로 도구, 권한, PR 생성 규칙을 먼저 결정한다.
