# ADR 0106: foundation-platform — 등기 대지권 이름이 호 정규화를 교차확증한다

- Status: Accepted
- Date: 2026-09-25

## Context

`catalog.building_unit` 19,536,363행의 호 명칭을 전량 실측한 결과(2026-09-25),
결정적 규칙 사다리가 99.39%를 해결하고 108,054행(0.55%)이 규칙 밖에 남는다.
이 꼬리를 등기 대지권(`silver.land_right_registration`, 호 이름 보유)과 전량
대사했더니:

- 꼬리의 87.7%(94,737행)가 대지권 기록이 있는 필지 위에 있다.
- 양쪽을 각자 정규화한 뒤 비교하면 **39,084행(36.2%)이 유일하게 일치**한다 —
  보수 기준(붙임표 보존)으로 측정했고, 등기가 `6-2`·`24-1` 같은 하위 호를
  그대로 보유해 일치가 실제임을 확인했다.
- 같은 필지 안에서 정규형이 중복 일치하는 모호 사례가 3,865행 있다.

두 장부는 같은 호를 다르게 적는다(등기 `1601` vs 대장 `1601호`, `비-116` vs
`B116`, 동 `0000` = 없음 센티널). 원문 문자열 동일성 비교는 성립하지 않으며,
마지막-숫자런 호번호는 같은 건물 안에서 812,298행이 충돌하므로 호번호 단독
조인도 성립하지 않는다.

## Decision

1. **정규화는 원천별로, 교차는 그다음이다.** 대장 호명은 대장 안의 증거로,
   등기 호명은 등기 안의 증거로 각각 정규화한다. 한 원천의 정규화 입력에 다른
   원천의 값을 쓰지 않는다 — 오류 순환과 계보 소실을 막는다.
2. **교차확증은 dbt entity_resolution 층의 후보 모델로 도출한다.**
   `int_entity_resolution__building_register_unit_land_right_candidates`가
   같은 PNU 범위에서 **양방향 유일**(대장 쪽에서도, 등기 쪽에서도 그 정규형이
   각 1회)할 때만 후보를 낸다. 모호 일치는 후보가 아니다.
3. **정규형은 보수적이다.** 공백·괄호주석 제거, 앞 `제`·뒤 `호` 제거, 층 접두
   제거(지층→`B`), 한글 음역 6종(에이/비/씨/디/에프/에이치)만 영문화, 선행 0
   제거. **붙임표·구분자는 보존한다** — `6-2`와 `62`는 다른 호다. 정규형 SSOT는
   dbt 매크로 `foundation_normalized_unit_name` 한 곳이다.
4. **후보는 `silver_entity_link_assertion_candidate`에 실린다**
   (rule_version `building-unit-land-right-corroboration.v1`, publish_state는
   기존 계약대로 `candidate` 고정). canonical 데이터 적용은 이 층이 하지
   않는다 — 기존 정규화 제안·승인·실버 오버라이드 기계(FP 소관)를 통해서만
   반영된다.
5. **잔여 꼬리는 미루지 않는다.** 교차확증 뒤 남는 약 69,000행(전체의 0.35%)은
   기존 정규화 proposal 파이프라인(엔티티 문맥 포함)으로 전량 제안을 생성하고,
   사람은 제안 검토만 한다.

## Consequences

- 규칙 99.39% + 교차확증 0.20%p = 자동 판정 99.59%. 사람 몫은 제안 검토로
  한정된다.
- 대지권 실버가 dbt 원천(`foundation.land_right_registration`)으로 선언되고,
  스테이징·후보·깔때기 모델과 정적 계약 시험이 추가된다. 깔때기 모델이 운영
  실행 시 위 측정치(39,084)를 재현하는지 대조하는 것이 첫 운영 검증이다.
- 미래의 경매 매칭(GZ `court_auction` 후보 모델)과 같은 정규형 매크로를 공유해
  표기 정규화가 한 곳에 남는다.
- 이 층은 Trino 위 dbt로 로컬/운영자 실행이며 상시 스케줄이 아니다. 상시화는
  별도 결정이다.
