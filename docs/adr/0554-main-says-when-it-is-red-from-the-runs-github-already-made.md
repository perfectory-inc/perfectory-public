# ADR 0554: main 이 깨지면 GitHub 이 이미 돌린 실행에서 읽어 알린다

- Status: Accepted
- Date: 2026-11-12
- Builds on: [ADR-0313](./0313-merge-queue-and-pull-requests-verify-only-what-changed-and-main-does-not-repeat-the-queue.md)(큐·PR 은 바뀐 것만, main 푸시는 큐를 되풀이하지 않는다),
  [ADR-0271](./0271-a-security-advisory-that-arrives-without-a-commit-is-found-by-a-daily-run-and-kept-as-one-issue.md)(일정 전용 작업이 이슈 하나를 맞춰 둔다),
  [ADR-0421](./0421-a-run-that-failed-only-because-its-runner-did-is-re-run-once-and-the-merge-queue-keeps-building-two.md)(러너 때문에만 실패한 실행은 판정이 아니다)

## Context

PR 과 머지 큐는 변경이 닿는 것만 돌리고, main 푸시는 큐가 통과시킨 트리를 다시 돌리지 않는다. 그래서 선택이 놓친
고장은 main 자신의 어디에도 나타나지 않는다. 2026-11-11 실측(`gh api`, 읽기 전용):

| 사고 | 병합 | main 푸시 실행 | 드러난 곳 | 고치는 PR 이 열린 때 | 고쳐진 때 |
|---|---|---|---|---|---|
| #1268 뒤 `foundation-jobs` 시험 실패 | 04:30Z | 전부 초록 | 큐에서 #1281(04:51Z)·#1255(05:11Z)·#1278(05:46Z) 실패 | 05:27Z (57분 뒤) | 07:16Z (2시간 46분) |
| #1302 뒤 공짱 사본 시험 `8 != 6` | 19:04Z | 전부 초록 | 큐에서 #1324·#1330·#1327·#1337 실패 | 20:59Z (115분 뒤) | 21:41Z (2시간 37분) |

두 번 모두 알림은 없었다. 누군가 큐 실패 로그를 읽고 "내 PR 탓이 아니다"를 알아챈 때가 탐지 시각이었다.
전체를 돌리는 매일 밤 실행(17:41Z)은 최대 24시간 뒤에야 본다.

main 에 병합할 때마다 전체를 다시 돌리는 방법은 쓰지 않는다. 바쁜 시간에 표준 러너 20칸이 이미 차 있고
(ADR-0552 측정 3), 전체 실행 하나가 큐 실행 여럿의 자리를 쓴다. 신호는 이미 있다. 큐에서 **서로 다른 PR 둘이 같은
작업에서 연달아 실패**하면 그 작업은 main 에서 깨진 것이다.

## Decision

1. **`scripts/ci/main_health.py` 가 작업마다 마지막으로 일어난 일로 판정한다.** 대상은 PR 을 막는 워크플로
   (`tools/ci/change-scope.json` 에 적힌 것)의 작업이다. `required/*` 는 다른 작업을 되풀이할 뿐이라 뺀다.
   - 단계가 실패한 작업만 실패다. 단계 없이 죽은 작업은 판정이 아니다(ADR-0421).
   - main 자신의 실행(매일 밤 전체 실행, 수동 실행, 푸시 실행)에서 마지막으로 실패한 작업은 빨강이다(최근 26시간).
   - 큐에서 **서로 다른 PR 둘 이상**이 사이에 성공 없이 연달아 실패한 작업은 빨강이다(최근 3시간). 큐 실패 하나는 그
     PR 의 몫이다.
   - 같은 작업이 그 뒤 main 줄기 어디서든(큐·푸시·밤 실행) 성공하면 풀린다. 건너뛴 작업은 아무 말도 하지 않는다.
   - 큐 실패는 3시간 뒤 스스로 풀린다. 아직 깨져 있으면 그 작업에 닿는 다음 PR 이 다시 실패하고, 아무도 닿지 않으면
     아무도 막히지 않는다.
2. **빨강이 하나라도 있으면 `main-red` 라벨의 이슈 하나를 열어 둔다.** 작업과 근거 실행을 표로 적고, 목록이 바뀌면
   고치고, 비면 닫는다. 알림은 GitHub 의 이슈 알림으로 간다. 공개 저장소의 CI 에는 Slack 비밀을 두지 않는다(ADR-0007).
3. **`main-health.yml` 이 10분마다 돈다.** 일정·수동 전용이고, 작업 하나만 작업 수준 `issues: write` 를 가진다.
   ADR-0271 의 `dependency-advisories.yml` 과 같은 예외이고 같은 규칙이다. `tools/conftest/workflow/contracts.rego` 의
   허용 파일 목록에 이 파일 하나를 더했다. 자기 시험은 이 파일의 승인과, push 트리거를 붙이면 거부되는지를 확인한다.
   실패가 막는 사고: 이슈를 쓰는 권한이 PR 코드가 도는 실행으로 번지는 일이다.
4. **GitHub 을 읽지 못한 실행은 이슈를 그대로 둔다.** 502 나 요청 한도는 main 에 대한 판정이 아니다.

## Consequences

- 탐지의 하한은 큐 실행 두 번이다. 고장에 닿는 PR 이 큐에 둘 들어와 실패해야 보인다. 닿는 PR 이 없으면 매일 밤
  실행이 본다(최대 24시간, 전과 같다. 다만 이제 이슈가 열린다).
- 나쁜 PR 둘이 우연히 같은 작업에서 연달아 실패하면 잘못 연다. 그 작업이 다시 통과하거나 3시간이 지나면 닫힌다.
- 일정 작업이 하루 144번 돈다. 각 1분 미만이고 공개 저장소 표준 러너라 비용은 0 이다(계산). API 호출은 실패한
  실행마다 1번, 빨강 후보마다 최대 40번이다. 실행 하나의 작업 목록은 한 번만 읽는다.
- 이슈 본문은 고치는 PR 을 큐 앞에 세우는 길(ADR-0553, `hotfix:main-red`)을 적는다.

## Rejected alternatives

- **main 푸시마다 전체 실행**: 가장 빨리 보지만 병합마다 전체 실행 하나가 러너를 쓴다. ADR-0313 이 그 반복을 없앴고,
  지금 처리량을 막는 것이 그 러너다.
- **호스트(Alertmanager → Slack)에서 감시**: 호스트는 GitHub 을 익명으로 읽고 한도가 시간당 60번이다. 자동 배포의
  판정이 그 한도를 쓴다.
- **큐 실패 하나로 알림**: 큐 실패의 대부분은 그 PR 자신의 것이다(11-11 하루 큐 실행 실패 13건 중 main 탓은 7건).
