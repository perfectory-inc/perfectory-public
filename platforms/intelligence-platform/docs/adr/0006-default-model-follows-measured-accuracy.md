# ADR 0006 — 기본 모델은 실측 정확성을 따른다: gemma2:9b → Qwen3.6-35B-A3B

- 상태: Accepted
- 날짜: 2026-09-19
- 소유자: Intelligence Platform
- 관련: [ADR-0002](./0002-canonical-release-rag-design.md) · [사례 레퍼런스](../../../../docs/reference/knowledge-search-industry-cases.md)

## 배경

기본 모델 `gemma2:9b`는 설정 예시가 처음 쓰일 때 서버에 있던 것을 그대로 적은 값이지
측정으로 고른 값이 아니었다. 지식 파이프라인의 다음 단계(distillation — 고시문에서
질문·요약·결정·근거를 구조화 추출)가 모델 품질에 직접 걸리게 되어, 실제 고시문으로
후보들을 측정했다.

## 측정

무안군 고시 제2019-203호 전문(6쪽, 텍스트 PDF에서 추출), 온도 0.1, JSON 강제,
같은 프롬프트. 서버는 ai-server(RTX 3060 7.6GiB — 대형 모델은 CPU 분담). **문서 1건의
단일 표본이며**, 최종 판정은 코퍼스 도착 후 평가 세트가 한다.

| 모델 / think | 웜 지연 | 사실 정확성 | 추출 깊이 |
|---|---|---|---|
| gemma2:9b | 17.1s | **오류** — 요약이 변경 전 날짜(2019)를 변경 후처럼 서술, 자기 changes 배열과 모순. 온도 0.1에서 **2회 재현** | 변경 1건 |
| **Qwen3.6-35B-A3B (Q4, MoE), think=false** | **9.8s** | 결함 없음 | 변경 1건 |
| qwen3.8:27b (Q4, dense), think=기본 | 396s | 결함 없음 | **변경 2건 + 면적·유치업종** |
| qwen3.8:27b, think=false | 73.5s | 결함 없음 | 변경 2건 (decision 서술은 얕아짐) |
| qwen3.8:27b, think=low | 191s | **오류** — gemma2와 같은 자리에서 날짜 뒤바뀜 | 변경 2건 |

## 결정

1. **기본 모델을 `hf.co/unsloth/Qwen3.6-35B-A3B-GGUF:UD-Q4_K_M`로 바꾼다.**
   측정에서 유일하게 "정확하면서 가장 빠른" 조합이다. MoE(35B 중 ~3B 활성)라
   CPU 분담 환경에서도 문서당 ~10초로, 18,582건 전량 distillation이 이틀 안이다.
2. **reasoning 모델이므로 `MODEL_RUNTIME_REASONING_EFFORT=none`을 기본 예시에
   포함한다** — README가 이미 요구하던 설정이다.
3. **gemma2:9b는 이 파이프라인의 판정 역할에서 제외한다.** 한국어 법령 날짜의
   전후를 뒤바꾸는 결함이 재현됐다. 요약이 원문과 반대로 말하는 오류는 법령
   정보에서 미완성이 아니라 틀림이다.
4. **qwen3.8:27b(think=false)는 심층 2차 패스 후보로 보관한다.** 다른 모델이 놓친
   두 번째 변경사항(수용·사용 토지 세목)까지 잡는 유일한 모델이지만 문서당 73.5초라
   전량에는 못 쓴다. 선별 문서에만 쓰는 구도가 맞다.
5. **qwen3.8의 `think=low`는 쓰지 않는다.** false보다 느리면서 정확성 결함을
   들여왔다 — 어중간한 생각이 무생각보다 나빴다.

## 이 결정이 아닌 것

- 임베딩·벡터 provider 선정이 아니다. [ADR-0002](./0002-canonical-release-rag-design.md)의
  금지는 그대로다 — 이것은 이미 존재하던 `MODEL_RUNTIME_DEFAULT_MODEL` 예시 값의 교체다.
- distillation 파이프라인 설계 승인이 아니다. 그 설계는 코퍼스와 평가 세트를 기다린다.

## 운영 사실 (측정 중 확인)

- ai-server GPU는 **RTX 3060 7.6GiB**다. 20GB급 모델은 전부 CPU 분담으로 돌며, 이것이
  대형 모델 지연의 주원인이다. 모델 선택보다 하드웨어가 먼저 병목이 될 수 있다.
- 서버의 시스템 Ollama(0.30.10)는 qwen3.8 계열을 거부한다(412). 평가를 위해
  **사용자 공간 병행 인스턴스**(v0.34.2, `:11435`, 모델은 `/data/ollama-models`)를
  띄웠다 — 시스템 서비스 무접촉, 제거는 프로세스 종료와 디렉터리 삭제로 끝난다.
  시스템 Ollama 승격은 root 권한이 필요하므로 별도 운영 결정이다.

## 재검토 트리거

| 조건 | 검토 대상 |
|---|---|
| 평가 세트에서 Qwen3.6의 추출 누락이 문제로 측정됨 | qwen3.8 2차 패스 도입 |
| GPU 교체(VRAM ≥ 20GB) | qwen3.8 기본 승격 재평가 |
| 새 모델 출시 | 같은 고시문 표본으로 같은 측정을 먼저 |

**측정 없이 트리거를 당기지 않는다.**
