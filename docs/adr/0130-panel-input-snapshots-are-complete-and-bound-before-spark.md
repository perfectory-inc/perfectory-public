# ADR-0130 — 필지·건물 조회자료는 입력 판 전체를 고정한다

## 원인과 불변식

`parcel_panel_silver_to_gold.py`는 `--iceberg-snapshot-id`를 기록하면서 실제로는 현재 표를
읽었다. 건물 생산자는 입력 판 파일을 지원했지만 파일이 없으면 표제부만 고정하고 다른
표는 현재 판을 읽었다. 검사와 쓰기 사이에 원천 표가 갱신되면 같은 실행 인자로 다른
내용을 만들 수 있었다. 판 파일을 검사 뒤 다시 읽는 것도 같은 문제를 허용한다.

Iceberg 입력을 쓰는 두 생산자는 **사용할 모든 표의 판을 실행 시작 전에 한 번 읽고**,
모든 조회와 실행 요약이 그 동일한 매핑을 사용해야 한다. 원본의 논리적 수집 번호
`source_snapshot_id`와 Iceberg의 물리적 판 번호는 서로 다른 사실로 기록한다.
필지의 지번 변경 연결을 사용할 때는 `silver.parcel_lineage`도 필수 입력이다.

## 결정

- 건물 생산자에 이미 있는 `--source-snapshots-path`의 JSON 매핑 형식을 재사용한다.
  필요한 표 목록은 각 생산자의 기존 입력 상수가 소유한다. 새 표 목록·원장은 만들지 않는다.
- 공통 `lakehouse_snapshot_pins.py`가 파일 해석과 Iceberg 고정 조회를 소유한다.
  두 생산자는 같은 함수를 호출한다. 누락·추가·중복 키, 잘못된 숫자, 기준 표와 CLI 판의
  불일치는 Spark 시작 전에 거부한다. 검사 전용 실행도 같은 규칙을 따른다.
- Iceberg 모드에서는 완전한 매핑이 필수다. 암묵적으로 현재 판을 선택하지 않는다.
  Parquet 모드에는 물리적 Iceberg 판을 주장하지 않으며 판 파일을 거부한다.
- 조회는 Iceberg의 `DataFrameReader.option("snapshot-id", ...)`를 사용한다.
  판이 만료되거나 사라지면 실패하며 현재 판으로 대체하지 않는다.
- 실행 요약의 `source_iceberg_snapshots_by_dataset`에 실제 조회에 사용한 매핑을 남긴다.
  기존 논리적 수집 번호 목록의 의미는 바꾸지 않는다.

## 재사용과 기각한 대안

Apache Iceberg의 [고정 판 읽기](https://iceberg.apache.org/docs/latest/spark-queries/#time-travel-queries-with-dataframe)를
사용한다. 이미 채택된 Apache-2.0 의존성의 기능이라 새 서버·라이브러리·데이터 복사가 없다.
별도 데이터 복사본을 만들어 고정하는 방법은 저장·전송 비용을 늘려 기각한다.
실행 전후에 현재 판만 비교하는 방법은 실행 도중 다른 판을 읽는 일을 막지 못한다.
필지에 건물의 해석 코드를 복제하는 방법은 같은 규칙을 두 곳에 남기므로 기각한다.

## 검증과 경계

누락·중복·추가·범위 밖 숫자·기준 판 불일치를 양쪽 진입점에서 검사하고, 입력 판 파일이
검사 뒤 바뀌어도 이미 해석한 매핑을 쓰는지 확인한다. 격리 Linux 시험 환경의 실제 Spark/Iceberg 시험
저장소에서 현재 판을 바꾼 뒤에도 고정된 과거 값을 읽고, 없는 판은 실패하는지 확인한다.

표별 판을 고정하는 것은 여러 표가 같은 업무 시점을 나타낸다는 증명이 아니다. 수집 범위,
논리적 판 호환성, 누락 지번 연결자료의 정식 생성, 출력의 검증 후 승격·복구·예약은 별도다.
운영 실행 목록은 [운영 준비 작업 목록](../roadmap/production-readiness.md)이 소유한다.
