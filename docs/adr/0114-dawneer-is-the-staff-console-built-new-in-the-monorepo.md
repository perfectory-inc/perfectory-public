# ADR 0114: 더니어는 모노레포 안에 새로 짓는 직원 통합 콘솔이고, 고객 제품과 다른 자리(`consoles/`)에 둔다

- Status: Accepted
- Date: 2026-09-30
- Builds on: [GZ-ADR-0050](../../products/gongzzang/docs/adr/0050-dawneer-workbench-and-internal-admin-surface.md)(직원 화면은
  더니어 하나, 더니어는 화면만 소유), [ADR-0001](./0001-monorepo-governance-and-conventions.md)(모노레포 통합)
- Revises: `products/gongzzang/AGENTS.md` 의 "dawneer — 별도 repo, 모노레포 미통합" 행

## Context

- 2026-07-19 모노레포 통합(ADR-0001) 때 공짱과 세 플랫폼은 들어왔고 더니어만 별도 저장소로 남았다. 그
  저장소는 산업단지 B2B 작업대(Next.js 16, AWS Amplify·RDS, 자체 로그인 Better Auth)이고, Rust 재구축
  계획(D0–D9)은 2026-06-01 초안에 머물러 있다. 검토·승인·지도 편집·파이프라인 관리 계획은 없다(2026-09-30 확인).
- 사용자 결정(2026-09-30): 더니어는 **통합관리도구**다 — 모든 파이프라인, 인사, 데이터, 승인을 여기서 다룬다.
  Foundation·Identity 등 플랫폼과 아주 밀접하다. 옛 저장소를 이어받지 않고 **새로 짓는다**.
- 지금 사람이 할 일이 쌓이는데 화면이 없다: 필지 계보 검토(ADR-0113 §10), 지도 폴리곤 편집(ADR-0112),
  정규화 제안 승인, 타일 승격·되돌리기. API 는 대부분 Foundation 에 있다.
- 사례: AWS 콘솔은 공통 틀(로그인·메뉴·권한) 하나에 서비스 팀이 자기 화면을 붙이고, Spotify Backstage 는
  포털 하나에 팀별 플러그인을 꽂는다. 둘 다 틀은 조립만 하고 기능의 규칙과 데이터는 각 팀이 가진다. 대형
  모노레포(Google·Meta)는 사내 도구도 같은 저장소에 두어 플랫폼 API 변경이 도구까지 같이 검사된다.

## Decision

1. **더니어는 이 모노레포의 `consoles/dawneer` 에 새로 짓는다.** 옛 저장소(`dawneer` 별도 repo)는 이어받지
   않는다. 코드를 옮겨 오지 않으며, 그 저장소는 새 콘솔이 같은 일을 할 때 은퇴한다.

2. **최상위 자리는 셋이다.** `platforms/` — 데이터·규칙·API 의 주인. `products/` — 고객이 쓰는 것(공짱).
   `consoles/` — 직원이 쓰는 것(더니어). 고객 제품과 직원 콘솔은 배포·권한 경계가 다르므로 같은 줄에 두지
   않는다. 고객용 배포물에 직원 기능이 섞이지 않는다.

3. **더니어는 틀만 가진다(GZ-ADR-0050 유지).** 로그인 화면, 메뉴, 레이아웃, 작업 상태, 화면 조립. 기능의
   규칙·데이터·권한 판정은 그 기능의 주인이 가진다: Foundation(데이터·파이프라인·지도·계보 검토),
   Identity(직원·인사·권한), Intelligence(AI 제안), 공짱(자기 고객·매물). 더니어는 자기 DB 에 도메인 데이터를
   복사하지 않고, 쓰기는 반드시 주인의 API 를 거친다. 결정의 정본은 주인 쪽(레이크하우스 행 등)이다.

4. **서버는 Rust, 화면은 TypeScript.** 더니어 서버는 플랫폼의 계약 타입(Rust crate)을 경로 의존으로 직접
   쓴다 — 계약을 베낀 사본을 두지 않는다. 플랫폼 API 가 바뀌면 같은 CI 가 더니어 빌드까지 깨뜨린다.
   직원 로그인은 Identity Platform(Zitadel)이 한다.

5. **플랫폼은 더니어가 부를 관리 API 를 계약으로 먼저 낸다.** 화면이 없는 동안 사람의 결정은 같은 API 를
   부르는 명령줄 도구와 슬랙 요약으로 받는다. 화면이 생기면 같은 API 에 붙기만 한다.

## Consequences

- `products/gongzzang/AGENTS.md` 의 영역 표와 루트 `AGENTS.md`·`README.md` 의 영역 목록에 `consoles/dawneer`
  가 "계획, 아직 없음"으로 들어간다. 디렉터리는 첫 코드가 들어올 때 만든다 — 빈 자리를 먼저 만들지 않는다.
- 첫 소비 기능은 필지 계보 검토(ADR-0113 §10)다. Foundation 이 검토 목록 읽기·결정 쓰기 API 를 계약과
  함께 먼저 낸다.
- 비용: 옛 더니어의 산업단지 사이트 제작 기능은 이어받지 않는다. 필요하면 공짱 쪽 제품 기능으로 따로 판단한다.
  모노레포 가드(영역 목록을 세는 검사)는 `consoles/` 가 생길 때 함께 늘린다.
- 되돌릴 조건: 더니어를 독립 팀이 따로 배포·운영해야 하는 보안 경계가 실제로 생기면 저장소 분리를 다시 본다
  (GZ-ADR-0050 의 재검토 조건과 같다).
