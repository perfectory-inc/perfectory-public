# ADR 0113: 필지 계보와 고정 필지 ID 가 지역 개편·합병·분할을 코드로 흡수하고, 모든 지도 굽기 앞에서 폴리곤 매칭을 검문한다

- Status: Accepted
- Date: 2026-09-29
- Builds on: [ADR-0103](./0103-place-identity-outlives-administrative-code-changes.md)(안정 ID·시간 사전·해석기·스튜어드),

## Context

2026-07-01 에 두 개편이 동시에 시행됐다. 광주(29)+전남(46) → 전남광주통합특별시(12), 인천 중구·동구·서구 →
제물포구(28125)·영종구(28155)·서해구(28275)·검단구(28290). 2026-09 원천은 이미 새 코드로 온다.
2026-09-29 에 **코드만으로**(폴리곤은 근거에서 제외) 실측한 사실:

| 대상 | 7월 필지 | 같은 지번·새 코드로 이어짐 | 사라짐 / 생김 | 9월 필지 |
|---|---:|---:|---:|---:|
| 광주+전남 → 12 | 6,315,425 | 6,303,927 (99.82%) | 11,498 / 6,773 | 6,310,700 |
| 인천 전체 | 667,468 | 665,283 (99.67%) | 2,185 / 2,504 | 667,787 |

- 두 경우 모두 `7월 − 사라짐 + 생김 = 9월` 이 정확히 성립한다. 사라짐·생김의 대부분은 토지이동이력에 사유가
  적힌 평소 변동(합병·분할·지적재조사·등록전환)이다. 광주+전남은 사유 미확인 916(0.015%), 인천은 1,058
  (지적재조사 지구·지도 반영 지연으로 보이나 인천은 미검증).
- 법정동 수준: 공식 법정동코드 전체자료(존재/폐지)에서 (시군구명, 동명)으로 광주+전남 2,947개 동 전부 1:1,
  인천 80개 동 중 78개 1:1. 동명이 겹치는 금곡동 2개는 지번 겹침률(100%)로 갈린다.
- **인천 997필지**(옛 서구 시천동·오류동 일부 → 서해구 검암동 875·경서동 122)는 지번까지 새로 매겨졌다.
  토지이동이력은 7/1 "행정관할구역변경"으로 이 997개 **새 번호**를 정확히 싣지만 옛 번호는 없다.
  필지고유번호변동연혁(VWorld 30527, 인천 2026-09-15판)의 7/1 기록은 중구→제물포구 동 단위 44건뿐이다.
  건축물대장 고유번호 연속성으로 78개가 옛 번호와 이어지고, 면적(0.1㎡)·지목·소유구분·공유인수가 모두
  맞는 유일한 짝이 그 78개 중 77개와 일치했다(불일치 1은 대장의 "산 0-0" 오기).
- **위험:** 9월 지도 폴리곤은 새 번호인데 공시지가·토지특성·소유 파일은 2026-05-26 이 최신이라 옛 번호다.
  그대로 붙이면 인천 폴리곤 132,613개(19.9%)의 공시지가가 빈다. 옛·새 연결을 거치면 전부 붙고, 남는
  빈칸은 정부 공시지가가 원래 없는 땅(4.0%)과 기준일 이후 생긴 필지(0.25%)뿐이다.
- 설계 문서(`docs/reference/geography-identity-wave1-technical-design.md` §4)의 필지 계보 DAG 는 표 모양까지
  있으나 구현이 없다. ADR-0103 은 동 수준 해석기를 정했지만 필지 수준 연결과 지도 매칭 검문은 정하지 않았다.

## Decision

1. **필지 계보 표를 레이크하우스 정본으로 둔다.** `silver.parcel_lineage` — 한 행이 "옛 PNU → 새 PNU" 하나다.
   칸: `predecessor_pnu, successor_pnu, relation, cardinality, effective_date, grade, evidence_kind, evidence_ref,
   derived_at_utc, derivation_run_id`. `relation ∈ {code_change, jurisdiction_transfer, registration_conversion,
   merge, split, resurvey, other}`, `cardinality ∈ {1:1, 1:N, N:1, N:M}`. 덮어쓰지 않고 쌓는다(append-only).
   시험: 같은 입력으로 두 번 돌리면 새 행이 0개이고, 근거가 바뀌면 새 행이 붙을 뿐 옛 행은 남는다.

2. **필지는 PNU 가 아니라 바뀌지 않는 필지 ID 로 식별한다(ADR-0103 1항의 필지판).** `parcel_id` 는 불투명한
   UUID 이고 PNU 는 속성이다(CoreLogic CLIP·Overture GERS·Regrid `ll_uuid` 와 같은 자리).
   - **ID 가 이어지는 변화:** 1:1 이고 `relation ∈ {code_change, jurisdiction_transfer, registration_conversion}`
     이며 등급이 `evidence_strong` 이상인 계보 — 땅은 그대로이고 번호만 바뀐 경우.
   - **새 ID 가 나오는 변화:** 합병·분할·지적재조사, 그리고 등급이 `evidence_weak` 이하인 계보. 옛 ID 는
     지우지 않고 과거 상태가 되며, 계보가 옛 ID 와 새 ID 를 잇는다(LINZ·Esri Parcel Fabric 의 historic 규칙).
   - **나중에 등급이 올라 "같은 땅"으로 확정되면** 새로 낸 ID 를 폐기하지 않고 옛 ID 로 **리다이렉트**한다
     (FIGI·GERS 의 폐기 ID 처리). ID 는 재사용하지 않는다.
   - ID 값은 다시 돌려도 같게 나와야 하므로 `uuid5("parcel:" + 계보 사슬에서 처음 본 PNU + ":" + 그 PNU 를
     처음 본 스냅숏 날짜)` 로 정한다. 시험: 광주 필지 하나를 7월(29…)과 9월(12…) 스냅숏에서 각각 조회하면
     같은 `parcel_id` 가 나오고, 합병된 두 필지는 합병 뒤 새 `parcel_id` 하나가 되며 옛 둘은 과거 상태로 남는다.

3. **필지 상태 표를 양시간으로 둔다.** `silver.parcel_registry` — `parcel_id, pnu, status ∈ {current, historic,
   redirected}, redirect_to, valid_from, valid_to, recorded_at_utc, source_snapshot_id`. `valid_*` 는 실세계
   유효기간(개편 발효일·합병일), `recorded_at_utc` 는 우리가 안 시각이다(ISO 19152 LADM `VersionedObject`,
   Kimball SCD2). 시험: "2026-03-01 기준 이 PNU 의 땅"과 "2026-09-01 기준 같은 땅의 PNU"가 모두 답해진다.

4. **등급은 근거로만 정하고, 높은 등급이 효력을 가진다.** 도출 규칙과 등급(높은 순):
   - `official` — 필지고유번호변동연혁의 짝, 토지이동이력의 합병·분할 문구가 가리키는 같은 동 안의 지번.
   - `code_derived` — (a) 같은 지번 + 공식 코드목록으로 1:1 대응된 법정동, (b) 건축물대장 고유번호가
     개편 전후 스냅숏에서 같은 건물.
   - `evidence_strong` — 면적(0.1㎡)·지목·소유구분·공유인수가 모두 같고 양쪽에서 유일한 짝.
   - `evidence_weak` — 면적·지목이 유일하게 같되 소유 자료가 없거나, 소유로 동률을 가른 짝.
   - `needs_review` — 면적·지목은 유일하게 같은데 소유가 다른 짝.
   - `pending` — 짝 없음.
   효력 연결 = 한 옛 PNU 에 대해 가장 높은 등급의 행. 높은 등급이 낮은 등급과 다른 짝을 가리키면 경보를 낸다
   (병원 EMPI 의 definite/probable/possible 등급과 같은 구조). **폴리곤 겹침·포함은 어떤 등급의 근거도
   아니다** — 표시와 품질 점검에만 쓴다. 시험: 폴리곤만 일치하는 짝을 심으면 `pending` 에 머문다.

5. **법정동 대응은 공식 코드목록의 연속 스냅숏에서 나온다(ADR-0104 확장).** 코드목록은 (코드, 전체 이름,
   존재/폐지)만 주므로 대응 규칙은: 같은 날 폐지된 코드와 새로 존재하게 된 코드 사이에서 (시군구명, 동명)
   일치 → 없으면 동명 유일 일치 → 그래도 동률이면 지번 겹침률이 더 높은 쪽. 동 대응은 계보의 `code_change`
   를 만드는 입력이며, 지번 겹침률이 95% 미만인 동 대응은 분할 신호로 보고 해당 동의 사라진 지번만 4항의
   증거 규칙으로 넘긴다(시천동: 겹침 37.8% → 871 지번이 증거 규칙으로).

6. **속성 붙이기는 필지 ID 를 거친다.** 모든 속성(공시지가·토지특성·소유·건물)은 그 속성의 기준 시점 PNU 로
   들어오므로, 상태 표로 그 시점의 PNU 를 `parcel_id` 로 바꾸고 현재 지도 폴리곤의 `parcel_id` 에 붙인다.
   분할·합병을 건넌 값은 "원래 필지의 값"으로만 붙인다. 붙은 경로(`same_pnu | lineage:<grade>`)를 서빙 행에
   남기고, `evidence_*` 로 붙은 값은 화면에서 구분할 수 있어야 한다.

7. **모든 필지·행정경계 굽기 앞에 매칭 검문을 둔다.** 굽기(ADR-0112)는 다음을 통과해야 한다:
   (a) 모든 폴리곤의 법정동이 공식 코드목록에서 "존재"이고 그 읍면동에 경계가 있다 — 위반 0;
   (b) 모든 폴리곤이 `current` 상태의 `parcel_id` 를 하나씩 갖고, 스냅숏 간 `전 − 사라짐 + 생김 = 후` 가
   성립한다(LINZ 의 "폐기 필지는 새 필지로 빈틈없이 대체" 규칙);
   (c) 속성 빈칸은 허용 사유(원천에 값이 없음, 기준일 이후 생김, 계보 `pending`)로만 설명되고, 허용 사유
   밖의 빈칸이 0 이다. 위반이 있으면 굽지 않고 슬랙에 사유별 개수를 보낸다. 매일 같은 대사를 돌려 사유
   미확인 목록을 남기고 다음 원천이 오면 다시 확인한다. 시험: 속성 PNU 하나를 옛 코드로 바꿔 심으면 계보가
   없을 때 검문이 거부하고, 계보를 넣으면 통과한다.

8. **스냅숏마다 세 파일을 발행한다(Overture GERS 의 registry·bridge·changelog).** 지도 스냅숏이 승격될 때
   레이크하우스 Gold 에 함께 쓴다:
   - **ID 목록** — 지금까지 발급한 모든 `parcel_id`·행정경계 id 와 상태(`current / historic / redirected`).
   - **연결 파일** — `parcel_id ↔ PNU ↔ 법정동코드` 와 유효기간.
   - **변경 내역** — 이번 스냅숏에서 생김·과거화·번호변경·리다이렉트된 ID 와 그 계보 근거.
   API·웹은 저장해 둔 옛 참조(관심 필지, 공유 링크, 매물의 필지)를 이 파일로 현재 ID 에 다시 잇는다.
   시험: 옛 PNU 로 저장된 관심 필지가 다음 스냅숏 뒤에도 같은 땅을 가리킨다.

9. **행정경계 id 도 같은 규칙을 따른다(ADR-0112 개정).** ADR-0112 이행에서 쓴
   `uuid5("scope:legal-dong:" + 현재 코드)` 는 코드가 바뀌면 id 가 바뀌어 ADR-0103 1항을 어긴다. 새 규칙은
   `uuid5("scope:legal-dong:" + 5항 승계 사슬의 가장 이른 코드)` 다. 분할된 동(시천동)은 지번 대부분이 남은
   쪽이 id 를 잇고, 떨어져 나간 부분은 받는 동(검암동)의 id 에 흡수된다. 표시(이름·코드)는 항상 현행이다.
   시험: 광주 동구 학동(2911012200)과 전남광주 동구 학동(1221012200)이 같은 id 를 갖는다.

10. **사람은 `needs_review`·`pending` 만 본다.** 스튜어드 결정은 코드가 아니라 계보 행(`evidence_kind =
    steward`, 결정자·근거·시각)으로 쌓인다(ADR-0103 4항). 매일 슬랙 요약: 새 개편 감지, 등급별 건수 변화,
    리다이렉트, 검문 결과.

11. **수집은 이 ADR 의 범위 밖이다.** 위 표의 원천(특히 법정동코드 전체자료, 30527, 토지이동이력 CH/AL,
    건축물대장 월별)을 매일 받는 일은 수집 레인이 한다. 이 ADR 의 도출은 Bronze 에 있는 것만 읽고, 원천이
    늦으면 등급이 늦게 오를 뿐 잘못된 연결을 만들지 않는다.

## Consequences

- 지역 개편·합병·분할·지적재조사가 같은 경로로 흡수된다. 개편 때 엔지니어가 할 일은 없고, 사람은
  `needs_review`·`pending` 만 본다. 이번 개편 기준 인천 997필지 중 `code_derived` 78, 증거 등급 약 770,
  `needs_review` 65, `pending` 89 로 시작한다(2026-09-29 측정).
- 굽기가 매칭 검문을 통과해야 하므로, 옛 코드 속성이 새 코드 지도에 안 붙어 "가격이 빈 지역"이 생기는
  사고(인천 기준 19.9%)가 운영에 나가지 않는다.
- 서비스의 모든 필지 참조가 `parcel_id` 로 옮겨 간다. 코드가 바뀌어도 관심 필지·가격 이력·링크가 끊기지
  않고, 분할·합병은 "원래 필지"로 따라간다. 이미 PNU 로 저장된 참조는 8항의 연결 파일로 일회 전환한다.
- 비용: 계보 도출 Spark 작업(스냅숏 쌍마다), 상태 표 갱신, 스냅숏마다 세 파일 발행, 속성 붙이기의 ID 조인,
  검문 단계, 스튜어드 목록. 속성 파일마다 기준 시점 PNU 를 유지해야 한다(현재 Silver 는 이미 원천 PNU 를
  보존한다). 전국 약 4천만 필지의 첫 ID 발급은 한 번의 대량 작업이다.
- ADR-0112 로 올라간 행정경계 서빙본(`gold.administrative_boundary_served`)은 9항 규칙으로 id 를 다시 계산해야
  한다. 7월 스냅숏은 개편 전 코드가 곧 사슬의 첫 코드이므로 id 가 그대로이고, 9월 스냅숏을 들일 때부터
  차이가 난다.
- 우리는 Regrid 보다 엄격하다. Regrid 는 폴리곤 겹침으로 ID 를 옮기고 계보 파일을 두지 않지만, 우리는 코드와
  공식 기록만 근거로 삼고(LINZ·Esri 방식) 계보를 남긴다.
- 후속 PR 순서: ① 계보 표·도출(1·4·5항) ② 필지 ID·상태 표(2·3항) ③ 행정경계 9월 스냅숏과 id 개정(9항)
  ④ 검문(7항) ⑤ 세 파일 발행(8항) ⑥ 속성 붙이기(6항) ⑦ 스튜어드 목록(10항).
