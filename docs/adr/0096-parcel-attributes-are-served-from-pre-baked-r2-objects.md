# ADR 0096: 필지 속성은 R2 미리구운 객체로 서빙한다

- Status: Accepted
- Date: 2026-09-08

## Context

지금까지 우리는 수집·정제한 대량 데이터(필지 3,986만·토지이동이력 1.21억·용도지역
4,784만·세대 공시가격 1.88억 등)를 **전부 서빙용 PostgreSQL 로 투영**해 왔다. by-pnu
패널은 그 PostgreSQL 을 색인 조회한다. 이 방식은 다음 문제를 만든다.

- **비용**: 서빙 DB 가 수억 행으로 커진다. AWS(RDS/Aurora) 이전 시 큰 인스턴스가
  필요해 월 비용이 크다. 이는 우리가 R2(저비용·**egress 무료**)를 정본으로 고른 이유와
  정면으로 어긋난다.
- **운영 취약성**: 2026-09-08 세대 가격 1.88억 행 투영이 서버 루트 SSD(240GB, 상시 98%)를
  가득 채워 롤백됐다. 서빙 DB 가 커질수록 이런 디스크·튜닝·단일 장애점 문제가 반복된다.
- **패러다임**: 대량 데이터를 서빙 DB 로 통째 복사(reverse-ETL)는 안티패턴으로 불린다.
  넷플릭스는 레이크하우스(Iceberg+S3)를 정본으로 두고, 서빙할 모양만 배치로 **가벼운
  KV 저장소**에 밀어낸다(Bulldozer). 우리는 이미 **지도 타일을 R2 에서 직접 서빙**하고
  있어, 속성 데이터도 같은 방식이 가능하다.

**실측(2026-09-08)**: postgres 색인 by-pnu 조회 ≈ 31ms, R2 객체 직접 GET(서버→R2
인터넷 경유) ≈ 74ms. 즉 **속도는 R2 가 더 빠른 게 아니다** — 서버 근처에선 postgres 가
비슷하거나 약간 빠르다. 전환의 근거는 속도가 아니라 **비용·운영 안정성·확장성·AWS
이전 용이성**이다. Worker(Cloudflare 내부)→R2 + 엣지 캐시는 이보다 빠를 것으로 추정하나
실물 전 미측정이다.

민감도 요건(사장 확인): 기본 토지정보는 공개 가능하나 **나중에 비공개로 전환 가능**해야
하고, 향후 수집할 **개인정보·서류는 개인정보보호법상 무슨 수를 써서라도 비공개**여야 한다.

이 결정은 새 방향이 아니라 **ADR-0006(객체 저장소 우선 제공)** 과 지도 타일 발행
(ADR-0039)이 이미 세운 "정적 아티팩트를 R2 에서 직접 서빙" 원칙을 **필지 속성 데이터로
확장**하는 것이다.

## Decision

1. **서빙 정본은 R2 의 미리구운 객체다.** 필지의 공개 패널 데이터는 필지 하나당 합성
   JSON(`serving/parcels/by-pnu/v{generation}/{pnu}.json`) 으로 R2 에 굽는다. 한 객체가
   그 필지 패널이 보여주는 전부(기본·공시지가·토지특성·임야·이동이력·대지권·세대 가격)를
   담는다. 세대별 가격 이력도 이 객체 안에 포함한다. **서빙 형식은 JSON 으로 시작한다**
   (브라우저 native·디버깅 용이, Cloudflare 가 전송 시 자동 압축). Parquet 은 칼럼형이라
   한 건 조회에 부적합하므로 서빙에 쓰지 않는다(분석용 Iceberg 는 계속 Parquet). 형식
   결정은 Worker 계층에 격리되어, 특정 핫패스가 크거나 뜨겁다고 **측정되면** 그 경로만
   MessagePack/FlatBuffers 로 승격할 수 있다(구조 불변, 락인 없음).
2. **서빙 경로에 서버를 두지 않는다.** 브라우저는 얇은 Cloudflare Worker
   (`catalog.gongzzang.app/parcels/by-pnu/{pnu}`) 를 통해 현재 generation 의 객체를 받고,
   응답은 엣지 캐시된다. Worker 는 **민감도 정책의 단일 지점**이다: 공개 데이터는 통과+캐시,
   (향후) 비공개 데이터는 인증·접근통제·무캐시·감사로그.
3. **민감도 2계층.** 공개 계층(현재 토지정보)은 R2 미리굽기+엣지. 비공개 계층(향후
   개인정보·서류)은 **공개 R2 경로에 절대 올리지 않는다** — 별도 인증 경로로만, 캐시 금지.
   이 ADR 은 공개 계층을 구현하고 비공개 계층은 인터페이스만 예약한다(YAGNI).
4. **굽기는 배치이며 타일 파이프라인을 재사용한다.** R2 Iceberg 를 읽어 필지별 JSON 을
   합성해 R2 에 쓰고 manifest 로 generation 을 고정한다(무중단 세대 교체, 타일 발행과
   동일). 매일 배치에서 **바뀐 필지만 재굽기**한다.
5. **PostgreSQL 은 소형 운영 데이터로 축소한다.** by-pnu 읽기 경로는 R2 로 옮긴다.
   산업단지 목록·사용자·설정 등 검색·수정·조인이 필요한 **작은** 데이터만 postgres 에
   남긴다. 이미 투영한 대형 표들은 후속 ADR 에서 순차적으로 R2 굽기로 대체한다.
6. **세대 가격 postgres 적재(ADR-0095 의 catalog 투영)는 취소한다.** silver.unit_official_price
   1.88억 행(스냅숏 5418698144561658655)은 폐기하지 않고 R2 굽기의 **원천으로 재사용**한다.
   ADR-0095 의 조인·Silver 결정은 유효하며, catalog 서빙 투영 부분만 이 ADR 이 대체한다.
7. **한 레인 먼저 증명한다.** 최초 구현은 필지 by-pnu 공개 패널 한 레인으로 한정한다:
   굽기→R2→Worker→브라우저를 끝까지 증명하고(동작·비용·엣지 지연 측정), postgres by-pnu
   응답과 대조한다. 증명 후 다른 레인·표로 일반화한다.

## Consequences

- **비용**: 서빙 인프라가 대형 DB(월 수십만원+)에서 R2 저장(월 수천원)+Worker+무료 egress
  로 내려간다. AWS 이전 시 서빙은 거의 손대지 않는다.
- **운영**: 서빙 경로에 서버가 없어 오늘 같은 디스크 풀·단일 장애가 원천 소멸한다. 굽는
  서버(굽는 배치 호스트)가 죽어도 마지막 generation 이 계속 서빙된다.
- **속도**: 서버 근처 단일 조회는 비슷하거나 postgres 가 약간 빠르다. 전 세계 사용자·부하
  급증에는 엣지가 유리하다. 속도는 이 전환의 목적이 아니다.
- **비용의 형태 변화**: 저장·조회 요금이 R2 연산 요금으로 바뀐다. 전량 재굽기(약 4천만
  객체)는 일회성 쓰기 비용이 있으나, 매일은 바뀐 필지만이라 미미하다.
- **새 배관**: 필지별 JSON 합성·재굽기·manifest 배관을 만든다. 타일 파이프라인 재사용으로
  새 개념은 아니다.
- **후속**: 이미 postgres 에 투영한 대형 표들(이동이력·용도지역 등)을 R2 굽기로 되돌리는
  순서, 그리고 비공개 계층(개인정보·서류) 인증 경로는 별도 ADR 로 다룬다.
