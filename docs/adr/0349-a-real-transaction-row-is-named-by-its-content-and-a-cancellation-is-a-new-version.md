## Context

실거래 내보내기는 거래마다 번호를 주지 않는다. `NO` 는 그 내보내기 안의 줄 번호일 뿐이다. 같은 달을 다시 받으면
(ADR-0348 §4) 그 사이에 몇 가지가 바뀐다.

- 새 신고가 들어온다.
- `해제사유발생일` 이 채워진다.
- 아파트·연립은 `등기일자` 가 채워진다.
- 드물게 행이 고쳐지거나 빠진다.

같은 날·같은 값의 거래가 한 달에 두 번 나올 수도 있다(같은 단지·층·면적).

내보내기의 `시군구` 는 법정동 전체 이름이다(예 `경기도 김포시 대곶면 대명리`). 지번은 데이터셋마다 다르게 가린다.
2026-10-30 실측(ADR-0348 의 API 표본과 같은 행):

| 데이터셋 | 지번 |
|---|---|
| 공장창고 | 일반건물 70% 가림(`4**`), 집합 30% 전체 |
| 토지 | 100% 가림 |
| 상업업무용 | 31% 가림 |
| 단독다가구 매매 | 가림 |
| 아파트·연립·오피스텔 | 전체(`본번`·`부번` 도 준다) |

## Decision

1. **표 하나: `silver.real_transaction`.**
   - 12 데이터셋이 같은 열로 들어간다. 그 데이터셋에 없는 열은 null 이다.
   - 정해진 열이 있다. 금액은 만원, 면적은 m² 와 원천의 면적 종류, 계약일·해제일·등기일, 주소·지번·도로명.
   - 그 옆에 `NO` 를 뺀 원천 열 전부를 받은 그대로 `provider_fields_json` 에 남긴다.
   - 표가 모르는 열은 적재 요약의 `unrepresented_fields` 로 센다.

2. **행의 이름(키) = (`dataset_slug`, `deal_ym`, `row_key`).**
   - `row_key` 는 `NO` 와 나중에 채워지는 열(`해제사유발생일`, `등기일자`; 계약 `csv.mutable_columns`)을 뺀 원천 열 전부의
     sha256 앞 32자에 `-` 와 같은 이름 안의 순번을 붙인 것이다.
   - 순번은 같은 이름의 행들을 바뀌는 열 순으로 세운 차례다. 그래서 똑같은 두 거래 중 하나만 해제돼도 이름이 흔들리지
     않는다.
   - 금액 정정 등으로 내용이 바뀌면 새 이름이 생기고, 옛 이름은 3번의 삭제 표지를 받는다.

3. **비교는 달마다, 내보내기 전체로.**
   - 적재는 Bronze 객체 하나를 커밋 하나로 싣는다. 객체가 R2 에 내려앉은 순서대로 싣는다.
   - 객체는 한 데이터셋의 한 달 전국 CSV 이고 그 달의 행 전부다. 그 달의 현재 행(계약의 `current_row_latest`)과
     견준다(`silver_release_compare.release_changes`).
   - 새 이름과 내용이 바뀐 이름의 행을 붙인다.
   - 그 달의 현재 행인데 이번 내보내기에 없는 이름에는 삭제 표지(`row_state = removed`)를 붙인다.
   - 현재 행은 그 달의 행만 읽는다(표 전체를 읽지 않는다, ADR-0314).

4. **계약해제는 지우지 않는다.**
   - `해제사유발생일` 이 붙은 행은 같은 이름의 새 판이다(`cancelled = true`, `cancel_date`).
   - 해제 거래를 시세에서 뺄지 보일지는 읽는 쪽(Gold)이 정한다.
   - 원천이 행을 아예 빼면 그것만 삭제 표지다.
   - 판의 순서는 `[source_snapshot_id, ingested_at_utc]` 다. `source_snapshot_id` 는 객체가 R2 에 내려앉은 시각
     (`plan-silver-load-objects` 의 `last_modified`)이다. 같은 달을 다시 실으면 나중 것이 이긴다(ADR-0328).

5. **PNU 와 법정동은 정본 해석기로(ADR-0288 §1).**
   - 법정동 10자리: `reference.legal_dong_code_snapshot` 의 가장 새 스냅숏에서 전체 이름이 `시군구` 와 같은 코드다.
     `존재` 가 먼저이고, 없으면 `폐지` 코드다. 하나로 안 모이면 `legal_dong_not_found` 다.
   - 후보 PNU: 법정동 + 산(지번이 `산` 으로 시작하면 2, 아니면 1) + 본번 4자리 + 부번 4자리.
   - 가린 지번(`*`)은 후보가 없다. `pnu_unresolved_reason = jibun_masked` 이고 `legal_dong_code` 는 남는다.
   - 후보는 `place_identity_resolver.resolve` 로 간다. 옛 코드는 현재 코드로 옮겨지고, 현재 필지일 때만 `pnu` 가
     된다. `legal_dong_code` 도 같은 crosswalk 를 거쳐 현재 코드다.
   - 가린 지번으로 필지를 추정하지 않는다(면적·지목으로 맞추기 등). 국토교통부가 일부러 가린 것을 되돌리는 일이라
     사장 결정이 먼저다(Consequences).

6. **연결률을 매 적재 보고하고, 떨어지면 시끄럽게 한다.**
   - 적재 요약에 데이터셋마다 행 수, `pnu` 가 선 행, 법정동만 선 행, 이유별 미연결 수를 적는다.
   - 가리지 않은 지번인데 `pnu` 가 안 선 비율이 계약의 `silver_load.max_unmasked_unresolved_share` 를 넘으면, 그 적재는
     행을 다 싣고 실패로 끝난다(경보, ADR-0288 §6).

## Consequences

**연결률(2026-10-30 실측, 적재 전).**

벌크 전국 2025-09 아파트 전월세 95,786행을 이 모듈의 함수로 읽었다. 법정동 100%, PNU 후보 99.76%(지번이
`1블록` 처럼 읽히지 않는 232행과 지번 없는 1행)였다.

API 2025-09, 무작위 30개 시군구:

| 데이터셋 | 행 | 법정동 | PNU 후보(가리지 않은 지번) | 후보 중 현재 필지(12개 시군구, Trino) |
|---|---:|---:|---:|---:|
| 공장창고 | 171 | 100% | 70% | 14/14 |
| 토지 | 2,597 | 100% | 0% (모두 가림) | – |
| 상업업무용 | 834 | 100% | 76% | 189/190 |
| 아파트 매매 | 8,200 | 100% | 100% | 3,745/3,757 |
| 연립다세대 매매 | 1,813 | 100% | 100% | 489/489 |
| 오피스텔 매매 | 1,096 | 100% | 100% | 475/475 |
| 단독다가구 매매 | 379 | 100% | 0% (모두 가림) | – |

공장창고·토지의 "내 필지 거래" 는 상당 부분 법정동까지만 이어진다. 그래서 화면의 주된 쓰임은 같은 법정동의
비교 거래다(ADR-0350).

**사장 결정 대기:** 가린 지번의 필지 추정(같은 법정동·본번 앞자리·대지면적·용도지역이 하나로 맞는 필지). 민간
서비스들이 하는 일이지만 원천의 비식별 의도와 부딪힌다. 이 ADR 은 하지 않는다.
