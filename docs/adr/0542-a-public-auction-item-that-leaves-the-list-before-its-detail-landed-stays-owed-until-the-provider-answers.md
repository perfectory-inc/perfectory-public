# ADR 0542: 상세가 닿기 전에 목록을 떠난 공매 물건은 제공자가 답할 때까지 닫힌 채로 빚진다

- Status: Accepted
- Date: 2026-11-11
- Builds on: [ADR-0330](./0330-a-public-auction-round-is-detailed-until-its-media-landed-open-rounds-first.md)(열린 회차부터, 미디어가 닿을 때까지),
  [ADR-0339](./0339-a-public-auction-item-is-detailed-once-for-all-its-rounds.md)(물건 단위)

## Context

Silver 의 공매 물건 28,500 개 중 물건상세가 없는 것이 2,577 개(9.0 %)였다(2026-11-11 14:50Z 실측). 원인을 갈랐다:

| 무리 | 물건 | 실측 |
| --- | ---: | --- |
| 11-01 전에 목록을 떠남 | 2,569 | 마지막으로 목록에 보인 때가 10-19~10-29 — 물건상세 수집이 10-25 에 시작해 백로그가 닿기 전에 떠났다 |
| 11-01 뒤에 본 물건 | 8 | 지금 길은 따라잡는다(열린 회차 커버리지 45,402/45,894 = 98.9 %) |

수집기는 매 run 그 상태(`items`·`photos_landed`·미디어 메모)를 목록에 남은 물건으로 잘라 낸다. 그래서 상세가 닿기 전에
목록을 떠난 물건은 다시 묻지 않는다 — 이것이 우리 쪽 구멍이다. 그 물건을 물건상세 API 에 실제로 물어봤다(표본 62,
0.2초 간격): 수의계약가능은 15 중 14 가 사진째 답했고, 상태가 빈칸인 물건은 15 중 3, 입찰마감 15 중 1, 입찰준비중 10 중
0 — 나머지는 `03 NODATA_ERROR`(제공자가 거뒀다). 되살릴 몫(계산) ≈ 94 + 480 + 3 ≈ **580** 물건, 나머지 ~2,000 은
제공자에게 없다.

## Decision

1. **닫힌 채 빚진다** — 완전한 목록 한 바퀴(`close_vanished`)가 떠난 회차를 찾을 때, 그 물건이 다른 회차로도
   목록에 없고 상세가 닿지 않았으면(`items` 표 없음) 수집기 상태 `closed_owed`(물건 키 → 물은 횟수)에 넣는다. 목록으로
   잘라 내지 않는다 — 떠난 것이 바로 그 이유다. 다시 목록에 오르면 열린 길이 맡는다(빠진다).
2. **열린 물건 뒤에, 같은 상한 안에서** — 열린 물건의 물건상세를 다 물은 뒤 `item_detail.per_run_limit` 의 남은 몫과 API
   하루 예산 안에서 키 순으로 묻는다. 답한 줄은 열린 물건과 같이 같은 run 의 미디어 단계(사진·원본·사다리)를 지난다.
   `03 no data` 는 제공자가 거둔 것이라 바로 놓는다(`closed_gone`). 미디어가 다 닿으면 놓고(`closed_landed`), 아니면 한 번
   더 — 최대 3 번(`CLOSED_MAX_ASKS`).
3. **과거분 시드, 한 번** — 이 결정 전에 이미 잊은 물건은 수집기 상태에 없다. `scripts/ops/onbid_closed_owed_seed.py` 가
   Silver 에서 "목록 행은 있고 물건상세 행은 없는" 물건을 마지막 회차 키로 한 번 읽어(Trino, media_reconcile 과 같은
   길) `FOUNDATION_PLATFORM_DATA_GO_KR_ONBID_CLOSED_OWED_SEED` 로 넘긴다. `onbid-collect.sh` 는 한 run 이 받아 간 뒤
   `closed-owed-seed.done` 을 남기고 다시 읽지 않는다(부분: 한 번의 읽기). 읽기가 실패하면 그 run 은 시드 없이 돌고 다음
   run 이 다시 읽는다 — 수집을 깨지 않는다. 시드는 일감 목록이지 계보 입력이 아니다(데이터를 만들지 않으므로 파이프라인
   그래프 간선 없음; 작업 정의 설명에 적는다).
4. run 요약에 `closed_seeded`·`closed_received`·`closed_gone`·`closed_landed`·`closed_owed` 를 남긴다.

## Consequences

- 비용(계산): 시드 한 번 ≈ 2,577 물건상세 호출(하루 상한 안, per_run_limit 만큼씩 몇 run) + 되살아난 ~580 물건의
  사진(물건당 ~4 장 × ~190 KB ≈ 0.4 GB, R2 ≈ $0.006/월). Trino 읽기 한 번(수 초).
- 기대(계산): 상세 있는 물건 91.0 % → ~93.0 %. 상한이 100 % 가 아닌 것은 제공자가 거둔 ~2,000 물건 때문이다.
- 시험: `close_vanished` 가 미상세 물건만 넣고 상세된·아직 다른 회차로 열린 물건은 넣지 않음, `settle_closed` 의 놓기와
  횟수, `seed_closed` 가 열린·이미 빚진 물건을 건너뜀과 상태 왕복; 시드 스크립트의 키·잘못된 행·한 번만 읽기.
