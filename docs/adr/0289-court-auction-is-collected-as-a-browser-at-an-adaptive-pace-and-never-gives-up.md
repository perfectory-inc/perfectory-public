# ADR 0289: 법원경매는 브라우저로 접속해 스스로 속도를 조절하고, 막혀도 끝까지 모은다

## Context

사장 결정(2026-10-21): ADR-0281 의 수집 방식은 틀렸다. 저장소 밖에서 만든 Python 시제품을 기준으로 삼되, 그대로 쓰지 않고 Rust 로 더 낫게 만든다.

| 항목 | 지금 main (ADR-0281) | 시제품 (2026-10-21) |
|---|---|---|
| 속도 | 초당 0.3 요청 | 초당 수십 요청, 목록·상세 전체를 약 73분에 받음 |
| 막힘 | 10-20 낮 실행이 174 요청 만에 멈춤, 그 뒤 수집 없음 | 실행 중 여러 번 막혔으나 스스로 복구, 잃은 데이터 0 |
| 범위 | 목록 2종, 날짜를 안 보내 서버가 "오늘~14일" 만 줌 | 목록 전체 + 사건상세 4종 + 물건상세 |

시제품의 약점: 진행이 멈춰도 아무도 모른다. 동시 요청 수가 고정이다. 같은 key 는 다시 받지 않아 바뀐 내용이 반영되지 않는다(ADR-0290). 오류가 반복되면 그 건을 조용히 버린다. 값이 코드 안 상수다.

실측 수치, 막힘의 모양과 복구 방법, 헤더, 라이브러리 비교 근거는 비공개 운영 저장소(`perfectory-ops`)의 `collection/court-auction.md` 에 둔다. 이 ADR 은 결정만 적는다.

## Decision

1. **브라우저로 접속한다.** 접속 계층은 Rust 크레이트 `wreq`(+`wreq-util` 의 브라우저 프로필)로 브라우저와 같은 모양의 요청을 보낸다. 우리 이름을 단 User-Agent 는 보내지 않는다.
   - **채택 조건:** 같은 요청 묶음으로 시제품과 `wreq` 를 비교하는 스파이크를 먼저 한다. `wreq` 가 시제품보다 나쁘면 이 항목을 다시 결정한다. 접속 계층은 trait 하나 뒤에 두어, 크레이트를 바꿔도 수집기 나머지는 바뀌지 않는다.
2. **세션은 풀로 둔다.** 세션 여러 개를 두고 요청마다 하나를 빌린다. 세션마다 만든 시각·보낸 요청 수·막힌 시각을 지표로 남긴다.
3. **막혀도 멈추지 않는다. 다시 시도하는 데 상한은 없다.** 막힘 판정 신호, 대기 단계, 복구 방법은 계약 값이다. 실행은 끝까지 간다.
   - **진행 없음 알림:** 계약의 시간 동안 성공한 요청이 하나도 없으면 알린다. 알리기만 하고 멈추지는 않는다.
   - 막힘이 아닌 오류(네트워크 오류, 5xx, JSON 깨짐)는 계약의 횟수만큼 지수 대기로 다시 시도한다. 그래도 안 되면 **실패 장부**에 key 를 남긴다(ADR-0290 §5). 조용히 버리지 않는다.
4. **속도는 스스로 조절한다.** 엔드포인트 묶음마다(목록 검색, 사건상세, 물건상세) 동시 요청 수를 따로 조절한다(AIMD). 막힘 없이 일정 시간이 지나면 하나 올린다. 막히거나 응답 시간이 기준보다 길어지면 절반으로 내린다. 시작값·올리는 간격·내리는 비율·최대치·응답 시간 기준은 계약 값이다.
5. **시간대 제한을 두지 않는다.** 수집은 하루 언제든 돈다. ADR-0282 의 운영자 창(window) 스위치는 남긴다 — 운영자가 좁힐 때만 좁혀진다. 계약의 `quiet_hours_kst` 는 없앤다.
6. **이번 결정에 넣지 않는 것:** 프록시·IP 돌리기·CAPTCHA 풀기. 실측에서 필요 없었다. 필요해지면 새 ADR 로 정한다.
7. **SSOT — 값은 계약 한 곳에만 둔다.** `infra/lakehouse/contracts/courtauction-go-kr.contract.json` 이 다음 값을 가진다: 엔드포인트(경로·요청 모양), 목록 검색 조건과 날짜 범위, 쪽 크기, 브라우저 프로필, 세션 풀 크기, 막힘 신호, 대기 단계, 진행 없음 알림 시간, 속도 조절 값.
   - 수집기 코드에는 이 값들의 리터럴이 없다. **시험:** 수집기 소스에서 계약에 있는 엔드포인트 경로를 찾으면 실패한다. 위반을 심어 거부되는지도 확인한다.
   - 작업 등록부(`orchestration/jobs.v1.json`)·런북·systemd 설명·doc 주석은 값을 다시 적지 않고 계약을 가리킨다. 지금 `court_auction_collect` 설명이 간격과 시간대를 다시 적고 있는데, 이것을 지운다.
   - 시험은 계약 값을 베끼지 않고 계약을 읽어서 검사한다.
   - 계약의 `forbidden_in_collector` 목록과 그것을 읽는 시험은 ADR-0281 §4 를 지키던 것이라 함께 지운다.
8. **Bronze 쓰기는 FP-ADR-0016 관문 하나로 한다.** 모든 원본 응답은 `BronzeCommitter` 로 한 번만 쓰고(CreateOnly), SHA-256 을 찍고, `bronze_object` 행을 남긴다. 같은 이름에 다른 내용이 오면 `ChecksumConflict` 로 격리한다.

## Consequences

- 목록 한 바퀴가 약 78분에서 몇 분으로 줄고, 날짜 범위가 들어가 물건 검색 행 수가 약 1.7배가 된다. 상세 수집(ADR-0290)이 가능해진다.
- `wreq` 는 BoringSSL(C/C++)을 빌드한다. foundation 워크스페이스에 `openssl-sys` 가 없어 심볼 충돌은 없다. 빌드에 cmake·C 컴파일러가 필요하므로 CI 와 ai-server 빌드 이미지를 확인해야 한다. Rust-only 의 예외는 TLS 라이브러리 하나로 한정한다.
- 브라우저 프로필은 브라우저가 바뀌면 낡는다. 버전은 계약 한 곳에만 있으니 올리는 PR 은 한 줄이다.
- 막혀도 계속 다시 시도하므로 서버 IP 가 오래 막힌 상태로 남을 수 있다. 진행 없음 알림을 받은 사람이 운영자 스위치(ADR-0282)로 멈출 수 있다.
- 약관 제15조 1호(서비스 방해·설비 손상 금지)는 사장이 받아들인 법적 위험의 경계로 남는다. §4 에서 막힘이나 응답 지연이 보이면 속도를 내리는 것이 이 경계를 지키는 장치다.
- 거절 상태 파일(`refused.json`)과 `job clear-refusal`(#808)은 "거절 시 정지" 를 위한 것이라 없앤다. 초안 #801(작업 켜기)은 이 ADR 에 맞춰 다시 쓴다.

## Rejected

- **ADR-0281 유지:** 낮에 174 요청 만에 멈췄고, 3초 간격이면 상세 수집에 수백 시간이 걸린다. 사장이 기각했다.
- **Python 시제품을 그대로 운영:** 우리 수집기는 Rust 이고 Bronze 관문·계약·작업 등록부를 쓴다. 시제품은 값이 코드 상수이고, 진행 감시·실패 장부·증분이 없다.
- **다른 접속 라이브러리:** 비교 근거는 비공개 운영 문서에 있다. §1 의 스파이크가 `wreq` 를 기각하면 다시 본다.
