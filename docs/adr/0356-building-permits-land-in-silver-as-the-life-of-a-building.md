# ADR 0356: 건축인허가 기본개요는 건물의 수명 사건열로 Silver 에 쌓는다

- Status: Accepted
- Date: 2026-10-30
- Builds on: ADR-0355(원천 판정·연결 순서 1순위), ADR-0169(Silver 레인은 장부에서 판을 고른다),
  ADR-0092·ADR-0094(HUB 스트리밍 엔진), ADR-0318(키 묶음마다 바뀐 키만), ADR-0145(HUB 코드 → PNU),
  ADR-0288(place-identity), ADR-0314(부분 처리가 기본)

## Context

ADR-0355 는 건축인허가 기본개요를 "지금 연결" 1순위로 정했다. 산업용 부동산 매수인·임차인이 필지에서 먼저 묻는 것은
"이 땅에 지금 무엇이 지어지고 있나, 허가만 나고 착공하지 않은 건물이 있나, 이 공장은 언제 사용승인을 받았나" 다.
표제부(`silver.building_register_titles`)는 다 지어진 건물만 싣는다. 허가 → 착공 → 사용승인의 사건은
인허가 대장에만 있다.

**측정 (2026-10-30, 최신 판 ZIP 전체를 R2 읽기 전용 범위 읽기로 끝까지 읽음).**

- 판: `bronze/source=hubgokr__building_permit_basis_outline/OPN202610201211105530.zip`. 430 MB 이고,
  멤버 `mart_kcy_01.txt` 는 1,719,117,872 바이트다. 이 원천의 다섯 판 합계는 2.19 GB 다.
- **6,527,521 행이고, 모든 행이 41칸이다.** 관리허가대장PK(칸 0) 6,527,521 개가 모두 고유하다. 그래서 키는 관리번호 하나다.
- PNU 입력(시군구 5·법정동 5·번 1–4·지 1–4 자리 숫자)이 맞는 행은 6,520,913 개(99.90%)다.
- 날짜가 채워진 행: 허가일 6,486,201, 착공예정일 3,335,131, 실제착공일 3,361,631, 사용승인일 3,310,298,
  착공연기일 199,135.
- 주용도 `공장` 289,484 건, `창고시설` 243,717 건. 건축구분은 신축 2,894,618, 증축 954,682, 용도변경 442,992 건이다.
- 키 길이는 13자리 3.9M, 8자리 1.1M, 22자리 0.8M 이다. 앞 두 글자는 `10`·`11`·`12` 셋뿐이다.
- 칸 2(건물명)에는 개인 이름이 든 행이 있다(예: "… 단독주택 (성명)").

### 실사례

- **Shovels·BuildZoom(미국)**: 지자체 허가 원장을 모아 허가·착공·준공을 필지 단위 사건열로 판다.
  CoStar·Reonomy 의 "under construction / proposed" 단계도 같은 원천에서 온다.
- **Debezium·Delta CDF**: 원본 행을 그대로 두고 키마다 바뀐 행만 쌓는다(ADR-0318 과 같음).

## Decision

1. **표 `silver.building_permit_basis_outline`.** 허가 한 건이 한 키(`mgmt_key` = 관리허가대장PK)다. 이름 붙인 칸은
   PNU 입력 6개와 수명 칸 12개다: 건축구분 코드·이름, 주용도 코드·이름, 대지·건축·연면적, 허가일, 착공예정일,
   착공연기일, 실제착공일, 사용승인일. 값은 제공자 글자 그대로다. 날짜는 `YYYYMMDD` 이거나 빈칸이다.
   41칸 전부는 `raw_columns` 에 남긴다. 이름을 붙이지 않은 칸의 뜻은 추정하지 않는다.
2. **새 엔진은 만들지 않는다.** HUB 스트리밍 엔진(`hub_register_silver_export`)에 계약
   `hub-building-permit-basis-outline-source-objects.json` 과 18줄 어댑터를 붙인다. 새 명령은
   `export-building-permit-basis-outline-silver-handoff` 다. PNU 는 같은 `standard_pnu_from_hub_register_codes`
   (ADR-0145)로 만든다. 이것이 place-identity(ADR-0288)의 HUB 쪽 입구다.
3. **부분 처리.** Silver 갱신 레인 `building-permit-basis-outline` 을 만든다(ADR-0169). 판은 장부가 고른다.
   부분을 load branch 에 쌓고, compare 가 관리번호마다 바뀐 허가의 행과 사라진 허가의 삭제 표시만 main 에 붙인다
   (ADR-0318). 묶음은 키 앞 두 자리다. 실측으로 세 묶음이며, 묶음마다 1.5M–2.6M 행이다. 작업은
   `silver_refresh_building_permit_basis_outline` 이고 `scope` 는 `changed-keys` 다. 일일 수집이 새 판을 받으면 시작하고(ADR-0171),
   매일 07:00 UTC 에 대체 실행된다. 이 작업을 켜는 것은 사장이 2026-10-30 에 승인한 수집 범위 안이다.
4. **개인 이름이 든 칸은 이름을 붙이지 않는다.** 칸 2 는 원본 보존(`raw_columns`) 안에만 있다. 다음 PR 의 Gold 는
   이 칸을 읽지 않는다. 공개 저장소의 시험 데이터는 합성 값(99999)만 쓴다.
5. **소비자는 다음 PR 이다.** 그래프에서 이 표는 `contract_only`, 엣지는 `partial` 이다(등록공장과 같은 섬 규칙).
   건물 by-PNU 패널에 "공사 중·허가만 남·사용승인일" 을 싣는 Gold 슬라이스가 이 표를 읽으면, 그 PR 이
   표와 엣지를 `implemented` 로 바꾼다. 그때 문서 스키마 레지스트리(ADR-0336)에 확장(expand) 판으로 올린다.

## Consequences

- **비용(계산).** 첫 실행은 판 하나 전부(6.5M 행)를 쓴다. Parquet 로 수백 MB 다. 다음 판부터는 바뀐 허가만 쓴다.
  R2 $0.015/GB·월 기준으로 월 100원 안쪽이다. Spark 는 기존 `spark` 풀 3칸을 쓴다. 판 원문은 전유부(판당 0.98 GB ZIP)보다 작고,
  시간 상한 150분은 전유부 레인과 같다.
- 첫 적재는 무거운 일회성 백필이 아니다. 전유부 레인과 같은 크기 등급이라 정규 시간에 돈다. 다만 운영 by-PNU bake 가
  도는 동안에는 이 PR 을 병합하지 않는다(병합하면 자동 배포가 bake 를 끊는다).
- `enabled_since` 는 병합 시각으로 바꾼다(ADR-0239).
