# 전역 용어집

이 문서는 모노레포 문서에서 같은 개념을 같은 말로 쓰기 위한 용어 정본입니다. 코드·API·
패키지·환경변수 이름은 이 표의 한글 표기로 바꾸지 않습니다. 표에 괄호로 적은 식별자는
그 용어가 가리키는 정본 위치이며, 의미는 그 코드가 소유합니다.

## 문서·거버넌스 용어

| 정본 용어 | 의미 | 쓰지 않을 표현 |
|---|---|---|
| 정본 | 해당 사실을 한 곳에서만 정의하는 문서 | 원본, 기준 문서 혼용 |
| 단일 진실 원천(SSOT) | 다른 문서가 복사하지 않고 링크해야 하는 유일한 사실의 출처 | SSOT와 원장 혼용 |
| 설계 결정 기록(ADR) | 왜 특정 설계·정책을 선택했는지 남기는 변경 불변 기록 | 회의록, 작업 목록 |
| 현재 구조 문서 | 지금 코드와 배포 구성이 무엇인지 설명하는 문서 | 계획서 |
| 안내서 | 개발자가 어떤 작업을 어떻게 수행하는지 설명하는 문서 | 설계 결정 |
| 운영 런북 | 배포·장애·복구 시 실행하는 절차 | 일반 안내 |
| 사실 기록 | 조사·실행·장애·릴리스의 날짜가 있는 증거 | 현재 정책 |
| 보관 문서 | 현재 정책이 아니지만 역사적 이유로 보존하는 문서 | 삭제된 문서 |
| 한글 정본 | 사람이 읽는 설명의 현재 기준 언어인 `ko-KR` 문서 | 번역본 |
| 번역본 | 한글 정본의 특정 버전을 다른 언어로 옮긴 문서 | 별도 정본 |
| 조직 브랜치 | 조직 저장소에 직접 생성한 작업 브랜치 | 개인 포크 브랜치 |

## 데이터 계층 용어

| 정본 용어 | 의미 | 쓰지 않을 표현 |
|---|---|---|
| 브론즈 | 수집 시점의 원자료와 수집 증거를 보존하는 계층 | 원장 |
| 실버 | 검증·정규화된 분석용 중간 계층 | 공개 데이터 |
| 골드 | 소비자에게 제공하기 위해 선별한 결과 계층 | 원자료 |
| 원장 | 변경·감사·멱등성을 보존하는 기준 상태 | 임시 캐시 |

## 공간 데이터 발행 용어

[단일 출처 공간 데이터 공개 아키텍처](./architecture/single-source-spatial-publication.md)와
[ADR 0013](./adr/0013-release-uniqueness-admits-both-source-kinds.md)~[0017](./adr/0017-a-data-revision-belongs-to-the-unit-it-revises.md)이
쓰는 용어입니다. 세 원장(발행 리비전·투영 적재·릴리스)의 역할 구분은 아키텍처 문서가 정본이며
여기서는 각 용어가 무엇을 가리키는지만 고정합니다.

| 정본 용어 | 의미 | 쓰지 않을 표현 |
|---|---|---|
| 발행 단위 | `parcels`·`complex`처럼 함께 검증하고 함께 전환하는 하나의 논리 지도 계층이자 원자성 경계(`catalog.vector_tile_publication_unit`) | 레이어, 타일셋 |
| 발행 리비전 | 한 발행 단위의 데이터가 어느 정본 스냅샷인지를 기록한 원장 행(`catalog.publication_revision`). 단위에 스코프되므로 다른 단위의 리비전을 지명할 수 없다 | 데이터 버전, 스냅샷 |
| 사실 리비전 | 수집한 사실 자체의 리비전(예: `catalog.administrative_boundary_revision`). 발행 리비전이 계보로 이것을 가리키며 그 반대가 아니다 | 발행 리비전과 혼용 |
| 투영 적재 | 한 발행 리비전을 PostGIS 서빙 표에 실체화한 1회 실행(`serving_postgis.spatial_projection_load`). 언제·몇 행이 들어갔는지를 답한다 | 동기화, 미러링 |
| 릴리스 | 어느 적재를 서빙할지 고정한 불변 기술자(`catalog.vector_tile_release`). 만든 뒤에는 바뀌지 않는다 | 배포, 버전 |
| 제공 세대 | 한 단위의 활성 릴리스가 바뀔 때마다 증가하는 정수(`serving_generation`). 데이터가 아니라 무엇을 서빙하는지가 바뀐 횟수다 | 데이터 리비전과 혼용 |
| 런타임 매니페스트 | 모든 발행 단위의 현재 선택을 한 번에 담은 불변 스냅샷. 활성 매니페스트를 가리키는 포인터 행은 정확히 하나다 | 설정 파일, 카탈로그 |
| 승격 | 런타임 매니페스트 포인터를 다음 매니페스트로 전진시키는 일. 예상값 비교·교환(CAS)으로만 일어나며 무조건 덮어쓰지 않는다 | 배포, 반영 |
| 계보 | 파생된 사실이 자신이 파생돼 나온 사실을 가리키는 참조. 방향이 있으며 역방향 참조는 두 원장의 소유 관계를 뒤집는다 | 참조, 링크 |
| 발행자 권한 | 추가 전용 원장에 쓸 수 있는 트랜잭션 범위 능력. 문장 단위로 얻고 즉시 반납한다 — 트랜잭션 전체에 걸면 무관한 추가 전용 검사까지 함께 풀린다 | 관리자 권한, 데이터베이스 롤 |

## 표기 규칙

- 처음 등장할 때만 한글 용어 뒤에 표준 약어를 괄호로 붙입니다. 예: 단일 진실 원천(SSOT).
- 문서 제목과 본문은 한글로 쓰되 `PostgreSQL`, `Kafka`, `R2`, `Iceberg`, `Cargo` 같은
  제품명과 표준 이름은 공식 표기를 유지합니다.
- 상태값은 메타데이터의 영문 열거값(`current`, `proposed`, `deprecated`, `archived`)을
  그대로 사용합니다. 사람이 읽는 설명에서 상태 의미를 한글로 풀어 씁니다.
- 번역이 추가되면 용어집의 정본 한글 용어와 `source_revision`을 기준으로 번역합니다.
