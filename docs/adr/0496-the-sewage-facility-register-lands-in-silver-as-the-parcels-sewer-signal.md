# ADR 0496: 건축물대장 오수정화시설을 Silver 에 올려 필지의 하수도 신호로 쓴다

- Status: Accepted
- Date: 2026-11-11
- Builds on: ADR-0355(건축HUB 원천 판정), ADR-0402(HUB 레인 하나에 PR 하나, 같은 엔진), ADR-0397(행 글자를 키로),
  ADR-0169(장부가 판을 고른다), ADR-0318(바뀐 키만 쌓는다), ADR-0329 §3(`views.changed_codes`), ADR-0288(place-identity)
- Supersedes(부분): ADR-0355 원천별 판정의 `hubgokr__building_register_sewage_facility` "Bronze 보관만" — 이 원천만 "지금 연결" 로 올린다

## Context

공장·창고 매수인과 임차인은 필지마다 "하수도에 이을 수 있나" 를 묻는다. 하수관로 도형은 국가공간정보 보안관리규정의
공개제한 정보라 받을 수 없다(W63 조사, `platforms/foundation-platform/docs/catalog/parcel-utility-connectivity-sources.md` 1·11번).
ADR-0355 는 건축물대장 오수정화시설을 "Bronze 보관만" 으로 두었다. 화면이 그 값을 쓰지 않았기 때문이다.

**측정(2026-11-11, 운영 장부의 2026-10 판 ZIP 전체를 R2 읽기 전용 키로 읽음).**

| 항목 | 값 |
|---|---:|
| ZIP / 멤버 `mart_djy_07.txt` | 342,373,235 B / 1,602,995,282 B |
| 행(모든 행 29칸) | 6,616,909 |
| 관리건축물대장PK 서로 다른 값 | 6,567,455 (한 건물에 시설 여럿 — 행을 가르지 못한다) |
| 서로 다른 지번(PNU 입력 유효 99.9997%) | 5,439,288 |
| 오수정화방식이 채워진 지번 | 2,826,917 |
| 그중 300 하수종말처리장연결·400 마을하수처리장연결 | 756,006 |
| 그중 그 밖의 방식(1xx 오수처리시설·2xx 단독정화조 등) | 2,085,118 (둘 다 14,337) |
| 방식이 채워진 지번 표본 2,000 의 서빙 필지판 연결률 | 1,778 (88.9%) |
| 한 달 변화(09 → 10 판, 서로 다른 행) | 새 행 22,165 · 사라진 행 11,289 |

**새로 안 것.** 이 파일은 "개인하수처리시설을 신고했다" 만이 아니다. 오수정화방식 코드 300(하수종말처리장연결)과
400(마을하수처리장연결)은 그 건물의 오수가 **공공하수처리시설에 이어져 있다** 는 대장 기재다. 그래서 한 파일이
두 신호를 준다: 공공하수도 연결의 증거(약 76만 지번)와 개인하수처리시설의 증거(약 209만 지번).
하수도법 제34조는 하수처리구역 밖에서 오수를 내는 건물에 개인하수처리시설을 두게 하지만, 합류식 지역은 구역 안에서도
정화조를 둔다. 그래서 개인하수처리 신호는 "확정" 이 아니라 "강한 추정" 이다.

### 실사례

- 미국 매물 정보망(MLS)과 그것을 싣는 Zillow·Redfin 의 매물 상세는 `Sewer: Public Sewer / Septic Tank` 을 기록의 낱말
  그대로 보인다. 관로 도형이 아니라 신고·기재 기록이 근거이고, 확인은 매수인 몫이라는 단서를 붙인다. 우리 근거와 화면도 같은 모양이다.

## Decision

1. **이 원천을 지금 연결한다.** ADR-0402 와 같은 엔진(`hub_register_silver_export`)·Silver 갱신(ADR-0169)·키 비교(ADR-0318)다.
   새 엔진은 없다. 레인은 `building-register-sewage-facility`, 표는 `silver.building_register_sewage_facility` 다.
2. **키는 행 글자의 SHA-256 이다**(`row_key: "sha256_of_row"`, ADR-0397). 관리건축물대장PK 는 `building_mgmt_key` 로
   남겨 표제부(`silver.building_register_titles`)와 잇는다.
3. **칸 뜻은 공공데이터포털 건축HUB 건축물대장정보 서비스 `getBrWclfInfo` 의 응답 항목 29개와 실측의 교차 확인이다.**
   이름 붙인 칸은 PNU 입력 다섯, 대장종류, 오수정화방식 코드·이름, 기타방식, 단위·용량 둘, 생성일자다. 나머지(대지위치·
   건물명·새주소 칸)는 `raw_columns` 의 원래 index 로만 둔다. 건물명은 화면에 내보내지 않는다(ADR-0356 §4).
4. **원문이 1.6 GB 라 나눠 비교한다**(ADR-0402 §6). 키가 16진수 SHA-256 이라 앞 한 자리로 16 묶음이다(`bucket_prefix_length: 1`).
5. **PNU 와 코드 변경.** PNU 는 엔진이 HUB 코드로 짓는다(ADR-0145, FP-ADR-0023). 합병·분할·법정동 코드 변경으로 바뀐 필지는
   소비자(by-PNU 종류)가 place-identity 해석기와 `views.changed_codes`(ADR-0329 §3)로 지금 PNU 에 옮긴다. 적재 때 한 번 풀고
   멈추지 않는다.
6. **화면은 다음 PR 이다.** 소비자는 새 자기 생산자 종류 `parcel-utility`(ADR-0497)다. 총괄표제부 종류(ADR-0450)는 문서가
   총괄표제부가 있는 약 62만 필지뿐이라 일반건축물 시설(약 583만 행)을 실을 수 없다. 필지 화면의 "인입 가능성" 구획이
   오수정화방식을 원천 낱말 그대로 보인다. 그때까지 Silver 는 `contract_only` 섬이다.

## Consequences

- **비용(계산).** Bronze 는 이미 받는다(5판, 판당 약 0.34 GB). Silver 첫 적재는 662만 행(원문 1.6 GB, Parquet 수백 MB)이고
  이후는 바뀐 행만(실측 한 달 약 3.3만 행) 더한다. R2 저장 $0.015/GB·월, 1,450원/$ 로 월 10원 안팎이다. 계산은 ai-server 에서 돈다.
- **실행 시간(계산).** 같은 틀의 기본개요(6.53M 행, 438 MB 판) 실측 357초와 일이 같다. 첫 run 은 16 묶음 커밋을 더해 1,200초로
  잡았고 단위 제한 150분 안이다.
- **위험.** 오수정화방식 칸이 절반(340만 행)은 비어 있다. 비어 있는 필지는 "자료 없음" 이지 "하수도 없음" 이 아니다.
  화면은 신호가 있는 필지에만 값을 보인다.
- 실패가 막는 사고: 칸 배치가 판마다 달라지면 하수처리장연결 필지를 정화조로 잘못 보인다. `test_register_sewage_facility_contract.py`
  가 칸 index 와 키 규칙을, `sewage_facility_tests.rs` 가 엔진의 행 키와 칸 이름을 지킨다.
