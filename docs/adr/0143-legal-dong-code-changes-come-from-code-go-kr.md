# ADR 0143: 법정동 코드 변경은 code.go.kr 에서 받는다 — 공식 짝은 변경안내 첨부, 날짜는 전체 표

- Status: Accepted
- Date: 2026-10-04
- Supersedes: [ADR-0104](./0104-the-authority-api-is-current-only-so-the-crosswalk-comes-from-snapshot-diffs.md) (API 스냅숏 차이를 정본으로 한 결정)
- Amends: [ADR-0113](./0113-parcel-lineage-absorbs-reorganizations-and-gates-every-map-bake.md) §5 (대응 규칙의 입력)

## Context

ADR-0104(2026-09-13)는 data.go.kr `getStanReginCdList` 를 매일 받아 연속 스냅숏을 비교하는 것을 정본으로 했다. 근거는
두 가지였다.

- API 에는 현행 코드와 생성일만 있다.
- code.go.kr 은 화면의 다운로드 버튼뿐이라 자동 수집이 어렵다고 보았다.

ADR-0113(2026-09-29)은 code.go.kr "법정동코드 전체자료"를 원천으로 더했다.

- 적재 코드 `legal_dong_code_snapshot_to_reference.py`(#252)가 있다.
- 그러나 그 파일을 받아오는 수집기는 저장소에 없다. 그 파일은 (코드, 이름, 존재/폐지) 세 칸뿐이다.

2026-10-03 광주·전남(12xxx) 코드 누락 사고(ADR-0142)에서 대응표 27쌍은 손으로 만든 것이었다. 소유자 결정은 "code.go.kr
을 쓴다"이다. 행정안전부 일반 게시판은 자동화가 어렵다.

2026-10-04 code.go.kr 을 전수 조사했다(읽기 전용).

| 자료 | 요청 | 내용 | 자동화 |
|---|---|---|---|
| 법정동 전체 표 | `POST /stdcode/regCodeL.do`, 전국 한 번 | 53,403행. 코드·이름·현존/폐지·상위코드·**생성일·폐지일**·주민/지적 코드 | 요청 한 번, 약 5초 |
| 코드변경안내 목록 | `POST /bbsmng/dataBbsL.do` (`btype=dataBbs`) | 개편 공지 1,256건, 제목·게시일 | 요청 한 번 |
| 변경안내 상세·첨부 | `POST /bbsmng/dataBbsR.do`, `/bbsmng/filedownload.do` | 시행일·사유·법적 근거 문서, **옛 코드 → 새 코드 짝 엑셀**(최근 공지) | 첨부 하나씩, 15초 간격 |
| 전체자료 파일 | `/etc/codeFullDown.do?codeseId=00002` | 코드·이름·존재/폐지 | 날짜 없음 |
| 제개정현황·변경관리방안 버튼 | — | 비어 있음 | — |

- `robots.txt` 는 전부 허용한다. 자동 접근을 금지하는 약관은 찾지 못했다.
- 2026-07-01 공지(전남광주 통합) 첨부 엑셀에는 3,336행이 있다.
  - 예: 4611010100 → 1211010100, 2911010100 → 1221010100.
  - "같은 날 폐지·생성 + 시도를 뺀 이름 일치" 규칙으로 만든 짝 3,205개는 엑셀의 쓸 수 있는 짝 3,176개와 모두 같았다.
- 같은 달 인천 구 분리 공지에서는 이름 규칙이 83개 중 78개만 하나로 정했다. 분리·재번호는 이름만으로 확정할 수 없다.

## Decision

1. **법정동 코드 변경의 정본은 code.go.kr 이다.** data.go.kr API 스냅숏 차이(ADR-0104)는 정본에서 내려와 보조 검증이 된다.
2. **매일 전체 표를 받는다.**
   - 수집은 등록된 작업(ADR-0122)으로 한다. 응답 원본을 그대로 Bronze 에 불변 객체로 남긴다.
   - (코드, 이름, 현존/폐지, 상위코드, 생성일, 폐지일)을 `reference.legal_dong_code_snapshot` 에 스냅숏으로 쌓는다
     (append-only, ADR-0113).
   - 표 크기가 직전보다 크게 줄면 적재하지 않는다. 기준은 계약 파일이 정한다.
3. **짝의 1순위는 코드변경안내 첨부다.**
   - 목록에서 제목에 "법정동"이 들어간 새 공지를 찾아 첨부를 받는다(Bronze 보관).
   - 엑셀의 옛 코드 → 새 코드 짝을 `source = official_notice:<공지번호>` 로 기록하고, 시행일·사유를 함께 둔다.
   - 엑셀은 칸 위치가 아니라 머리글 이름으로 읽는다. 공지마다 양식이 다르기 때문이다.
   - 머리글을 해석하지 못하거나 엑셀이 없는 공지(한글 문서만 있는 경우)는 사람 확인 목록으로 보낸다.
4. **2순위는 날짜·이름 규칙이다.**
   - 같은 날 폐지된 코드와 생성된 코드 사이에서 상위 단위를 맞추고, 시도를 뺀 이름이 하나로 일치하면 짝 후보다
     (ADR-0113 §5 규칙에 날짜를 더한 것).
   - 폐지일 = 생성일 − 1일도 같은 날로 본다.
   - 후보가 공식 짝과 다르면 공식 짝을 쓰고 차이를 기록한다.
   - 공식 짝이 없을 때 후보가 하나뿐이면 "근거: 날짜·이름"으로 쓴다.
   - 후보가 없거나 둘 이상이면 사람 확인 목록으로 보낸다. 분리·재번호가 여기에 걸린다.
5. **대응표의 정본이 자동 산출로 바뀐다.**
   - 지금 손으로 만든 `sigungu-canonical-crosswalk.contract.json` 의 27쌍은 자동 산출과 비교하는 기준으로만 남긴다.
     두 결과가 다르면 적재를 멈춘다.
   - 적재 프로그램은 자동 산출 대응표를 읽는다. 사람이 승인한 행만 확인 목록에서 들어간다.
   - ADR-0142 의 거부(통합 시도 미대응 코드, PNU 누락 비율)는 그대로 둔다.
6. **예절과 실패.**
   - 요청 간격 15초 이상, 하루 한 번만 받는다. 실패하면 다음 날 다시 받는다.
   - 사이트 형식이 바뀌어 파싱이 실패하면 아무것도 적재하지 않는다. 그 사실을 알림으로 낸다(Slack, ADR-0122 실패 알림).
   - 조용히 빈 결과를 적재하지 않는다.

## Consequences

- 다음 개편은 공지 첨부 → 자동 짝 → 대응표 → 재적재(ADR-0142 검사) → Gold(ADR-0139) → 굽기(ADR-0141)로 흐른다.
  사람은 확인 목록에 오른 애매한 건만 승인한다.
- 공식 API 가 아닌 웹 화면에 기댄다. 형식 변경이 가장 큰 위험이다. 그래서 파싱 실패는 적재 중단 + 알림이고, data.go.kr
  API 차이를 보조 검증으로 남긴다.
- 9-29 에 만든 적재 코드(#252)와 짝 도출 코드(#210·#211·#214)를 재사용한다. 새로 필요한 것:
  - 수집기 두 개(전체 표, 변경안내);
  - 엑셀 파서;
  - 대응표 정본 전환.
- 확인 목록을 사람이 보는 화면은 더니어(ADR-0114)의 계보 검토 창구를 쓴다.

## 개정 기록

- 2026-10-04: §3(코드변경안내 첨부를 짝의 1순위로 둔 결정)은 [ADR-0144](./0144-region-code-changes-are-derived-from-downloaded-data-only.md)가
  대체했다. 게시판은 원천이 아니며, 짝은 전체 코드 표와 VWorld 연속지적·필지고유번호변동연혁 데이터로만 판단한다. 위 결정 본문은 고치지 않았다.
