# ADR 0084: 등록부는 수집된 모든 객체를 안다

- Status: Accepted
- Date: 2026-09-06

## Context

`catalog.bronze_object` 는 수집물의 등록부인데, 2026-09-06 실측으로 hub.go.kr 172객체만
알고 있었다. 2026-07-02 일괄 수집된 vworld 24개 prefix(11,495객체, 약 271GB)는 등록부
이전 시대의 산물이라 어디에도 적혀 있지 않다 — 같은 사실(무엇이 수집돼 있는가)의 답이
등록부와 버킷에서 갈라진 상태다.

복구 레인(`compile-vworld-bronze-catalog-recovery-manifest` → `recover-bronze-catalog`)은
이미 있고, 증거 모델도 있다: 후보마다 그 메타데이터를 보증하는 증거 종류가 붙고, 경로
추론(`object_path_inference`)은 비권위로 거부된다. 실측 결과 이 모델의 빈틈이 드러났다:

- 오늘의 제공자 목록으로 대조하면 11,495 중 **2,904 가 미대조**다. 제공자가 옛 파일을
  목록에서 회전 제거하기 때문이다(토지특성: 7/14 목록 807개 → 오늘 538개).
- 과거 컴파일이 봉인해 둔 목록 보관본(`control/evidence/bronze-catalog-recovery/
  provider-inventory/`, 7/14·9/4)을 합치면 미대조가 **862** 로 준다. 그 862는 수집(7/2)과
  첫 보관 목록(7/14) 사이에 회전된 파일들로, 어떤 생존 목록도 다시 보증할 수 없다.
- 수집 당시의 ingest evidence JSON 은 수집 기계와 함께 사라졌다(로컬·R2 전수 수색).

즉 등록부를 실물과 일치시키려면, "목록이 보증하는 객체"와 "목록은 잃었지만 저장소가
관측한 객체"를 구별해서 둘 다 적을 수 있어야 한다.

## Decision

1. **목록 대조는 스냅샷 하나가 아니라 보관본 전체와 한다.** 컴파일의 제공자 목록 입력은
   경로 목록(쉼표 구분)을 받아 합집합으로 대조한다. 같은 파일이 여러 스냅샷에 있으면
   최신 스냅샷의 메타데이터가 이긴다. (이 결정 전에는 사람이 손으로 JSON 을 합쳤다 —
   그 손작업이 이 조항으로 코드가 된다.)
2. **저장 관측(`storage_observation`)을 권위 증거로 추가한다.** 어떤 보관 목록도 보증하지
   못하는 canonical-prefix 객체는, R2 감사 실측(etag·크기·last-modified)과 apply 시
   전체 재해시를 증거로 등록한다. 이 증거가 주장하는 것은 관측 가능한 것뿐이다:
   checksum 과 크기는 실측, 수집 시각과 snapshot 날짜는 저장소의 last-modified,
   `provider_file_id`·`provider_file_name`·`provider_updated_at` 은 **NULL** — 파일명에서
   제공자 의미를 지어내지 않는다. 행의 `request_params` 에 증거 종류가 남아, 등록부가
   각 행이 어떻게 보증됐는지를 스스로 말한다.
3. **경로 추론은 계속 거부한다.** `storage_observation` 은 경로에서 의미를 읽는 것이
   아니라 저장소 실측을 적는 것이다 — 제공자 의미를 채우고 싶으면 목록 보관본을 늘리는
   것이 길이지, 추론이 길이 아니다.
4. **회전 제거는 삭제 사유가 아니다.** 제공자가 목록에서 내린 수집물도 등록부와 버킷에
   남는다(전 데이터 append-only 원칙). 반대로 목록에는 있는데 대조가 안 되는 객체는
   여전히 unresolved 로 manifest 를 막는다 — 그것은 회전이 아니라 사고다.

## Consequences

- vworld 24개 prefix 11,495객체가 등록부에 오른다: 10,633 은 목록 증거로, 862 는 저장
  관측으로. 등록부 질의 하나가 수집 실물 전체를 답하게 된다.
- 컴파일이 보관 목록을 읽으므로, 오늘의 목록 수집이 실패해도 과거 보관본만으로 재대조가
  가능하다.
- 남는 격차는 이 결정의 범위 밖으로 명명한다: vworld 레인은 아직 daily sweep 에 편입돼
  있지 않아 **신간 파일은 수집되지 않는다**(hub 레인만 ADR-0077 타이머를 탄다). 다음
  결정 후보.
