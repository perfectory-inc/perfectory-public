# ADR 0475: 주소정보 전자지도는 승인키 하나로 공식 변동자료 연계에서 매일 받는다

- Status: Accepted
- Date: 2026-11-10
- Amends: [ADR-0355](./0355-the-building-hub-juso-map-and-other-bulk-sources-are-judged-one-by-one-and-connected-in-order.md)
  §3("승인 뒤 첫 판을 실측한 PR 이 수집기를 만든다"). 나머지 판정(11 종의 등급과 연결 순서)은 그대로다.
- Builds on: [ADR-0457](./0457-a-job-never-run-takes-its-first-run-unattended-bounded-by-its-unit-and-the-run-is-the-measurement.md)
  (사람 없는 첫 run), ADR-0153(런타임 비밀 계약), ADR-0329 §3(법정동 코드 변경 따라가기), ADR-0445(OnFailure 알림)

## Context

주소정보 전자지도 11 종(건물·출입구·건물군·도로구간·기초구간·실폭도로·국가기초구역·법정구역 시도·시군구·읍면동·리)은
받은 객체가 0 이다. ADR-0355 §3 은 "사장이 이용 신청 → 승인 → 첫 판 실측 PR 이 수집기"로 정했고, 전자지도 내려받기는
달마다 손으로 신청하는 길이라 사장이 거절했다(2026-11-04: 매달 수동 신청 거절 = 자동화하라는 뜻).

자동 경로가 있다. 주소기반산업지원서비스의 **데이터 연계(변동자료 연계서비스)**는 한 번의 신청으로 승인키(app_key)를
주고, 그 키로 `update.juso.go.kr/updateInfo.do` 에 요청 코드(cntc_cd)와 날짜를 물으면 그날의 변동 파일을 준다. 사장이
2026-11-10 신청했다. 2026-11-10 에 확인한 사실:

| 항목 | 값 | 출처 |
|---|---|---|
| 요청 | `app_key`, `date_gb=D`, `cntc_cd`, `retry_in=Y`, `req_dt`·`req_dt2`(YYYYMMDD, 최대 10일) | 제공처 공개 가이드(기타언어, 72쪽) §3.1 |
| 전자지도 요청 코드 | 300001 건물도형(JUSURB: 건물·출입구·연결선), 300002 건물군 내 동 도형(JUSUED), 300003 도로 도형(JUSUZG: 도로구간·기초구간·실폭도로), 300006 구역의 도형(JUSUGE: 법정구역 4 단계·행정구역·기초구역·지점번호표기지역) | 가이드 p.10, pp.17–23 |
| 응답 | 파일마다 100 바이트 고정폭 머리(순번 0–2, 기준일 2–10, 파일명 10–60, 크기 60–70, 결과 70–75, cntc_cd 75–81, 재반영 81–82, 생성일 82–90) + zip(shp·shx·dbf, 삭제는 `<표>.Deletion.TXT` 의 PK) | 가이드 §3.2, p.34 |
| 오류 | HTTP 200, 응답 머리 `err_code: E0001`, `approval_yn: N`, 빈 본문 | **실측**(키 없이 1 회) |
| 좌표계 | EPSG:5179 | 가이드 pp.54–55 |

`req_dt` 없이 물으면 서버가 "마지막 제공일"부터 고르고 같은 날 두 번째 질문엔 P1000(아무것도 안 줌)으로 답한다
(가이드 §3.1). run 하나를 잃으면 그 파일도 잃는 모양이라, 창을 늘 우리가 정한다.

큰 곳의 방식: 변경 데이터 수집(CDC)은 소비자가 자기 오프셋을 가진다 — Kafka 소비자 그룹의 커밋 오프셋, Debezium 의
source offset, AWS DMS 의 체크포인트. 제공처의 "마지막으로 준 곳"에 기대지 않고, 같은 위치를 다시 물으면 같은 것을 받는다.
Airflow 의 데이터 구간(`data_interval_start/end`)으로 백필하는 것도 같은 모양이다.

## Decision

1. **원천은 공식 변동자료 연계다.** 계약 `infra/lakehouse/contracts/juso-electronic-map.contract.json` 이 URL·질문·머리의
   바이트 위치·결과 코드·요청 코드·11 종을 가진다. 다른 곳은 이 값을 다시 적지 않는다. 승인키는 런타임 비밀 묶음 `juso`
   (`/etc/foundation-platform/juso.env`, root:root 0600, `FOUNDATION_PLATFORM_JUSO_APP_KEY`, 선택)에만 있고, 질문 URL 말고는
   Bronze·manifest·로그 어디에도 적히지 않는다(오류는 URL 을 뺀다).
2. **커서는 우리 것이다.** 요청 코드마다 상태 디렉터리에 다음에 물을 날(`<cntc_cd>/cursor.json`)을 둔다. run 은 커서부터
   어제(KST)까지 최대 10 일 창을 오래된 것부터 묻고, 창을 늘 `req_dt`/`req_dt2` 로 이름 붙인다. 창의 파일이 모두 커밋된
   뒤에만 커서를 옮긴다. E1001(그 기간 파일 없음)은 창을 끝낸다.
3. **Bronze 는 받은 그대로, 종류마다 한 벌.** 받은 zip 은 그 요청 코드가 맡는 모든 종류의 Bronze(`jusogokr__<kind>`, 카탈로그의
   11 원천)에 바이트 그대로 남는다(같은 SHA-256). 객체 이름은 파일명·재반영 여부·생성일이라 같은 파일을 두 번 받아도 같은
   객체이고, 커미터의 쓰기-한 번 충돌이 같은 체크섬이면 성공으로 끝난다(FP-ADR-0016). 종류의 Silver 는 자기 원천만 읽는다
   (부분 처리 원칙). zip 을 Bronze 전에 자르지 않는다.
4. **거부는 멈추고 알린다; 풀어 줄 파일은 없다.** E0001–E0004(키), E1008(승인되지 않은 요청 코드)은 그 자리에서 모든 질문을
   멈추고 run 을 실패시켜 유닛의 OnFailure 가 알린다(ADR-0445). 다음 일정의 run 이 스스로 다시 묻는다 — 사람이 지울 차단
   파일이 없다. 제공처 오류(E1005·E1999)는 그 코드만 이번 run 에서 멈추고 실패로 끝난다. 우리가 잘못 만든 질문(P1000 등)과
   모르는 코드는 실패다.
5. **백필과 run 당 상한.** 역사는 `backfill.first_day`(2020-01-01)부터다. 상한은 코드마다 창 30 개, run 전체 6 GB 중 먼저
   닿는 것(작업 `per_run_cap.limits` 가 두 값을 가리킨다). 2,505 일은 코드마다 251 창이라 매일 run 9 번쯤에 따라잡는다.
6. **키가 없으면 기다리고, 생기면 첫 run 이 측정이다.** 작업 `juso_electronic_map` 은 켜져 있고(ADR-0457 `first_run`, 계산
   2,400 s / 제한 7,200 s, `as_it_goes`, `retries: 0`), 키가 없으면 스크립트가 아무것도 묻지 않고
   `foundation-job-outcome waiting …` 으로 끝난다. 사장이 키를 한 번 놓으면(`foundation-release.sh env-set juso <파일>`) 다음
   일정(매일 23:30 UTC = 08:30 KST, 제공처가 07:00 KST 뒤에 만든다)의 run 이 사람 없이 첫 측정 run 이 된다. 측정 PR 은
   `waiting` 으로 끝난 run 을 세지 않는다.
7. **Silver 는 종류마다, 모두 법정동 코드 변경을 따라간다(다음 변경).** 계약 `kinds` 가 종류마다 표·PK·법정동 칸
   (`legal_code`: 건물·출입구·도로·기초구역은 `SIG_CD` 시군구, 건물군은 `BD_MGT_SN` 앞 10 자리, 법정구역은 자기 코드)을
   가진다. Silver 적재는 일별 변동을 기준일·생성일 순으로 바뀐 키와 삭제 표지만 쌓고(ADR-0318), 그 칸을
   `views.changed_codes` 아래 행만 다시 잇는다(ADR-0329 §3). 그 적재는 이 수집의 첫 측정 run 으로 받은 실물 판에 맞춰
   만든다.

## Consequences

- 사장 할 일은 승인키를 놓는 것 하나다. 요청 코드 목록은 제공처 공개 가이드에 있어 따로 받을 필요가 없다. 다만 신청 때 고른
  자료에 300001·300002·300003·300006 이 없으면 그 코드는 E1008 로 거부되어 알림이 간다 — 그때는 연계 신청에 그 자료를
  더하는 것이 사장 할 일이다.
- **초기 전체본은 이 연계에 없다.** 가이드는 "초기자료 구축"을 따로 받는 전체자료로 하라고 한다. 2020 년 이후 한 번도 바뀌지
  않은 건물·도로는 변동 파일에 나오지 않는다. 전체본을 어떻게 받을지(전자지도 1 회 신청 또는 다른 원천)는 사장 판단으로
  남긴다; 변동 수집은 그것과 관계없이 지금 시작한다.
- 크기와 시간은 아직 재지 않았다. 첫 run 이 잰다. 메모리 상한 3 GB(10 일 답의 파일을 들고 커밋마다 한 벌 더)는
  `tools/host-memory-budget.contract.json` 에 있고, 첫 run 의 `memory peak` 로 다시 정한다.
- 비용: R2 쓰기는 받은 바이트의 약 3.5 배(종류마다 한 벌). 백필 전체 크기를 모르므로 첫 run 의 실측으로 계산해 보고한다.
- 가드: `orchestration/tests/test_juso_electronic_map_command.py` 가 키 없는 run 이 아무것도 묻지 않고 `waiting` 으로
  끝남, 거부가 run 을 실패시킴, 빠진 변수가 부작용 전에 멈춤을 증명한다. 막는 사고: 키 없이 켠 수집이 매일 E0001 실패
  알림을 내거나(키를 놓기 전), 거부된 키로 계속 묻는 것.
