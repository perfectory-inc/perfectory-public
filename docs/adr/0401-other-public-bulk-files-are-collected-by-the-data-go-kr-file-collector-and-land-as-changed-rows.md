# ADR 0401: 기타 공공 일괄 파일은 data.go.kr 파일 수집기가 받고, 바뀐 행만 Silver 에 쌓는다

- Status: Accepted
- Date: 2026-11-04
- Builds on: ADR-0280 §4(data.go.kr 파일 데이터 수집기, 주소로 PNU), ADR-0355 §4(기타 일괄 12개는 실제 제공자부터),
  ADR-0288(place-identity), ADR-0318(바뀐 키만 쌓는다), ADR-0329 §3(`views.changed_codes`), ADR-0400(판정표)

## Context

ADR-0355 §4 는 기타 공공 일괄 파일 12개의 카탈로그 제공자가 `mixed_public_source` 라 수집기를 만들 수 없다고 했다.
원천마다 실제 제공자를 적고, data.go.kr 파일 데이터 수집기(`collect-data-go-kr-registered-factory`)를 계약에 적힌
여러 파일로 넓히라고 했다. ADR-0400 의 판정표에서 12개는 모두 "미수집" 이다.

**측정 (2026-11-04, 공공데이터포털 공개 페이지·파일을 직접 받음).** 포털의 두 단계(메타데이터가 현재 파일 id 를 말하고,
그 id 로 파일을 받는다)는 등록공장과 같다. 12개 원천의 실제 제공자는 다음과 같다.

- **표준데이터 3개는 같은 두 단계로 받을 수 없다.** 메타데이터가 파일 id 를 주지 않는다. 포털 화면의 내려받기는
  브라우저 스크립트가 행을 모아 CSV 를 만든다. 쿠키·Referer 를 붙인 요청도 HTML 을 돌려줬다. 표준데이터는 같은 행을
  공공데이터 OpenAPI(`api.data.go.kr/openapi/tn_pubr_*`)로 준다. 우리가 이미 가진 data.go.kr 서비스 키로 받는다.
  그 수집 방식은 파일 수집기와 다르므로 다음 PR 이다. 그때까지 판정표에서 "미수집" 으로 남는다.
- 사장 결정(2026-11-03 "보여 주는 것이 항상 이긴다")으로 ADR-0355 의 "Bronze 보관만"(학교·대학·세대수·상권·역↔노선)도
  받아 Silver 까지 잇는다. 보관만 하는 이유(가치가 낮음)는 비용 이유였고, 비용은 이제 판정에 들지 않는다.

### 실사례

- **커넥터 하나, 스트림 선언 여럿.** Airbyte 의 파일 소스(`source-file`)와 Singer `tap-csv` 는 한 커넥터가 계약의 파일 목록을
  돌며 파일마다 스트림을 낸다. 새 파일은 선언 한 줄이다. 우리 data.go.kr 파일 수집기를 그렇게 넓힌다.
- **원천 행을 먼저, 형은 나중에.** Fivetran·Airbyte 의 raw 표(`_airbyte_raw_*`)는 원천 행을 그대로 쌓고 형을 갖춘 표는
  그 위에 만든다. 여기서는 형(칸 이름)을 계약이 알므로 원문 칸 전체를 보존한 채 행마다 키를 갖춰 쌓는다.

## Decision

1. **수집기는 하나다.** `data-go-kr-registered-factory.contract.json` 의 포털 두 단계(메타데이터 → 파일 id → 내려받기)를
   파일 목록 계약 `infra/lakehouse/contracts/data-go-kr-file-data.contract.json` 으로 넓힌다. 파일마다 `source_slug`,
   `publicDataPk`·`publicDataDetailPk`·`fileDetailSn`, 형식(CSV 또는 ZIP 안의 이름 규칙), 인코딩, 정확한 머리줄,
   행 수 하한·줄어듦 한계, 행 키 규칙, 필지 연결 방식을 적는다. 등록공장은 같은 계약의 한 항목이 된다. 새 파일 id 만
   받고, 같은 id 는 두 번 받지 않는다. 받은 파일은 그 원천의 Bronze 에 남는다(append-only).
2. **카탈로그의 제공자를 실물로 바꾼다.** 수집을 켜는 PR 이 12개 항목의 `provider`·`operation`·`source_acquisition_lane`·
   `group` 을 위 표의 실물로 바꾼다(`mixed_public_source` 를 없앤다). slug 는 그대로다(Bronze 경로가 slug 다).
3. **Silver 는 바뀐 행만.** 파일마다 Silver 표 하나다. 행 키는 제공자 키가 있으면 그것(상가업소번호, 행정기관코드+기준연월,
   행정동코드+법정동코드 등), 없으면 행 글자의 SHA-256(ADR-0397 과 같은 규칙)이다. 판마다 키별로 비교해 새 행·바뀐 행과
   사라진 키의 삭제 표지만 쌓는다(ADR-0318). 원문 칸은 머리줄 이름 그대로 모두 보존한다. 매월 바뀌는 인구·세대수는
   `기준연월` 이 키의 일부라 지난 달 행은 사라지지 않고 쌓인다.
4. **필지·법정동 연결은 해석기로, 코드 변경을 따라간다.**
   - 주소 글(역·항만·공항·학교·대학)은 등록공장과 같은 `address_pnu` 단계(지번 → 도로명)로 PNU 를 찾고, 단계와
     못 찾은 이유를 행에 남긴다. 좌표로 정하지 않는다(ADR-0280 §4, ADR-0020).
   - 상권의 지번코드는 제공자 코드다. 그대로 복사하지 않고 place-identity 해석기(ADR-0288)로 현재 PNU 를 정한다.
   - 이름으로만 위치를 말하는 고속도로 출입시설은 도·시군구·읍면동 이름을 법정동 코드표로 법정동까지만 잇는다(PNU 없음).
   - 행정동 단위(인구·세대수)는 연계표(`public-bulk-adm-dong-code-linkage`)로 법정동에 잇는다.
   - 어느 경우든 적재 때 한 번 풀고 멈추지 않는다. 법정동 코드가 바뀌면 `views.changed_codes`(ADR-0329 §3)가 닿는 행만
     다시 해석한다.
5. **작업과 run 당 상한.** 수집·적재는 등록공장 작업과 같은 틀의 작업 하나(`jobs.v1.json`, `enabled: true`, `scope`)다.
   run 하나가 파일 하나의 새 판 하나를 적재한다. 상권(349 MB ZIP, 275만 행)만 크다. 그 PR 이 첫 적재 시간을 재고
   작업 단위 시간 안에 드는지 적는다.
6. **판정표를 따라 옮긴다.** 수집을 켠 endpoint 는 ADR-0400 분류에서 수집·미서빙이 되고, 화면이 읽으면 수집·서빙이 된다.

## Consequences

- **비용(계산).** 상권을 뺀 8개 파일은 합해 16 MB 이다. 상권은 분기마다 349 MB 이다(1년 1.4 GB). R2 저장 $0.015/GB·월,
  1,450원/$ 로 첫 해 말 월 약 40원이다. 포털 내려받기와 R2 쓰기는 무료 등급 안이다. 적재는 ai-server 에서 돈다.
- 표준데이터 3개(학교·대학·도시철도역)는 OpenAPI 수집 PR 이 따로 연다. 판정표는 그때까지 미수집이라 말한다.
- 거리 파생(필지 → 가장 가까운 IC·역·항만·공항)은 ADR-0355 §4 대로 새 Gold 틀이고 따로 ADR 을 쓴다. 이 ADR 은
  Silver 까지다.
