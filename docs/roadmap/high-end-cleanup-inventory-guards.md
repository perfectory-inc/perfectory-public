# 하이엔드 정리 인벤토리 — 가드 부록

[하이엔드 정리 인벤토리](./high-end-cleanup-inventory.md)의 부록이다. 기준 커밋과 측정 방법은 본문을 따른다.

LOC는 구현 파일(wrapper + checker + 그 가드가 소유한 helper/contract)의 줄 수이며, 자기 시험 LOC는 별도로 센다.

배선: `scripts/guard/monorepo-guard.sh`가 `tools/ci/change-scope.json`의 `guards.run`을 읽어 실행한다(141개 항목 = 가드 60개 + 자기 시험 81개). 이는 `monorepo-guard.yml`에서 `cargo xtask verify tooling`으로 돈다. pre-push는 루트 `lefthook.yml`이 맡는다.

분류 범례
- `E-SSOT`: 사본끼리 맞는지만 보는 가드 — 정본에서 생성하면 사라진다.
- `R-OSS`: 성숙한 도구 규칙으로 바뀐다.
- `KEEP-DOMAIN`: 도메인 불변식이라 남긴다.
- `PATCH`: 땜질 위 땜질 — 줄기만 하는 기준선, 가드를 지키는 가드.
- `DEAD`: 배선 없음 또는 지킬 대상이 사라짐.

## 메모

- 가드로 보지 않아 제외한 것: 러너 `monorepo-guard.sh`, build/deploy 도구의 자기 시험(release-build, release-push, tiles-slice-proof-env, foundation-ci-scope, assert-runtime-migrations, assert-runtime-environment). 그 외 제외: 런타임 운영 점검(`platforms/foundation-platform/scripts/ops/*-check.py`, service-checks)과 CI 셀렉터(`change_scope.py`, `guard_scope.py`, `foundation_ci_scope.py`).
- 앞서 나온 "커스텀 가드 76개, 대체 가능 ~40개" 수치에 대해: `scripts/guard`는 실행 목록에 가드 60개를 담고 있다. 자기 시험을 통해서만 드러나는 가드(workflow-policy, osv ratchet, identity/legal, GitHub API preflight 등)까지 세면 약 73개 가드 단위가 된다. 저장소 전체로는 표가 100행이다: 영역 가드, CI 인라인 점검, 정책성 시험이 포함되고 일부 행은 여러 파일을 묶는다. 38행이 R-OSS, 24행이 E-SSOT라 62행(구현 LOC 약 15.5k)이 사라지거나 규칙 파일 하나로 줄어들 것이다. E-SSOT까지 넣으면 "대체 가능 약 40개"는 과소집계다. `scripts/guard`만 보면 R-OSS 25 + E-SSOT 20 = 65행 중 45행이다.
- 배선 없는 것: `scripts/guard` 안에 배선 안 된 파일은 없다. 두 가드는 **공허**하다: xtask-path-coverage와 area-ci-input-coverage 둘 다 `paths:`가 없는 워크플로는 건너뛰는데, ADR-0207 이후 `paths:`가 있는 워크플로가 없다. gongzzang repo-guard 점검 둘은 루트 가드와 중복된다. check-billing-budgets / check-actions-cache-controls / check-publication-authority의 실제 점검 쪽은 손으로만 돌고, CI는 그 자기 시험만 돌린다.
- 중복 군집(규칙 하나에 가드 여럿): 필지 declared reads(foundation-parcel-current-selector, parcel-reads-the-served-edition, `test_platform_contracts.py`); R2 단일 읽기경로(r2-reads-have-one-path, `test_r2_read_policy.py`); env/자격증명 이름(r2-env-namespace-consistency, environment-variable-naming, credential-names, runtime-secrets-contract) 모두 runtime-secrets/r2-connections 계약 위에; 마이그레이션 이름(migration-naming, repo-guard migration_version_prefixes, `numbering_collisions.py`); 줄 수 상한(file-line-limit, repo-guard file_line_limit); append-only 버전(by-pnu-document-records-are-append-only, schema-registry).
- 축소전용 기준선(PATCH): `tools/ci/file-line-limit.exceptions.json`, `tools/ci/full-scope-jobs.baseline.json`, build-coupling 기준선, `tools/osv-vulnerability-baseline.tsv`, `scripts/catalog/documentation-debt.baseline.json`, 그리고 area-registry allow-list.
