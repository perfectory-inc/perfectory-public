# ADR 0289: 법원경매는 브라우저로 접속해 스스로 속도를 조절하고, 막혀도 세션을 바꿔 끝까지 모은다

## Context

사장 결정(2026-10-21): ADR-0281 의 수집 방식은 틀렸다. 저장소 밖에서 만든 Python 시제품(`curl_cffi` 로 크롬 흉내, 막히면 쿠키 교체, 동시 요청)을 기준으로 삼되, 그대로 쓰지 않고 Rust 로 더 낫게 만든다.

두 방식을 실측으로 비교했다.

| 항목 | 지금 main (ADR-0281) | 시제품 (2026-10-21 실측) |
|---|---|---|
| 접속 | 우리 이름 User-Agent, 연결 1개, 요청 사이 3초 | 크롬 TLS·HTTP/2 지문, 동시 요청 3(목록)·10(사건상세)·6(물건상세) |
| 속도 | 초당 0.3 요청 (10-19 밤 1,377 요청에 77분) | 평균 초당 약 37 요청 (약 16.2만 요청에 73분) |
| 막힘 | 10-20 낮 실행이 174 요청 만에 `ipcheck=false` 로 멈춤, 그 뒤 수집 없음 | 16번 막힘(목록 2·사건상세 4·물건상세 10), 전부 쿠키 교체로 풀림, 잃은 데이터 0 |
| 범위 | 목록 2종만, 그것도 날짜를 안 보내 서버가 "오늘~14일" 만 줌(물건 검색 1,125쪽) | 목록(앞뒤 365일, 2,169쪽, 고유 66,326행) + 사건상세 4종 + 물건상세 |

시제품이 확인한 사이트의 동작:

- 차단은 **HTTP 200** 으로 온다. 본문이 `{"message":"해당 IP는 비정상적인 접속으로 보안정책에의하여 차단되었습니다.","data":{"ipcheck":false}}` 다. 문구는 IP 차단이지만 **새 쿠키**(첫 화면 `GET /pgj/index.on` 한 번)로 바로 풀린다. 차단 단위는 쿠키다.
- 쿠키 하나의 수명은 일정하지 않다: 검색 API 약 1,000~1,400 요청, 상세 API 약 12,000~45,000 요청.
- 검색 API 는 서버가 한 건씩 처리해서(약 450ms) 동시 요청을 늘려도 빨라지지 않는다. 상세 API 는 동시 10 에서 초당 115~135 요청이 나온다. 물건상세는 응답이 1.5~5MB 라(사진) 초당 8~13 이 한계다.
- `pageSize` 는 최대 50 이다(100 부터 HTTP 400).

시제품의 약점: 막히면 다시 시도하는 데 상한이 없는 것은 그대로 두되(사장 결정), 진행이 멈춰도 아무도 모른다. 동시 요청 수가 고정이다. 같은 key 는 다시 받지 않아 바뀐 내용이 반영되지 않는다(ADR-0290). 오류 5번이면 그 건을 조용히 버린다. 값이 코드 안 상수다.

## Decision

1. **브라우저로 접속한다.** 접속 계층은 Rust 크레이트 `wreq`(+`wreq-util` 의 브라우저 프로필)로 크롬의 TLS(JA3/JA4)·HTTP/2·헤더 순서를 흉내 낸다. 쓰는 프로필 이름과 크레이트 버전은 계약에 한 번만 적는다. 요청 헤더는 사이트 화면이 보내는 그대로다(`Origin`, `Referer`, `submissionid`, `SC-Userid`, `SC-Pgmid`). 우리 이름을 단 User-Agent 는 보내지 않는다.
   - **채택 조건:** 같은 요청 묶음을 시제품(`curl_cffi`)과 `wreq` 로 보내 쿠키당 수명·차단 횟수·초당 요청을 비교하는 스파이크를 먼저 한다. `wreq` 가 시제품보다 나쁘면 이 항목을 다시 결정한다. 접속 계층은 trait 하나 뒤에 두어 크레이트를 바꿔도 수집기 나머지는 바뀌지 않는다.
2. **세션은 풀로 둔다.** 쿠키 세션 여러 개를 두고 요청마다 하나를 빌린다. 세션은 첫 화면 `GET` 한 번으로 만든다. 세션마다 만든 시각·보낸 요청 수·막힌 시각을 기록한다(쿠키 수명 지표).
3. **막히면 세션을 바꿔 끝까지 다시 시도한다. 상한은 없다.** 막힘 판정은 계약의 신호 목록이다: HTTP 3xx·403·429, JSON 자리에 HTML, `data.ipcheck == false`, `data` 가 객체가 아님. 막히면 계약의 대기 단계(지금 값 5→15→60→300초, 마지막 값 반복)만큼 기다린 뒤 그 세션을 버리고 새 세션으로 같은 요청을 다시 보낸다. 실행은 멈추지 않는다.
   - **진행 없음 알림:** 계약의 시간(분) 동안 성공한 요청이 하나도 없으면 알린다. 알리기만 하고 멈추지 않는다. 쿠키를 바꿔도 안 풀리는 진짜 IP 차단은 이것으로 사람이 안다.
   - 막힘이 아닌 오류(네트워크 오류, 5xx, JSON 깨짐)는 계약의 횟수만큼 지수 대기로 다시 시도하고, 그래도 안 되면 **실패 장부**에 key 를 남긴다(ADR-0290 §5). 조용히 버리지 않는다.
4. **속도는 스스로 조절한다.** 엔드포인트 묶음마다(목록 검색, 사건상세, 물건상세) 동시 요청 수를 따로 조절한다. 계약의 시작값에서 출발해, 막힘 없이 일정 시간이 지나면 하나 올리고, 막히거나 응답 시간이 계약의 기준보다 길어지면 절반으로 내린다(AIMD). 시작값·올리는 간격·내리는 비율·최대치·응답 시간 기준은 계약 값이다.
5. **시간대 제한을 두지 않는다.** 수집은 하루 언제든 돈다. ADR-0282 의 운영자 창(window) 스위치는 남긴다 — 운영자가 좁힐 때만 좁혀진다. 계약의 `quiet_hours_kst` 는 없앤다.
6. **이번 결정에 넣지 않는 것:** 프록시·IP 돌리기·CAPTCHA 풀기. 실측에서 차단 단위가 쿠키라 필요 없었다. 필요해지면 새 ADR 로 정한다.
7. **SSOT — 값은 계약 한 곳에만 둔다.** `infra/lakehouse/contracts/courtauction-go-kr.contract.json` 이 엔드포인트(경로·dataMap 이름·`submissionid`·`SC-Pgmid`·바디 키), 목록 검색 조건과 날짜 범위(앞뒤 일수), 쪽 크기, 브라우저 프로필, 세션 풀 크기, 막힘 신호, 대기 단계, 진행 없음 알림 시간, 속도 조절 값을 가진다.
   - 수집기 코드에는 이 값들의 리터럴이 없다. **시험:** 수집기 소스에서 계약에 있는 경로 문자열(`/pgj/`)과 dataMap 이름을 찾으면 실패한다(위반을 심어 거부를 확인한다).
   - 작업 등록부(`orchestration/jobs.v1.json`)·런북·systemd 설명·doc 주석은 값을 다시 적지 않고 계약을 가리킨다. 지금 `court_auction_collect` 설명이 "3초", "01:00 and 06:00" 을 다시 적고 있는데 이것을 지운다.
   - 시험은 계약 값을 베끼지 않고 계약을 읽어서 검사한다.
   - 계약의 `forbidden_in_collector` 목록과 그것을 읽는 시험은 ADR-0281 §4 를 지키던 것이라 함께 지운다.
8. **Bronze 쓰기는 FP-ADR-0016 관문 하나로 한다.** 모든 원본 응답은 `BronzeCommitter` 로 한 번만 쓰고(CreateOnly), SHA-256 을 찍고, `bronze_object` 행을 남긴다. 같은 이름에 다른 내용이면 `ChecksumConflict` 로 격리한다. 수집기가 자기 방식으로 R2 에 쓰지 않는다.

## Consequences

- 목록 한 바퀴가 약 78분에서 약 8분으로 줄고, 날짜 범위가 들어가 물건 검색이 약 2배(1,125쪽 → 약 2,169쪽)가 된다. 상세 수집(ADR-0290)이 가능해진다.
- `wreq` 는 BoringSSL(C/C++)을 빌드한다. foundation 워크스페이스에 `openssl-sys` 가 없어 심볼 충돌은 없다. 빌드에 cmake·C 컴파일러가 필요해 CI 와 ai-server 빌드 이미지를 확인해야 한다. Rust-only 의 예외는 TLS 라이브러리 하나로 한정한다.
- 크롬 프로필은 크롬이 바뀌면(약 4주) 낡는다. 버전은 계약에 한 곳만 있으니 올리는 PR 은 한 줄이다. 진행 없음 알림과 쿠키 수명 지표가 낡은 프로필의 신호다.
- 차단이 계속되는 동안에도 다시 시도하므로, 진짜 IP 차단이 오면 서버 IP 가 계속 차단 상태로 남을 수 있다. 진행 없음 알림을 받은 사람이 운영자 스위치(ADR-0282)로 멈출 수 있다.
- 약관 제15조 1호(서비스 방해·설비 손상 금지)는 사장이 받아들인 법적 위험의 경계로 남는다. §4 가 막힘과 응답 지연이 보이면 속도를 내리는 것이 이 경계를 지키는 장치다.
- 거절 상태 파일(`refused.json`)과 `job clear-refusal`(#808)은 "거절 시 정지" 를 위한 것이라 없앤다. 초안 #801(작업 켜기)은 이 ADR 에 맞춰 다시 쓰고, #802 는 닫는다.

## Rejected

- **ADR-0281 유지(신원 공개·3초·새벽만·거절 시 정지):** 낮에 174 요청 만에 멈췄고, 상세 수집은 3초 간격으로 수백 시간이 걸린다. 사장이 기각했다.
- **Python 시제품을 그대로 운영:** 우리 수집기는 Rust 이고 Bronze 관문·계약·작업 등록부를 쓴다. 시제품은 값이 코드 상수이고, 진행 감시·실패 장부·증분이 없다.
- **curl-impersonate 를 Rust 에서 직접 연결:** `curl_cffi` 와 같은 엔진이지만 Rust 바인딩(`impcurl`, `ratcurl` 등)이 소규모 개인 프로젝트다. §1 의 스파이크가 `wreq` 를 기각하면 다시 본다.
- **`impit`:** rustls 와 h2 를 워크스페이스 전체에서 패치해야 빌드된다. foundation 의 다른 TLS(R2, Postgres)까지 패치된 포크 위에서 돌게 된다.
