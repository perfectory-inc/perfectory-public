# ADR 0556: 컴파일 시 읽기는 소스 파일마다 한 줄로 선언한다 — 서로 무관한 PR 이 숫자 하나를 함께 고치지 않는다

- Status: Accepted
- Date: 2026-11-12
- Amends: `scripts/guard/build-coupling-baseline.sh` 의 컴파일 시 읽기 기준(숫자 하나 → 파일별 목록). 빌드 스크립트 기준과
  "이미지는 자기가 컴파일하는 파일을 가진다"(ADR-0345)는 그대로다.

## Context

레인 PR 과 수집기 PR 은 서로 다른 파일을 고치는데도 하나씩 차례로만 병합됐다. 뒤 PR 은 앞 PR 이 병합될 때마다
리베이스해야 했다. 같은 줄을 고치기 때문이다. 2026-11-12 실측:

| 여러 PR 이 함께 고치는 줄 | 어디 | 크기 |
|---|---|---|
| `COMPILE_TIME_READ_BASELINE="${3:-170}"` 와 그 위의 이유 주석 | `scripts/guard/build-coupling-baseline.sh` | 지금까지 87번 올림. **열린 PR 8개**(#1343·#1335·#1325·#1295·#1290·#1283·#1282·#1277)가 지금 이 줄을 고친다 |
| `const ALL: [Self; 31]` | `silver_refresh/lane.rs` | 열린 PR 5개 |
| `assertEqual(len(lanes), N)`, `["hub"] * N + ["vworld"] * M` | `test_lakehouse_ingest.py`, `test_silver_refresh.py` | 열린 PR 4개씩 |
| 목록 끝에 덧붙이는 줄(`]` 과 같은 줄) | `test_job_specs.py` | 열린 PR 5개 |

최근 레인 추가 커밋 10개는 같은 파일 13개를 전부 고쳤다. 그 가운데 레인이 아닌 PR 까지 묶는 것은 첫 줄이다.
`include_str!` 를 하나 더하는 PR 은 어느 영역이든 그 숫자 한 줄을 고치고 바로 아래에 이유 한 단락을 덧붙인다.
그런 PR 둘은 내용이 무관해도 반드시 충돌한다.

가드의 뜻은 숫자가 아니다. "빌드 시스템이 추론하지 못하는 데이터 의존이 값을 치르지 않고 늘지 않는다"이다.
늘린 사람이 보이는 편집을 하나 남기면 된다.

## Decision

1. **컴파일 시 읽기는 `tools/build-coupling/compile-time-reads.txt` 에 소스 파일마다 한 줄(`경로:횟수`)로 선언한다.**
   경로순으로 정렬되어 있고 `git grep -c` 의 출력 그대로다. 가드는 트리의 실제 값과 이 목록이 줄 단위로 같기를 요구한다.
   - 읽기를 더한 파일의 줄이 없거나 횟수가 다르면 실패한다(늘어남).
   - 읽기가 사라졌는데 줄이 남아 있으면 실패한다(줄어듦). 전과 같이 양쪽으로 막는다.
   - `bash scripts/guard/build-coupling-baseline.sh --write` 가 목록을 다시 쓴다. 이유는 커밋 메시지에 적는다.
2. **한 줄은 그 파일을 고치는 PR 만 고친다.** 새 파일의 줄은 경로순 자리에 들어가므로, 서로 다른 파일에 읽기를 더한
   두 PR 은 목록에서도 서로 다른 자리를 고친다(바로 이웃한 경로일 때만 겹친다).
3. **가드 파일에 쌓인 이유 주석(읽기 87건)은 지운다.** 이유는 각 커밋에 있다. 빌드 스크립트 기준(10)과 그 이유는
   남긴다. 그것은 지금까지 두 번 바뀌었다.
4. **자기 시험**이 목록의 실패 경로 다섯을 확인한다: 맞는 목록은 통과, 줄 없이 더한 읽기·목록에 없는 새 파일·
   읽기가 사라진 뒤 남은 줄·목록 자체가 없음은 거부. 실패가 막는 사고는 가드의 원래 것(값을 치르지 않고 느는
   빌드 결합)이고, 이 변경이 없애는 것은 위 표의 첫 줄, 곧 무관한 PR 8개가 한 줄에서 충돌하는 일이다.
5. **레인 목록의 숫자(`Lane::ALL` 의 길이, 시험의 레인 수)는 ADR-0551 의 계열 레인이 줄인다.** 건축HUB 대용량 파일은
   계약 항목 하나로 레인이 되어 `Lane::ALL` 과 시험의 숫자를 고치지 않는다(#1343). 이 ADR 은 그 파일들을 건드리지
   않는다. 같은 줄을 두 PR 이 고치면 그것이 또 하나의 충돌이 된다.

## 전/후

| | 전 (실측) | 후 |
|---|---|---|
| `include_str!` 를 더하는 PR 이 고치는 공용 줄 | 숫자 1줄 + 주석 덧붙임 (모든 PR 이 같은 자리) | 자기 파일의 줄 하나 (경로순 자리) |
| 지금 그 줄을 함께 고치는 열린 PR | 8개 — 어느 둘도 리베이스 없이 함께 병합될 수 없다 | 0개 (계산: 8개 가운데 같은 소스 파일을 고치는 쌍만 남는다) |
| 가드 파일 | 404줄(그중 이유 주석 약 300줄) | 136줄 + 목록 127줄 |
| 막는 것 | 늘어남·줄어듦 | 같음, 파일 단위로 더 좁게 |

## Consequences

- 지금 열린 8개 PR 은 이 변경이 병합된 뒤 한 번 리베이스해야 한다. 자기 `COMPILE_TIME_READ_BASELINE` 편집을 버리고
  `--write` 를 돌려 목록을 커밋하면 된다. 그 뒤로는 서로 기다리지 않는다.
- 이유를 한곳에서 읽던 주석 기록이 없어진다. `git log -- tools/build-coupling/compile-time-reads.txt` 가 그 자리다.
- 목록은 손으로 쓰지 않는다. `--write` 가 쓰고 가드가 대조한다. 읽기를 더한 사람은 여전히 diff 에 한 줄을 남긴다.
- 레인 PR 끼리는 `lane.rs` 와 시험의 숫자에서 계속 충돌한다. ADR-0551 이 병합되고 남은 손 레인이 계열로 옮겨갈
  때까지다.

## Rejected alternatives

- **숫자를 없애고 가드가 세기만**: 충돌은 사라지지만 "늘린 사람이 보이는 편집을 남긴다"도 사라진다.
- **`.gitattributes` 의 `merge=union`**: GitHub 의 머지 큐는 서버에서 병합하고 사용자 정의 병합 방식을 쓰지 않는다.
- **크레이트마다 숫자 하나**: 같은 크레이트를 고치는 PR 이 다시 한 줄에서 만난다. 레인 PR 이 바로 그 경우다.
