# ADR 0397: 철거멸실 신고는 제공자 키가 없어 행 글자 자체를 키로 Silver 에 쌓는다

- Status: Accepted
- Date: 2026-11-04
- Builds on: ADR-0355(연결 순서 5순위), ADR-0356·ADR-0357(같은 틀), ADR-0169, ADR-0318, ADR-0328, ADR-0288, ADR-0329

## Context

공장 매수인에게 "이 필지에 있던 공장이 언제 헐렸나" 는 두 가지 신호다. 땅이 비었다는 것과 그 전 쓰임이다. 그 원천이
건축인허가 철거멸실관리대장(`hubgokr__building_permit_demolition_loss`)이고, ADR-0355 가 지금 연결 5순위로 정했다.

**측정 (2026-11-04, 운영 장부의 최신 판 ZIP 을 R2 읽기 전용 키로 받아 끝까지 읽음).**

- 2026-10 판 ZIP 15,082,185 바이트, 멤버 `mart_kcy_07.txt` 79,051,004 바이트. **462,774 행, 모든 행 34칸.**
- **칸 0(관리허가대장PK)이 모든 행에서 빈칸이다.** 다른 HUB 레인의 키(`mgmt_key`)를 이 파일은 주지 않는다. 서로 다른 행은
  458,314 개이고, 같은 행이 최대 47번 되풀이된다.
- PNU 입력이 맞는 행은 99.91%(462,368)다. 철거멸실구분은 철거 175,500, 부분철거 17,209, 멸실 6,070 이다(표본 20만 행).
  주용도는 공장류(공장·일반공장·기타공장 등) 21,791 행, 창고시설 10,950 행이다.
- **필지 연결률(표본 2,000 행, 대응표 없는 단순 조합, `silver.parcel_boundaries`)은 78.3% 다.** 헐린 건물의 지번은 그 뒤 합병·분할로
  사라진 필지를 자주 가리킨다. 다섯 레인 중 가장 낮다. 소비자가 place-identity 해석기와 필지 계보(ADR-0113)로 지금 필지에 옮겨야 한다.
- **한 달 사이 변화는 0 이다.** 2026-09 판과 2026-10 판은 ZIP 바이트가 다르지만 행 묶음은 같다(한쪽에만 있는 행 0). 다섯 판의 ZIP 크기가
  모두 15,082,185 바이트다.
- 날짜 세 칸(13–15)과 면적·동수·층 칸은 뜻을 제공자 명세로 확인하지 못했다. 칸 13 ≤ 칸 14 인 행이 371,459, 반대가 2,561 이다.

### 실사례

- 키가 없는 이벤트 원장은 내용 해시를 키로 삼는다. Git 의 object id, Kafka 의 idempotent producer 가 쓰는 레코드 해시,
  Fivetran 이 기본 키 없는 표를 동기화할 때 쓰는 `_fivetran_id`(행 해시)가 같은 방식이다. 행이 바뀌면 새 키가 되고, 옛 키는
  사라진 행이 된다. append-only 원장과 그대로 맞는다.

## Decision

1. **표 `silver.building_permit_demolition_loss`.** 행 하나가 한 키다. `mgmt_key` 는 행 글자(칸을 `|` 로 이은 원문)의 SHA-256(소문자 16진수)이다.
   되풀이되는 같은 행은 한 키의 묶음으로 둔다(`keep_ties`, ADR-0328). compare 가 되풀이까지 센다(ADR-0318).
   이름 붙인 칸은 PNU 입력 5개, 철거멸실구분 코드·이름, 주용도 코드·이름, 구조 코드·이름이다. 값이 스스로 뜻을 말하는 칸만 이름을 붙였다.
   34칸 전부를 `raw_columns` 에 남긴다. 날짜·면적 칸은 이름 없이 둔다. 화면 PR 이 제공자 명세로 확인하고 이름을 붙인다.
2. **엔진은 키를 계약에서 받는다.** HUB 스트리밍 엔진의 레이아웃에 `row_key: "sha256_of_row"` 를 더한다. 이것이 있으면 `mgmt_key` 를
   칸에서 읽지 않고 행에서 만든다. 둘을 함께 쓰거나 둘 다 빠뜨린 레이아웃은 거부한다. 지금 있는 레인은 이 필드가 없으므로 그대로다.
3. **ADR-0356·0357 과 같은 틀이다.** 명령은 `export-building-permit-demolition-loss-silver-handoff`, 레인은 `building-permit-demolition-loss`,
   작업은 `silver_refresh_building_permit_demolition_loss` 다(`changed-keys`, 켜짐). compare 묶음은 하나다(`bucket_prefix_length` 0).
   전국 46만 행이라 나눌 이유가 없다. **run 당 상한은 판 하나다.** 갱신은 run 마다 가장 새 판 하나만 적재한다.
   크기는 기본개요(6.53M 행, 실측 6분)의 7% 라 단위 제한 150분 안에 넉넉히 든다.
4. **PNU 는 적재 때 한 번 정하고 멈추지 않는다.** Silver 의 `pnu` 는 다른 HUB 레인처럼 Rust 내보내기가 만든다(ADR-0145).
   필지에 붙이는 소비자는 place-identity 해석기로 옛 법정동 코드를 지금 코드로 옮긴다. 그 Gold 는 `views.changed_codes` 를 따라
   바뀐 코드 아래 PNU 만 다시 만든다(ADR-0288 §1, ADR-0329 §3). 사라진 필지는 필지 계보로 이어 받는다.
5. **소비자는 다음 PR 이다.** 그래프에서 표는 `contract_only`, 엣지는 `partial` 이다. 필지 패널에는 "철거·멸실 이력" 으로
   철거멸실구분과 철거된 건물의 주용도·구조를 제공자 낱말 그대로 보인다.

## Consequences

- **비용(계산).** 판당 ZIP 0.015 GB 다. 첫 실행은 46만 행으로, Parquet 수십 MB 다. 이후에는 바뀐 행만 더하는데, 실측으로는 0 이다.
  R2 저장은 월 1원 아래다.
- 실패가 막는 사고: 키 칸이 빈 원천을 `mgmt_key` 칸 그대로 읽으면 46만 행이 키 하나가 된다. 그러면 행 하나만 바뀌어도 전국을
  다시 쓴다. `a_layout_takes_its_key_from_a_column_or_from_the_row_not_both` 와 계약 시험이 지킨다.
- 다음: 월별 전기·가스(ADR-0355 4순위)는 판 하나가 사용 월 하나이고 지난 달을 다시 내기도 해서(2026-10 장부에 202605·202606 두 객체),
  판 고르기를 넓힌 뒤 잇는다(ADR-0396).
