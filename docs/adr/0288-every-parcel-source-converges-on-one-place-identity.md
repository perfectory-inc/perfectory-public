# ADR 0288: 모든 필지 원천은 하나의 place-identity 해석기로 수렴하고, 모든 개편 종류를 흡수하며, 조용히 실패하지 않는다

- Status: Accepted
- Date: 2026-10-20
- Builds on: [ADR-0103](./0103-place-identity-outlives-administrative-code-changes.md)(안정 ID·시간 사전·적재 입구 해석기·스튜어드),
  [ADR-0113](./0113-parcel-lineage-absorbs-reorganizations-and-gates-every-map-bake.md)(필지 계보가 개편을 흡수),
  [ADR-0143](./0143-legal-dong-code-changes-come-from-code-go-kr.md)·[ADR-0144](./0144-region-code-changes-are-derived-from-downloaded-data-only.md)·[ADR-0145](./0145-one-source-of-truth-for-region-code-changes.md)(지역코드 변경 정본),
  [ADR-0280](./0280-public-sale-court-auction-and-factory-registration-are-foundation-parcel-sources.md)(공매·경매·공장은 필지 원천)
- 관련: ADR-0043(정본 ID는 재계산 않고 읽는다), ADR-0286(표마다 행 버전 규칙), ADR-0287(공매 kind), ADR-0001(가드는 위협모형을 밝힌다)

## Context

ADR-0103 은 지리 정체성을 "변하는 행정코드"에서 떼어 **불변 안정 ID** 위에 세웠다 — 시간 사전
(`reference.legal_dong_code_*`), 안정 ID 레지스트리/다리/변경이력(`gold.place_id_registry`·
`place_id_bridge`·`place_id_changelog`), 그리고 **적재 입구의 유일한 해석기**(모든 소스 행의
`(external_code, data_vintage)` → 안정 ID). 선례는 Overture **GERS**(Registry/Bridge/Changelog)
와 **Who's on First**(`superseded_by`, 삭제 없이 대체). ADR-0113 은 이를 필지에 구현해 2026-07-01
전남광주·인천 개편을 **99.8% 코드만으로 자동 흡수**함을 실측했다.

그 핵심은 필지·건물·가격(허브 등록 코드 경로)에만 적용됐다. 2026-10 에 붙인 새 필지 원천
(공매·경매·공장, ADR-0280)은 정본을 거치지 않는다. 2026-10-20 **코드와 운영 데이터로 실측**한 결함:

1. **공매는 해석기를 아예 안 거친다.** `infra/lakehouse/spark/jobs/data_go_kr_onbid.py` 에 크로스워크·
   해석기·place_id 참조가 없다 — 원천(온비드)이 준 `ltnoPnu` 를 그대로 `pnu` 로 싣는다. 결과:
   온비드가 주소는 새 구("동탄구")로 갱신했으나 코드는 옛 화성시(**41590**)로 주는 **진행 중** 물건
   **57건**(진행 중 물건 1건의 여러 호실·여러 차수)이 현재 필지(동탄구 41597)에 **못 붙고 고아**가
   된다. 더해 폐지 시도(29·42·45·46)로 들어온 공매 **22건**은 현재 필지에도 없고 계보에도 없다.

2. **경매는 자기만의 해석기를 따로 쓴다.** `infra/lakehouse/spark/jobs/courtauction_go_kr.py` 가
   행정구역 이름으로 `address_pnu`(`pnu`, `pnu_basis`, `pnu_unresolved_reason`, `pnu_candidate_count`)
   를 자체 도출한다 — 정본 place-identity 를 거치지 않는 **두 번째 해석 경로**다.

3. **정본 자체가 "분구형" 개편을 흡수하지 못한다.** 화성시는 2026-02-01 에 만세구(41591)·효행구(41593)·
   병점구(41595)·동탄구(41597)로 **분구**됐다 — 시(41590)는 그대로 "존재"하고 구가 새로 생겼다.
   `reference.legal_dong_code_change` 에는 동 단위 변경(41590→4159x)이 있으나, `gold.place_id_bridge`
   에는 **옛 41590 이 0건**이고 41590↔41597 이 공유하는 place_id 가 **0건**이다. 원인: 크로스워크
   (ADR-0145)가 **"스냅숏에서 사라진 시군구"**를 말소로 보는데, 분구에서는 모(母) 시군구(41590)가
   사라지지 않고 하위 구만 생긴다 — 그래서 매칭쌍이 나오지 않는다.

4. **이 결함을 시스템이 신호하지 않았다.** 세 결함 모두 **사람이 조인 실패로 우연히** 발견했다 —
   해석률이 떨어지거나 고아가 생겨도 경보가 없었다. 신호가 없으면 다음 개편에서 **조용히 반복**된다.

즉 지금 **PNU/장소 해석이 세 갈래**(필지·건물=정본, 경매=자체, 공매=없음)로 갈려 ADR-0103 §3
"적재 입구 해석기가 유일한 코드 처리 지점"이 깨졌고(SSOT 위반), 정본조차 분구를 못 잡으며, 실패가
조용하다.

## Decision

ADR-0103 의 정체성 모델은 그대로 두고, **모든 필지 원천을 그 하나의 해석기로 수렴**시키고,
흡수하는 개편 종류를 **전수로** 넓히며, **실패를 시끄럽게** 만들고, **과거까지 전수 재해석**한다.
각 항은 시험 가능하게 적는다.

1. **모든 필지 원천은 적재 입구에서 정본 해석기 하나만 거친다.** 공매·경매·공장(및 앞으로의 모든
   필지 원천)의 Silver 적재는, 원천이 코드를 주든(공매) 주소 이름을 주든(경매), 정본 place-identity
   해석기로 `(external_code 또는 address, data_vintage)` → **안정 place_id + 현행 pnu** 를 받는다.
   원천 코드를 검증 없이 `pnu` 로 복사하거나 원천별 자체 해석기를 두는 것을 금지한다(ADR-0103 §3
   확장). **시험:** 공매/경매/공장 Silver 잡이 정본 해석기를 호출하고, 파이프라인 그래프를 읽는
   가드가 "필지 원천인데 해석기를 안 거치는 잡"을 거부한다(위반을 심어 거부 확인).

2. **경매의 자체 해석기를 정본으로 수렴해 없앤다.** 정본 해석기는 **코드 입력(공매)과 주소-이름 입력
   (경매)을 모두** 받는다. 경매의 `address_pnu` 자체 도출을 정본 호출로 바꾸고 삭제한다. **시험:** 같은
   주소에 대해 경매 경로와 정본 경로가 같은 `place_id`/`pnu` 를 내고, `courtauction_go_kr.py` 에 자체
   해석 상수가 남지 않는다.

3. **크로스워크/다리가 개편의 모든 종류를 흡수한다.** 흡수하는 변경 종류를 전수로 못 박는다:
   통합(merge)·분리(split)·개칭/재코딩(replaced_by)·**분구(모 시군구는 남고 하위 구가 신설되어
   하위 동코드가 바뀜)**·관할이전(jurisdiction_transfer)·등록전환(registration_conversion). 분구는
   시군구 스냅숏 차이(ADR-0145)로는 모 시군구가 안 사라져 매칭쌍이 안 나오므로, **동 단위
   `reference.legal_dong_code_change`(ADR-0143)에서 같은 (시군구명·동명)으로 옛 동코드 → 새 동코드를
   1:1 도출**해 안정 ID 다리에 적재한다. 어느 종류도 "정본이 못 잡는 변경"으로 남지 않으며, 모호
   (다:다·개명 불명)는 스튜어드에 남긴다(ADR-0103 §4). **시험:** 41590-장지동과 41597-장지동이
   다리에서 같은 place_id 를 공유하고(§Context 57건 해소), 각 변경 종류의 합성 사례가 올바른 안정
   ID로 흡수되며, 지원하지 않는 종류를 만나면 가드가 조용히 떨구지 않고 큐에 남긴다.

4. **해석마다 신뢰도 점수를 매기고, 못 맞춘 것은 버리지 않고 스튜어드 큐로 보낸다.** 각 해석은 신뢰도
   등급을 싣는다 — 정확 코드매치=최상, 승계사슬 1홉=높음, 분구·분할의 모호 후보나 이름 매칭=중간,
   미해결=없음. **중간 이하는 자동 적용하지 않고** provenance·미해결 사유·후보수와 함께 스튜어드
   큐로 보낸다(ADR-0287 §3 의 `lineage_missing` 를 이 큐로 통일). 폐지 코드이면서 승계 경로가 없는
   참조(§Context 22건형)는 고아로 떨구거나 죽은 코드에 붙이지 않는다. **시험:** 분할 모호 건은 낮은
   점수로 큐에 남고, 정확 매치는 높은 점수로 자동 적용되며, 승계 경로 없는 공매가 고아가 아니라 큐에
   보고된다.

5. **안정 `place_id` 가 모든 하위의 유일한 조인 열쇠다.** 경매·공매·공장·필지·건물·인텔리전스 플랫폼은
   가변 코드가 아니라 `place_id` 로 조인한다. 옛 주소/코드로 질의해도 다리를 타고 현재 필지와 전체
   이력(경매·공매·거래·용도·가격)이 하나로 모인다(ADR-0043). **시험:** 개편 경계를 가로지르는 raw pnu
   조인을 가드가 거부하고, 한 place_id 로 그 땅의 모든 원천이 조인된다.

6. **해석 건강을 능동으로 감시하고, 조용히 실패하지 않는다.** 매 적재마다 원천별 **해석률**(안정 ID로
   해석된 비율)·**고아수**·**스튜어드 큐 적체**를 지표로 낸다. 이전 실행 대비 해석률이 떨어지거나
   고아·큐가 임계 이상 늘면 **경보를 발생**시킨다. 이 결함(화성 분구·고아)은 시스템이 신호를 주지
   않아 사람이 조인 실패로 우연히 발견한 것이다 — **능동 경보가 막는 사고가 바로 "해석 결함이 신호
   없이 운영에 샌다"**이다(ADR-0001 위협모형). **시험:** 고아가 임계를 넘는 합성 적재에서 경보가
   발생하고, 임계 이하에선 발생하지 않는다(위반을 심어 거부 확인).

7. **완성된 해석기로 모든 과거 적재분을 한 번 전수 재해석한다.** 앞으로의 적재(§1)만이 아니라,
   지금까지 쌓인 모든 필지 원천의 옛 코드(§Context 57·22 건과 레거시 전부)를 완성된 정본 해석기로
   재해석해, 전환 시점 **이전·이후가 모두 현행 안정 ID에 수렴**하게 한다. append-only 이므로 원본은
   보존하고 재해석 결과를 새로 쌓는다(덮어쓰기 아님). **시험:** 전수 백필 뒤 고아는 0(원천이 주소·
   코드를 아예 비운 건만 남음)이고, 전환 경계를 걸친 과거 레코드가 전부 현재 필지로 조인된다.

## Consequences

- **SSOT 복구:** 세 갈래 해석을 정본 하나로 수렴한다. 경매 자체 해석기(쓰레기)가 사라지고, 공매는
   정본에 연결된다. 앞으로 어떤 필지 원천을 붙여도 해석은 한 곳이다.
- **전 종류·분구 흡수:** 화성형 개편이 다리에 들어와 57건이 현재 필지로 붙고, 모든 개편 종류가
   "정본이 못 잡는 것" 없이 흡수된다. 다음 개편은 엔지니어링 0.
- **조용히 실패 없음:** 해석률 하락·고아·큐 적체에 경보가 뜬다. 다음 결함은 사람이 우연히가 아니라
   시스템이 알려서 잡는다.
- **과거까지 완전:** 전수 백필로 레거시 고아가 0에 수렴한다.
- **인텔리전스:** 안정 ID 하나로 한 땅의 전 생애(경매·공매·거래·용도·가격·코드변화·분할합병)가 끊김
   없이 모여 AI 학습·추론의 정본이 된다. 이것이 이 ADR 의 궁극 목적이다.
- **비용·단계:** 코드만 바꾸고 운영 표 모양은 늘지 않는다(place_id 는 이미 존재). 단계로 나눈다 —
   (1) 정본 해석기를 두 입력(코드·주소)·공매 적재에 연결, (2) 모든 개편 종류 흡수(분구 동단위 도출·
   화성 백필 포함, §3), (3) 경매를 정본으로 수렴·자체 해석기 삭제, (4) 필지-원천-해석 가드·place_id
   조인 가드·신뢰도 등급(§4), (5) 능동 감시·경보(§6), (6) 전수 백필(§7)·미해결 스튜어드 큐 통일. 앞
   단계에 기대는 PR 은 draft 로 둔다.
- **선례 정합:** Overture GERS(안정 ID로 한 번 맞춰 영원히 조인), Who's on First(삭제 없이 승계),
   Kimball conformed dimension/SCD2(공유 차원·시점 유효), 엔티티 해상(적재 시 정본 키 부여 + 신뢰도)
   과 일치한다.

## Rejected

- **공매·경매에 각자 크로스워크를 붙이기:** 해석을 N벌로 늘려 SSOT 를 더 깬다. ADR-0103 §3 의 "한 곳".
- **옛 코드를 그대로 서빙하고 읽을 때 매번 매핑:** 소비자마다 다르게 풀어 드리프트가 생긴다. 정체성은
   적재 시 한 번 확정한다(resolve-on-write).
- **분구를 시군구 스냅숏 차이로만 잡기:** 모 시군구가 안 사라지므로 영원히 못 잡는다 — 동 단위 변경을
   근거로 삼아야 한다(§3).
- **미해결을 조용히 고아로 두고 요약에 숫자만 남기기:** 이번 사고가 그렇게 샜다. 경보와 스튜어드 큐로
   시끄럽게 만든다(§4·§6).
