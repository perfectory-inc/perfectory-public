# ADR 0077: 관은 매일 원천을 살핀다

- Status: Accepted
- Date: 2026-09-04

## Context

소유자 지시(2026-09-04): "매달이 아니라 **매일** 보고, 업데이트 된 것이 있으면 반영해야
한다. 우리 체크섬으로 하지 않나." 원천의 발행 주기(월별 스냅숏)와 우리의 확인 주기는 다른
것이다 — 발행일이 유동적이므로 매일 살펴야 도착 당일 안다.

지문 기계는 이미 있다. `ingest-building-hub-bulk-collection` 은 provider 파일 id 로
**받기 전에** 이미 가진 파일을 건너뛰고(`skipped_existing`), Bronze 커밋은 체크섬을
원장에 남긴다. 빠진 것은 감지가 아니라 **매일 돌리는 손과, 결과를 말하는 입**이다. 지금
관의 모든 방아쇠는 사람 손이고(로드맵 과제 4), 새 스냅숏이 와도 아무도 모른다 — 받을 곳
없는 수신자가 여섯 주를 버린 것과 같은 형태의 침묵이다.

## Decision

1. **매일 새벽 systemd 타이머가 원천 훑기를 돈다.** `foundation-source-sweep.{service,timer}`
   — 백업 타이머의 전례 그대로(같은 사용자·EnvironmentFile·강화 옵션), 03:40 + 지터.
   가변 산출물(plan·evidence·journal)은 릴리스 밖 `/var/lib/foundation-platform/source-sweep/`.
2. **범위는 지금 살아 있는 수직관의 원천부터.** hub.go.kr 건축물대장 벌크 레인 하나로
   시작하고, 레인 추가는 sweep 스크립트에 명령 한 줄이다 — 레인 목록을 다른 곳에 거울로
   적지 않는다.
3. **"아무 일도 없었음"도 기록된다.** 매 실행이 journal 에 한 줄(계획 N·신규 M·스킵 K)을
   남긴다. 신규 0 은 조용한 성공이지, 확인 부재와 구별 불가능한 침묵이 아니다.
4. **신규가 있으면 슬랙이 안다.** 신규 다운로드 M>0 이면 `#alerts` 로 파일 목록을 보낸다
   (알림 관의 봇 토큰 재사용). 실행 실패도 슬랙으로 외친다 — 매일 도는 것이 조용히 죽으면
   이 결정 전체가 거짓이 된다.
5. **이 결정은 "감지+획득"까지다.** 반영(Silver→내보내기→적재) 자동 실행은 다음 결정으로
   명명한다 — 확인 게이트와 Spark 자원을 무인으로 넘기는 것은 별도의 위험 판단이다. 그
   전까지 슬랙 알림이 "오늘 반영하라"는 신호이고, 반영 절차는 런북이 소유한다.

## Consequences

- 새 스냅숏 도착일 = 인지일이 된다. 지시의 "매일"이 충족되고, "반영"은 알림을 받은 손이
  런북으로 당일 수행한다(자동화는 후속 ADR).
- sweep 이 실행하는 퍼블리셔 바이너리는 배포 시 갱신되는 서버 빌드 사본이다. 배포와 사본
  갱신 사이의 어긋남은 수집 로직에 한해 무해하지만, 남은 부채로 적는다.
- 타이머 설치는 서버 1회 작업이며 런북이 소유한다. 설치 후 첫 실행이 성공해야 운영으로
  인정한다(백업 타이머의 규칙).
