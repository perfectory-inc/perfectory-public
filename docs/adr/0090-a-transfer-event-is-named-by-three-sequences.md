# ADR 0090: 토지이동 사건의 정체성은 세 순번이다

- Status: Accepted
- Date: 2026-09-07
- Supersedes: ADR-0089 의 사건 식별 조항 (PK (pnu, transfer_history_seq))

## Context

ADR-0089 의 첫 전국 투영이 설계대로 정직하게 거부했다: 제약 있는 스테이지가
`duplicate key value violates unique constraint` 로 멈췄다. 실물 1억 2,126만 행에서 측정한
사실 (2026-09-07, Trino r2.silver.land_transfer_history):

1. (pnu, 토지이동이력순번) 은 유일하지 않다 — 같은 이동이력순번에 **토지이력순번이 다른**
   별개 행이 있다 (예: 등록사항 회복이 08·09 두 행으로 옴).
2. 세 순번 (pnu, 이동이력순번, 토지이력순번) 으로도 11,767그룹이 겹치는데, 그중 대부분은
   **바이트까지 동일한 행**(제공자 원천의 중복 유입, 전체의 0.01%)이다.
3. 극소수(3개 시도 표본에서 4그룹)는 같은 세 순번에 자유문 사유의 표기만 다르다
   ("분할되어 본번에 -253을 부함" vs "-2, -3을 부함") — 같은 사건의 문구 흔들림이다.

## Decision

1. 사건의 서빙 정체성은 **(pnu, transfer_history_seq, parcel_history_seq)** 세 순번이다.
   `catalog.parcel_transfer_event` 는 `parcel_history_seq` 칼럼을 얻고 기본키를 세 순번으로
   바꾼다 (표는 아직 0행 — 첫 투영이 거부했으므로 데이터 이동 없음).
2. 병합은 거부 대신 **결정적 접기**다: 스테이지는 제약 없이 COPY 하고, 세 순번당 한 행을
   전체 칼럼 정렬로 결정적으로 골라 `ON CONFLICT DO NOTHING` 으로 넣는다. 접힌 행 수와
   "같은 키·다른 내용" 그룹 수를 로그로 남긴다 — 수십 건의 문구 변형 때문에 1억 행의
   전국 적재를 막는 것은 사실 보존이 아니라 가치 차단이다. 무엇이 접혔는지는 숫자로
   남고, 원문 전체는 Silver 에 그대로 있다 (레이크하우스가 정본, 서빙은 투영).
3. by-pnu 목록 정렬과 DTO 는 `parcel_history_seq` 를 함께 나른다.

## Consequences

- ADR-0089 의 "중복 키는 전체 거부" 조항은 이 문서로 대체된다. 거부가 틀렸던 게 아니라
  — 거부 덕에 가정이 실물과 다름을 배웠고, 이제 실측 위에서 결정한다.
- 접기는 결정적이므로 재실행이 같은 결과를 낸다.
- Silver 는 원문 전 행(중복 포함)을 계속 보존한다.
