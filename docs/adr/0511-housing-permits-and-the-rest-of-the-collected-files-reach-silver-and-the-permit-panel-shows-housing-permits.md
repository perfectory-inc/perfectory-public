ADR-0355 의 "Bronze 보관만" 은 공장·창고 매수인을 먼저 본 판정이었다. 그 뒤 사장 결정은 세 번이다:
2026-10-30 "나는 모든 데이터 수집을 승인할게", 2026-11-03 "비용은 상관없고, 데이터를 보여 주는 것이 항상 이긴다",
2026-11-11 "수집한 것은 모두 Silver → 서빙 → 화면, 중개사가 우선 사용자다". 중개사에게 아파트·다세대·주상복합의
사업계획승인·착공·사용검사는 매물 설명의 첫 줄이다. "주거 전용이라 미룬다" 는 이유가 남지 않았다.

**실측 — 주택인허가 기본개요(2026-10 판, R2 읽기 전용 키, 끝까지 읽음).** ZIP 7,627,051 바이트, 멤버
`mart_jty_01.txt` 56,425,710 바이트, 381,382 행, 모든 행 29칸, `|` 구분, UTF-8, 머리줄 없음. 칸 0(관리주택대장PK)은
모든 행이 채워졌고 381,382 개 모두 다르다. 날짜 칸 23–28 의 뜻은 data.go.kr 파일(15044697) 설명의 낱말(승인일·착공일·
사용검사일·생성일자)과 실측으로 맞췄다: 칸 28 은 모든 행에 있고 다른 날짜 칸보다 늦어 생성일자다. 칸 24·26 은 생성일자보다
늦은 날이 각각 38,418·67,457 행이라 **예정일**이고, 칸 23·25·27 은 12·152·14 행뿐이라 **실제 날**이다. 칸 23(99.8% 채움)
≤ 27 이 99.95%, 25 ≤ 27 이 99.6%, 24 ≤ 26 이 99.8% 다. 그래서 23 승인일, 24 착공예정일, 25 착공일, 26 사용검사예정일,
27 사용검사일이다.

### 실사례

- **모든 원천을 정제층까지.** Databricks·Snowflake 의 medallion 구조는 Bronze 를 원본 보관층으로 두고, 쓰는 원천은 모두
  Silver 로 정제해 소비자가 원본 형식을 몰라도 되게 한다. 원본만 쌓아 두는 것은 "보관" 결정이 있을 때뿐이다.
- **같은 엔진, 선언만 더한다.** Airbyte·Fivetran 의 스트림처럼 레인은 계약(칸·키·커서)만 선언한다(ADR-0402 와 같음).

## Decision

1. **주택인허가 16 을 지금 연결한다.** 판정을 "Bronze 보관만" 에서 "지금 연결" 로 올린다. 규칙은 ADR-0402 §2–§6 그대로다:
   새 엔진은 없고(`hub_register_silver_export`, Silver 갱신 ADR-0169, 키 비교 ADR-0318), 레인 하나에 draft PR 하나,
   칸 배치는 최신 판 ZIP 전체 실측, 키는 제공자 키가 행을 가르면 그 칸 아니면 `sha256_of_row`, PNU 는 엔진이 짓고 코드
   변경은 소비자가 `views.changed_codes` 로 따라간다. 순서는 기본개요(날짜) → 대지위치 → 동별개요 → 나머지다.
2. **주택인허가는 건축인허가와 같은 필지 패널에 선다.** 새 by-PNU 레인을 만들지 않는다. 건축인허가 레인
   (`gold.parcel_building_permits` → `parcels/building-permits/by-pnu`)의 문서에 주택인허가 기본개요를 따로 묶어 싣고
   (승인일·착공예정일·착공일·사용검사예정일·사용검사일·용도·총세대수·연면적, 제공자 낱말 그대로), 화면 섹션은
   "인허가 이력" 하나다. 부분 처리는 그 레인의 규칙(바뀐 PNU 와 `views.changed_codes` 가 닿는 PNU 만 다시 계산)을 따른다.
3. **건축인허가 나머지 7 도 같은 규칙으로 연결한다.** 순서는 호별개요·전유공용면적 → 지역지구구역·주택유형 → 나머지다.
4. **VWorld 10 도 Silver 로 간다.** 공인중개사(중개사무소 등록)를 먼저 한다(우선 사용자의 명부). 경계·산단 9 은 그다음이다.
   PNU 칸이 없는 표(경계·산단 위치·유치업종)는 자기 코드(시도·시군구·단지)가 키이고 PNU 연결을 주장하지 않는다.
5. **폐쇄(말소)대장 10 은 Bronze 보관만 그대로다(제품 결정).** 사라진 건물의 대장이고, 사라진 사실 자체는 철거멸실 레인
   (ADR-0397, 화면 "멸실")이 이미 보여 준다. 원본은 append-only 로 계속 쌓는다. 건물 수명(옛 건물→새 건물) 화면을 만들 때
   다시 판정한다. 이 결정은 파이프라인 그래프의 건축HUB 원천 노드 설명에 적는다.
6. **Silver 에서 멈춘 7 개의 이유.** 법원경매 3 은 Gold·bake 작업이 꺼져 있다(W18h 몫). 인구·세대수 2 는 행정동→법정동
   연계 표(`silver.adm_dong_code_linkage`)가 0 행이라 필지에 놓을 수 없다(data.go.kr 파일 run 고장, W59 #1230 몫);
   연계가 서면 법정동 단위 통계로 필지 문서에 싣는다. 법정동 스냅숏 1 과 필지번호 변동연혁 1 은 모든 레인의 키 해석과
   계보 입력이라 자기 패널이 없다(법정동 이름은 필지 문서의 `legal_dong` 으로 이미 보인다).

## Consequences

- **비용(계산).** 주택인허가 16 은 이미 받고 있다(ADR-0355 표: 다섯 판 합 약 1.0 GB, 최신 판 약 0.2 GB). Silver 는 최신
  판 하나의 Parquet(수십 MB)부터 쌓고 이후는 바뀐 키만 쌓는다. R2 $0.015/GB·월, 1,450원/$ 로 월 10원 아래다. 계산은
  ai-server Spark 풀에서 돌아 추가 지출이 없다. 건축인허가 7·VWorld 10 도 같은 규모다.
- 레인마다 같은 파일(`lane.rs`, 작업 정의, 그래프)을 건드린다. 먼저 병합되는 쪽 뒤의 PR 은 rebase 한다.
- 남는 "Bronze 보관만" 은 폐쇄대장 10·점검기관 1(필지와 무관한 명부)과 대장 오수정화시설·지역지구구역 2(ADR-0355)뿐이다.
