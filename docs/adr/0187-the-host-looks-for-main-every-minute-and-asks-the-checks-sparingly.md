# ADR 0187: 서버는 main 을 1분마다 보고, 검사 결과는 아껴서 묻는다

- Status: Accepted
- Date: 2026-10-12
- Amends: [ADR-0159](./0159-the-host-deploys-main-by-itself-once-its-checks-pass.md) §2(10분마다)

## Context

ADR-0159 의 서버는 10분마다 main 의 머리를 본다. 병합에서 배포 시작까지 평균 5분, 최악 10분을 그냥 기다린다.
2026-10-12 에는 병합 1초 전에 틱이 지나가 운영 수정 하나가 10분을 기다렸다.

사내망 서버라 GitHub 이 서버에 알릴 길(들어오는 연결)은 두지 않는다(ADR-0159 의 pull 방식). 그러니 더 자주 보는
것이 길이다. 비용은 둘이다.

- main 의 머리는 `git ls-remote`(git 전송)로 읽는다. REST API 한도와 무관하고 응답이 작다.
- 검사 결과(`release_checks.py`)는 REST API 를 익명으로 읽는다. GitHub 은 익명 클라이언트에 시간당 60회를 주고,
  한 번 묻는 데 최소 2회(check run, 머지 큐 실행)가 든다. 1분마다 물으면 판정이 나지 않은 커밋 하나로 한도를 넘는다.

## Decision

1. `foundation-autodeploy.timer` 는 1분마다(`OnUnitInactiveSec=1min`) 돈다. 간격의 정본은 그 타이머 파일이고,
   문서는 숫자를 베끼지 않고 그 파일을 가리킨다.
2. 새 머리는 바로 묻는다. 판정이 아직 없으면(진행 중이거나 읽지 못함) 같은 커밋은 `recheck_seconds`(5분)가 지난
   뒤에만 다시 묻는다(`state/asked/<sha>` 의 시각).
3. 통과 판정은 그 커밋에 대해 저장한다(`state/passed/<sha>`). 운영자 유닛이나 Worker 배포를 기다리는 동안 다시 묻지
   않고, 그것이 끝난 다음 틱에 바로 배포한다.
4. 시험이 성질을 지킨다. 판정 없는 커밋은 간격 안에 다시 묻지 않고, 새 머리는 바로 묻고, 통과는 다시 묻지 않으며,
   타이머 간격·재질문 간격이 익명 한도의 절반 안에 든다.

## Consequences

- 병합에서 배포 시작까지 최악 10분이 최악 약 1분이 된다.
- 판정 없는 커밋 하나가 쓰는 API 는 시간당 최대 24회(5분마다 2회)로, 익명 한도 60회의 절반 안이다.
- 서버가 이미 main 이면 틱은 `ls-remote` 한 번과 Worker 배포 유닛 시작뿐이다(ADR-0175: 바뀐 Worker 가 없으면
  아무것도 하지 않는다).
- 비공개 전환 때 읽기 토큰을 쓰면 한도는 시간당 5,000회로 오르지만 이 간격 규칙은 그대로 둔다.
