# ADR 0162: 거부된 속도 관문은 측정 파일에 묶인 결정으로만 연다

- Status: Accepted
- Date: 2026-10-08
- Builds on: [ADR-0147](./0147-by-pnu-documents-are-served-from-section-packs.md) §6(관문 가·나),
  [ADR-0154](./0154-building-pack-read-path-is-placed-beside-the-bucket.md)(읽기 경로 측정)

## Context

필지 documents/g1 묶음이 2026-10-08 관문 (가)를 통과했다. 39,861,511 PNU 전부가 객체 문서와 같았다. 관문 (나)는
불합격이었다(미리보기 Worker, 표본 1만, 양쪽 모두 R2 에서 처음 읽기).

| 항목 | 객체 | 묶음 | 기준 |
|---|---|---|---|
| 처음 읽기 p50 | 502 ms | 716 ms (+214) | +50 |
| 처음 읽기 p95 | 1,173 ms | 1,379 ms (+206) | +50 |
| 두 번째부터 p50 | 519 ms | 405 ms (−114) | |
| Worker CPU p99 | | 10.9 ms | 10 |
| 내용 불일치 | | 0 | 0 |

- 원인: 필지 묶음은 크다(중앙값 1.67 MB, 256 KiB 이하 3%). 그래서 처음 읽기마다 목차와 본문을 따로 읽는
  R2 왕복 두 번이 든다. 건물 묶음은 중앙값 111 KB 이고 81%가 한 번에 읽힌다.
- 사장 결정(2026-10-08, 출시 전): 이대로 발행하고, 큰 묶음 쪼개기는 나중에 한다.
- 발행기는 관문 (나)가 거부한 증거로는 발행하지 않는다. 결정을 기록할 길이 없었다. 기준을 낮춰 다시 재면
  기준의 뜻이 바뀌고, 발행기 검사를 건너뛰면 무엇을 받아들였는지 남지 않는다.

## Decision

1. **면제는 계약에 적는다.** `by_pnu_section_packs.cutover_gate.latency_waivers` 의 항목 하나가 결정 하나다.
   항목은 레인, 세대, 측정 파일의 sha256, 결정일, 이유를 갖는다. PR 로만 들어간다.
2. **면제는 그 측정 파일 하나에만 적용된다.** 발행기는 관문 (나)의 판정이 거부일 때, 증거 파일 바이트의
   sha256 이 면제 항목과 같고 레인·세대도 같을 때만 받아들인다. 같은 세대를 다시 재면 다시 판정한다.
3. **면제는 속도와 CPU 만 받아들인다.** 레인, 세대, 표본(관문 가와 같은 표본), 운영 환경 측정이라는 조건은
   그대로다. 탐침이 비교한 답 가운데 하나라도 내용이 다르면 면제가 있어도 거부한다.
4. **발행 기록에 남긴다.** manifest 의 전환 기록(`cutover`)에 면제 사유가 들어가고, 발행 로그에 경고로 남는다.
5. **운영 스크립트는 관문 (나)를 판정하지 않는다.** ADR-0161 의 `by-pnu-pack-operator.sh publish` 는 관문 (가)
   통과와 관문 (나) 증거가 있는지만 확인한다. 관문 (나)의 판정은 면제를 아는 발행기가 한다(ADR-0161 결정 4 의
   "두 관문 모두 passed" 를 이것으로 바꾼다).
6. 첫 항목: 필지 g1, 위 측정(sha256 `64482ef5…427c`), 사유는 위 표와 원인.

## Consequences

- 필지 묶음을 발행할 수 있다. 처음 읽기는 객체보다 약 0.2초 느리고, 다시 읽기는 약 0.1초 빠르다.
- 큰 묶음 쪼개기(256 KiB 상한, PNU 범위)가 이 면제를 없앨 일이다. 그 뒤의 새 세대는 면제 없이 관문을 통과해야
  한다.
- 시험(`section_packs/tests.rs`)은 다음을 확인한다. 계약의 면제는 그 sha256 의 거부된 증거만 연다. 다른
  sha256, 다른 표본, 내용 불일치는 면제가 있어도 거부된다.
