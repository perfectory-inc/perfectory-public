# ADR 0135: 첫 판 동등성 검사는 옛 오븐이 지운 것을 가려 세고, 설명 못 하는 차이만 막는다

- Status: Accepted
- Date: 2026-10-03
- Amends: [ADR-0133](./0133-parcel-tiles-are-rebaked-nationally-from-the-lakehouse.md) §4 (나)

## Context

ADR-0133 §4는 새 오븐의 첫 판을 승격하기 전에 표본 타일을 운영판과 비교한다. (나)는 "새 판에만 있는 id는
모두 타일 경계 밖"을 요구했다. 근거는 서울 타일 15장 측정이었다.

PR #315 구현으로 범위를 넓혀 다시 쟀다. 운영 필지판과 서울 시험판을 z14–16 표본 171장(운영 id 478,205개)으로
비교했다.

| 분류 | 건수 |
|---|---:|
| 운영 id 누락 | 0 |
| 속성 변경 | 0 |
| 값 형태만 변경 | 0 |
| 새 판에만 있는 id 중 타일 **밖**(버퍼) | 26,735 |
| 새 판에만 있는 id 중 타일 **안** — 작음(가로·세로 32단위 이하) | 812 (z14 751, z15 58, z16 3) |
| 새 판에만 있는 id 중 타일 **안** — 운영판에 아예 없음 | 0 |
| 새 판에만 있는 id 중 타일 **안** — 설명 안 됨 | 11 (z14 7, z15 4) |

설명 안 된 11건은 모두 가늘고 긴 조각 필지다. 길이는 30–60단위이고 넓이는 4–42제곱단위다(타일 한 변 4096단위,
한 화소는 16단위).

옛 오븐(PostGIS `ST_AsMVTGeom` → martin-cp)은 낮은 줌에서 화소보다 작은 도형을 지우고, tippecanoe는
`--no-tiny-polygon-reduction`으로 남긴다. 그래서 (나)를 그대로 두면 데이터가 같아도 첫 전국판이 거부된다.

## Decision

1. **(가)와 (다)는 그대로 엄격하다.**
   - 운영판 타일의 id는 새 판의 같은 타일에 모두 있어야 한다.
   - 공유 id의 속성 값(글자로 비교)은 같아야 한다.
   - 하나라도 어기면 거부한다.
2. **(나)를 넷으로 나눈다.** 새 판에만 있고 타일 안에 있는 id는 다음 순서로 분류한다.
   1. **버퍼**: 도형이 타일 경계 밖이다. 허용하고, 센다.
   2. **작음**: 그 타일 안 도형 넓이가 **64제곱단위 이하**다(화소 4분의 1). 길이가 아니라 넓이로 판정한다. 길이로는
      가는 조각을 놓친다. 허용하고, 센다. 옛 오븐이 지운 도형이다.
   3. **추가**: 그 필지를 담은 maxzoom 타일에 운영판의 같은 id가 없다. 즉 운영판에 그 필지가 아예 없다.
      - 허용하되, 표본 운영 id 대비 **0.1% 이하**여야 한다. 넘으면 거부한다.
      - 이것은 운영판을 만든 원천과 새 Silver 판이 다를 때 생긴다. 차이가 크면 사람이 확인해야 한다.
   4. **설명 안 됨**: 위 셋에 들지 않는 것. **0건이어야 한다.** 한 건이라도 있으면 거부한다.
3. **모든 분류의 건수를 남긴다.** 줌별·지역별 건수와 예시 id(분류마다 최대 20개)를 build 증거에 남긴다. 승격이
   허용돼도 남긴다. 64제곱단위와 0.1%는 계약 파일 `config/tile-equivalence.contract.json`이 정본이다.
4. **첫 전국판에서 다시 잰다.** 첫 전국 굽기의 분류 건수를 런북에 기록한다. 그 숫자가 위 기준과 크게 다르면 이 ADR을
   다시 연다.

## Consequences

- 서울 측정으로는 설명 안 됨이 0건이 되어 승격 가능하다(넓이 기준이면 11건이 작음으로 분류된다).
- 데이터가 바뀐 필지(추가)는 막지 않되 상한과 목록으로 드러난다. 운영판에서 사라지는 필지는 여전히 한 건도 허용하지
  않는다.
- 작은 필지는 화면에서 화소 이하라 보이는 결과는 같다.
