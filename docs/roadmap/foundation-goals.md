# 기반 목표

[운영 준비 작업 목록](./production-readiness.md)은 **"출시 전에 무엇을 해야 하는가"**를 소유한다.
이 문서는 **"무엇이 참이어야 하고, 무엇이 그것을 계속 재는가"**를 소유한다. 작업 항목을 여기에
복사하지 않는다 — 두 문서가 같은 목록을 들면 둘 중 하나는 반드시 낡는다.

각 목표는 **불변식 하나 + 지표 하나 + 재측정 명령 하나**로만 적는다. 재측정 명령이 없는 목표는
이 문서에 적지 않는다. **현재 수치는 이 문서에 적지 않는다** — 생성기 출력이 소유한다(G0).

## 진단

한 문장으로: **기록이 실물보다 빨리 늘어나고, 둘을 잇는 측정이 없다.** 스키마·ADR·주석이
시스템을 앞서 서술하는 것 자체는 문제가 아니다. 앞선 거리를 재는 것이 없어서 그 거리가 조용히
벌어지는 것이 문제다. 아래 목표는 전부 그 거리를 재고 좁히는 것이다.

2026-08 첫 실측에서 같은 형태가 세 번 나왔다: 생산자 없는 canonical 표, 실물과 다른 부채 서술,
아무것도 보지 않고 통과하던 검사. 그날의 개별 수치는 이 문서에서 지웠다 — 손으로 적은 수는 이
문서가 금지하는 바로 그것이고, 실제로 전부 낡았다.

## G0 — 모든 지표는 스스로를 잰다

**불변식.** 이 문서의 모든 수치는 명령으로 재생산된다. 손으로 적은 수는 없다.

**지표.** 정적으로 재생산되는 지표 = **6 / 6** — 2026-08-06 달성
(canonical 표 총수, 생산자 없는 표, 상태 CHECK 수, 쓰는 경로 없는 값, ADR 수, 부채 항목 수)

**재측정.** `python3 scripts/catalog/render-foundation-baseline.py` — 출력이 지표이며 저장소에
사본을 두지 않는다([ADR-0176](../adr/0176-generated-docs-do-not-make-unrelated-prs-conflict.md);
ADR 수 줄이 모든 ADR PR을 서로 충돌시켰다). `main`의 `docs` 워크플로 요약에도 실린다.

**여섯 개뿐인 이유를 명시해 둔다.** 나머지 수치는 성격이 달라 생성기가 소유할 수 없다.
가드 통과 수와 레인 실행 테스트 수는 **돌려야 나오는 수**이므로 실행 로그가 소유한다.
부채의 열림/닫힘은 판정이므로 사람이 소유한다([운영 준비 작업 목록](./production-readiness.md)의
"ADR이 기록한 남은 부채"). 생성할 수 없는 수를 생성한다고 적으면 이 문서가 금지하려는 것을
스스로 하게 된다.

**이 목표가 먼저인 이유**는 나머지 목표가 전부 "수가 줄었는가"로 판정되기 때문이고, 손으로
관리되는 수는 이 저장소에서 이미 여러 번 낡았다 — 부채표, ADR 색인, 로드맵의 열림 개수, 그리고
이 문서 자신의 수치.

## G1 — 스키마는 코드보다 앞서지 않는다

**불변식.** canonical 표는 생산자를 가지거나, 생산자가 없다는 사실이 선언되어 있다.

**지표.** 생산자 없는 canonical 표 수 → 0 (현재 값과 표 목록은 G0 생성기 출력의 "G1" 절)

**재측정.** 마이그레이션의 `CREATE TABLE catalog.*`와, 테스트·시드를 뺀 `INSERT INTO` 대조
(G0 생성기가 수행)

형태만 있고 생산자가 없는 표는 두 가지 결과를 낳는다. 첫째, 그 표를 전제한 제약·상태·ADR이 지킬
코드 없이 기록된다. 둘째, 부채 목록이 낡는다. 지킬 코드가 없으면 닫혔는지 열렸는지를 판정할 대상
자체가 없기 때문이다.

닫는 방법은 셋이다. **생산자를 만들거나, 표를 지우거나, 표를 미래 계약으로 명시 선언하고 선언을
검사가 센다.** 이것은 스키마 진화의 expand/contract(parallel change) 규율에서 contract 단계에
해당한다. 표를 지운 선례는 root [ADR-0194](../adr/0194-retire-the-five-postgres-copies-that-r2-already-holds.md)다 —
R2가 이미 가진 데이터의 Postgres 사본 다섯을 생산자를 만드는 대신 은퇴시켰다.

**배운 것: 격차는 하나가 아니라 줄이었다.** `catalog.parcel` 한 줄을 지우는 데 스키마(root
[ADR-0070](../adr/0070-the-boundary-source-carries-neither-use-nor-area.md)), 배포가 남긴 스키마(root
[ADR-0071](../adr/0071-a-deploy-that-leaves-the-schema-behind-has-not-finished.md)), 부트스트랩 권한이
차례로 필요했고, 그중 셋은 이 목록이 이름하지 않는 것이었다. **"막혀 있다"의 이유를 데이터로
적어 두면, 데이터가 도착한 날에도 목록은 막힌 채로 남는다.**

## G2 — 수직 슬라이스 하나가 CI 안에서 끝까지 지난다

**불변식.** 원천 → bronze → canonical → 발행 → 타일 → API 응답을 CI가 한 번에 통과시키는
경로가 최소 하나 있다.

**지표.** CI가 끝까지 덮는 수직 경로 — 동적(PostGIS → Martin MVT) 경로 2026-08-06 달성,
정적(PMTiles) 경로도 같은 증명에 들어 있다

**재측정.** `.github/workflows/foundation-ci.yml`의 `required/foundation` `needs`에
`boundary-slice`가 있는지. 그 잡은 `scripts/tiles/boundary-slice-proof.sh`를 돌린다 — 다이제스트
고정 이미지로 자기 Postgres와 Martin을 띄우고 자격증명을 쓰지 않으며, `complex` 단위는
PostGIS → MBTiles → PMTiles → Martin 디코드까지 정적 경로를 이어서 증명한다(R2에는 쓰지 않는다).
머지 큐에서만 도는 이유는 root
[ADR-0199](../adr/0199-verify-runs-side-suites-beside-cargo-and-pull-requests-leave-the-boundary-slice-to-the-merge-queue.md)가 소유한다.

가운데가 비어 있다는 진단은 **수직 슬라이스 하나로만 반증되거나 확증된다** — 단계별 테스트를
아무리 늘려도 단계 사이가 이어져 있다는 것은 증명하지 못한다.

**배운 것.** 로드맵은 이 증명이 Docker Compose를 필요로 한다고 적었지만 스크립트에 compose
참조는 없었고, 남은 일은 **아무도 부르지 않는다**는 것뿐이어서 잡 하나로 끝났다. 장애물 서술을
실물과 대조하지 않으면 한 줄짜리 일이 큰 일로 남는다.

## G3 — 두 곳에 적힌 규칙은 대조되거나 하나가 된다

**불변식.** 같은 규칙이 두 언어·두 시스템에 적혀 있으면, 둘을 대조하는 검사가 있다.

**지표.** "같다"고 주장하지만 대조 없는 지점 = **측정 필요** → 0

**재측정.** 도메인 enum ↔ CHECK 결속 표(ADR-0018)와, 아직 결속되지 않은 어휘 목록

[ADR-0018](../adr/0018-a-vocabulary-written-in-two-languages-is-compared.md)이 catalog의 세
어휘에 이것을 적용했다. 착수 근거는 추측이 아니었다 — 같은 주장이 붙어 있던 네 번째 자리가
실제로 **세 방향으로 어긋나** 있었다. 남은 범위는 그 ADR이 소유한다.

이 목표에는 조건이 하나 더 붙는다. **검사는 거부가 증명되어야 한다.** 통과만 확인한 검사는
첫 실측 하루에 세 번 배신했다. 검사를 추가하는 변경은 위반을 심어 실패까지 확인한 기록을
함께 가져온다(`scripts/guard/` 의 가드 옆에 `*-self-test.sh` 가 있는 이유).

## G4 — 스키마는 도달할 수 없는 상태를 약속하지 않는다

**불변식.** CHECK가 허용하는 상태값은 쓰는 경로를 가지거나, 그것이 없다는 사실이 결정으로
기록되어 있다.

**지표.** 쓰는 경로가 없는 상태값 수 → 0 (현재 값과 목록은 G0 생성기 출력의 "G4" 절)

**재측정.** `python3 scripts/catalog/render-foundation-baseline.py`

G1의 특수한 경우이며 별도로 세는 이유는 판정 방법이 다르기 때문이다. 각 값은 "구현이 온다" 또는
"지운다" 중 하나로 결정되어야 하고, 어느 쪽도 아닌 채로 남아 있는 것이 지금 상태다.

**이 수는 "운영 writer가 있는가"가 아니라 "테스트 밖 어디서든 쓰는가"를 센다.** 마이그레이션
백필이 쓰는 값도 지표상 도달 가능이다. 같은 상태값이 단위별로 다른 운영 경로를 갖는 사례
(`spatial_projection_load.failed`)는
[ADR-0016](../adr/0016-a-postgis-projection-load-is-a-fact-with-an-identity.md)이 소유한다. 지표는
기계가 판정할 수 있는 것만 세고, 판정이 필요한 것은 ADR이 소유한다.

## G5 — 안 도는 테스트를 0으로 만든다

**불변식.** 저장소에 있는 모든 테스트는 어떤 레인에서든 돈다.

**지표.** 어느 레인에서도 실행되지 않는 테스트 = **측정 필요** → 0

**재측정.** [ADR-0011](../adr/0011-test-execution-set-completeness.md)의 실행 집합 수집기
(`scripts/guard/live-lane-completeness.sh`)

레인별 실행 수는 돌려야 나오는 수라 실행 로그가 소유한다. 전체가 0인지는 아직 재지 않았으므로
**재지 않은 수를 목표에 적지 않기 위해 "측정 필요"로 남긴다.**

**배운 것.** 자격증명 레인을 처음 돌렸을 때 "자격증명이 막고 있다"는 서술은 셋 다 부정확했다 —
없던 것은 비밀값이 아니라 켜기 스위치였고, `data-go-kr` 레인이 치는 엔드포인트는
`public-source-endpoint-catalog.v1.json`에서 `disabled_api_duplicate`라 켤 대상이 아니었다.
이 목표는 저장소 밖 결정에 걸려 있지 않다.

## G6 — 운영 사실이 기록된다

**불변식.** 시스템이 한 일과 하지 못한 일은 원장에 남는다.

**지표.** 보존 기간 없는 무한 증가 표 = **측정 필요** → 0

**재측정.** 증가 경로가 있는 표 중 삭제/보존 정책이 선언된 비율

알려진 사례는 발행마다 geometry 한 벌이 쌓이는 publication 두 표다(ADR-0016 남은 부채 1).
백업·복구 리허설과 RPO/RTO 증거는 [운영 준비 작업 목록](./production-readiness.md) 우선순위 0이
소유한다.

## 건물 관이 남긴 과제 — 닫힘

root ADR-0073·0074·0075 가 정한 `catalog.building`·`catalog.building_unit` 투영과 호 → 건물 연결은
root [ADR-0194](../adr/0194-retire-the-five-postgres-copies-that-r2-already-holds.md)가 지웠다(세 ADR 모두 그것으로 대체).
건물 정보는 `silver.building_register_titles` 와 by-PNU 건물 레인이 소유한다. 이 절의 옛 과제(orphan 동 분포, `built_year`
보강, 수동 방아쇠)는 그 투영과 함께 사라졌고, 방아쇠는 `platforms/foundation-platform/orchestration/jobs.v1.json` 이 소유한다.

## 순서와 의존

```
G0 (측정)  ──┬─→ G1 (생산자)
             ├─→ G2 (수직 슬라이스)
             ├─→ G3 (대조)
             ├─→ G4 (도달 가능성)
             ├─→ G5 (레인)
             └─→ G6 (원장)
```

G0이 먼저인 이유는 나머지가 전부 "수가 줄었는가"로 판정되기 때문이다. G2는 G1을 기다리지
않는다 — 행정경계·산업단지 경계에 생산자가 있으므로 가운데가 이어지는지를 가장 빨리 답한다.
어느 목표도 저장소 밖 결정에 걸려 있지 않다.

## 이 문서를 닫는 조건

일곱 목표의 지표가 전부 생성기나 검사에서 나오고(G0), G1·G4가 0이 되면 이 문서는 목표를 잃는다.
그때 `production-readiness.md`만 남기고 이 문서는 ADR로 접는다.
