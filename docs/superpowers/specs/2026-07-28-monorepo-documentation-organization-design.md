# perfectory 문서 운영·한글화 설계

## 목표와 범위

모노레포의 사람이 읽는 문서를 한글 정본으로 통일하고, 문서의 책임·상태·기록·검색
경로를 하나의 운영 규칙으로 묶는다. 나중에 다국어를 추가하더라도 한국어 정본과
번역본의 관계가 깨지지 않도록 언어를 경로와 메타데이터로 분리한다.

이번 범위는 추적된 Markdown 문서 전체다. 코드, 명령어, API 필드, 패키지명, 파일명,
외부 라이선스 전문처럼 기계·법률 계약인 값은 번역 대상이 아니다. 설명 문장은 한글로
작성하고, 외부 원문에는 한글 안내를 붙인다.

## 결정

README는 각 코드 디렉터리의 짧은 지도이고, 깊은 설명은 `docs/`의 정본 문서가 소유한다.
루트 README는 모노레포 전체 책임 트리를, 각 플랫폼 README는 해당 플랫폼의 코드 트리와
운영 진입점을, 독립적으로 빌드·배포되는 서비스 README는 서비스 계약과 실행 방법을 제공한다.

README는 해당 디렉터리를 처음 방문한 사람이 다음 행동을 결정하는 데 필요한 내용만
담는다. 동일한 설계·운영 절차·기술 버전 표를 README에 복사하지 않고 정본 링크로
연결한다.

## 문서 계층

```text
README.md                         전체 프로젝트 진입점
docs/README.md                    전역 문서 지도
docs/document-catalog.md          자동 생성 전체 문서 색인
platforms/<area>/README.md        영역 코드·책임 지도
platforms/<area>/docs/README.md   영역 문서 지도
services/*/README.md              독립 실행 서비스 경계
crates/*/README.md                외부 계약 또는 독립 사용 패키지에 한해 제공
```

## 문서 분류

- `adr/`: 되돌리기 어려운 설계 결정
- `architecture/`: 현재 구조와 경계
- `catalog/`·`reference/`: 조회용 정본·레지스트리
- `contracts/`·`openapi/`·`schemas/`: 기계가 소비하는 계약
- `runbooks/`: 실행·장애·복구 절차
- `guides/`: 개발·기여 절차
- `records/`: 조사·실행 결과·사고·릴리스 같은 시간순 사실 기록
- `examples/` 또는 `*.example.*`: 코드·테스트가 실제 참조하는 fixture만 유지

ADR은 왜 결정했는지를 기록하고, architecture는 현재 무엇이 존재하는지를 설명하며,
guide/runbook은 어떻게 행동하는지를 설명한다. records는 이 셋을 대신하지 않으며
결정이나 현재 상태의 정본으로 사용하지 않는다.

## 언어와 다국어 확장

- 사람이 읽는 설명 문서의 정본 언어는 `ko-KR`이다.
- 영어 문서를 별도로 복제해 두지 않는다. 번역이 필요해지는 시점에만
  `docs/i18n/<locale>/` 아래에 정본 경로와 일대일 대응하는 번역본을 추가한다.
- 한국어 정본은 계속 유지하고, 번역본에는 `source`와 `source_revision` 메타데이터를
  기록한다.
- 명령어, 코드 블록, API·이벤트 필드, 데이터베이스 컬럼, 패키지명, 환경변수명은
  원래 표기를 유지한다.
- `LICENSE`, 외부 라이선스 전문, 공급업체 이용약관처럼 법적 원문인 파일은 임의로
  번역하거나 삭제하지 않는다. 같은 디렉터리의 한국어 안내 문서에서 핵심을 설명한다.

## 문서 메타데이터

정본 문서에는 다음 YAML 앞부분을 둔다.

```yaml
status: current | proposed | deprecated | archived
owner: foundation | identity | intelligence | gongzzang | repository-maintainers
doc_type: guide | runbook | architecture | adr | reference | record | catalog
last_reviewed: YYYY-MM-DD
```

번역본에는 다음 두 항목을 추가한다.

```yaml
source: 상대경로/한국어-정본.md
source_revision: 커밋 또는 문서 버전
```

`status: archived` 문서는 역사 보존용이며 현재 동작·정책을 설명하는 링크의 목적지가
될 수 없다.

## 기록 운영

- 설계 결정을 바꾸는 내용은 먼저 ADR 또는 RFC로 남긴다.
- 조사와 실행 결과는 `records/`에 날짜·범위·결론·근거·후속 작업을 기록한다.
- 장애 기록에는 영향·탐지·완화·근본 원인·재발 방지를 포함한다.
- 릴리스 기록은 버전·변경·검증·롤백 경로를 포함한다.
- 기록은 사실을 보존하지만 기술 기준표·현재 구조·운영 절차를 복제하지 않고 해당
  정본을 링크한다.

## 삭제·이동 정책

문서의 basename과 경로를 코드, 테스트, CI, 다른 문서에서 검색한다. 참조되는 계약과
fixture는 이동하지 않는다. 참조가 없고 정본·운영 절차·현재 구조 설명 역할도 없는 문서는
먼저 `archived`로 표시하고 대체 링크를 남긴 뒤 삭제 여부를 별도 검토한다. 법률·감사·사고
기록은 삭제하지 않는다. 같은 내용을 반복하는 문서는 하나를 정본으로 지정하고 나머지는
링크로 줄인다.

## 유지 장치

문서 색인은 JSON/경로 목록에서 자동 생성하고 CI에서 생성 결과, 상대 링크, 메타데이터,
금지된 기록 경로, 문서의 고립 상태, 번역본의 원문 연결을 검사한다. README는 사용법과
링크만 담으며 동일한 기술 세부사항을 복사하지 않는다.

## 단계적 이행

1. 전체 문서를 소유 영역·유형·언어·상태·참조 여부로 목록화한다.
2. 정본 경로와 중복 문서를 지정하고 고립·폐기 후보를 분류한다.
3. 루트와 각 영역의 지도, 기술 기준표, ADR 색인을 먼저 한글 정본으로 정리한다.
4. architecture, reference, guide, runbook을 순서대로 번역하고 중복 내용을 링크로
   치환한다.
5. records를 추가해 조사·실행·장애·릴리스 사실을 정해진 형식으로 남긴다.
6. 문서 메타데이터·링크·색인·번역 관계를 검사하는 가드를 CI에 연결한다.
7. 모든 추적 문서가 분류되고 한글 정본 또는 보존 사유를 갖췄을 때 완료로 판정한다.

## 완료 기준

- 추적된 사람이 읽는 문서에 담당 영역·유형·상태·검토일이 있다.
- 현재 정책·구조·절차·기술 기준마다 정본이 정확히 하나다.
- 루트와 영역 README에서 정본까지 링크로 도달할 수 있다.
- 상대 링크와 자동 색인이 CI에서 검증된다.
- 한글 정본에 없는 영어 설명문이 남아 있지 않으며, 남은 영어는 코드·식별자·법률
  원문으로 분류되어 있다.
- 번역을 시작할 때 원문 경로와 버전을 추적할 수 있다.
