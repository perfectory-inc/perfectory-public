# ADR 0357: 총괄표제부는 여러 동이 선 대지의 합계로 Silver 에 쌓는다

- Status: Accepted
- Date: 2026-10-30
- Builds on: ADR-0355(연결 순서 2순위), ADR-0356(같은 틀의 첫 레인), ADR-0169, ADR-0318, ADR-0145, ADR-0288

## Context

공장·물류 대지는 한 필지에 여러 동이 서는 경우가 많다. 표제부는 동마다 한 행이라 "이 대지 전체의 연면적·주차 수·
동 수" 를 바로 말하지 못한다. 그 합계를 제공자가 내는 대장이 총괄표제부(`hubgokr__building_register_master`)다.
ADR-0355 는 이것을 지금 연결 2순위로 정했다.

**측정 (2026-10-30, 최신 판 ZIP 전체를 R2 읽기 전용 범위 읽기).** 멤버는 `mart_djy_02.txt`(221,994,202 바이트)다.
**621,193 행이고 모든 행이 64칸이다.** 관리건축물대장PK 621,193 개가 모두 고유하다. PNU 입력이 유효한 행은 621,183 개(99.998%)다.
키 앞 두 자리는 `11` 257,254, `12` 210,663, `10` 153,276 이다. 64칸은 건축HUB 총괄표제부 API(`getBrRecapTitleInfo`)의
항목 64개와 같은 순서다. 표본 행의 값(시군구 27260, 법정동 10600, 주용도 01000 단독주택, 생성일자 20221126)으로 확인했다.
이 원천의 다섯 판 합계는 0.19 GB 다.

## Decision

1. **표 `silver.building_register_master`.** 대지(관리건축물대장PK) 하나가 한 키다. 이름 붙인 칸은 PNU 입력 6개와
   대지·건축·연면적, 주용도 코드·이름, 주·부속 건축물 수, 총주차 수, 허가·착공·사용승인일이다. 값은 제공자 글자
   그대로이고, 64칸 전부를 `raw_columns` 에 남긴다. 칸 9(건물명)는 이름을 붙이지 않는다(ADR-0356 §4 와 같은 이유).
2. **ADR-0356 과 같은 틀이다.** HUB 스트리밍 엔진 어댑터와 명령 `export-building-register-master-silver-handoff` 를 쓴다.
   Silver 갱신 레인은 `building-register-master` 이고, 작업은 `silver_refresh_building_register_master` 다(`changed-keys`,
   켜짐, 일일 수집이 새 판을 받으면 시작). compare 묶음은 키 앞 두 자리로, 실측 세 묶음이다.
3. **소비자는 다음 PR 이다.** 그래프에서 표는 `contract_only`, 엣지는 `partial` 이다. 건물 by-PNU 패널이 대지 합계를
   읽는 PR 이 이 둘을 `implemented` 로 바꾼다.

## Consequences

- **비용(계산).** 판당 원문 0.22 GB 다. 첫 실행 0.6M 행, 이후 바뀐 대지만 쓴다. 월 수십 원 수준이다.
- 부속지번(ADR-0355 3순위)은 이 틀로 바로 잇지 않는다. 실측 5,492,042 행에 키는 1,298,409 개다. 한 키에 최대 2,355 행이 달리고,
  행마다 두 번째 지번(부속 필지)이 있다. 엔진이 두 번째 PNU 를 만들어야 하므로 엔진 확장 PR 이 먼저다.
