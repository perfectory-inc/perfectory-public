# ADR 0185: 세대 가격 묶음은 그것을 만든 두 스냅숏이고, 패널은 한 판의 마지막 묶음을 읽는다

- Status: Accepted
- Date: 2026-10-12
- Amends: [ADR-0182](./0182-the-gold-rebuild-joins-the-unit-prices-and-the-panel-reads-the-newest-vintage.md)
- Builds on: [ADR-0183](./0183-a-release-loaded-in-batches-is-staged-on-a-branch-and-published-at-once.md)(여러 배치 적재의 원자 공개)

## Context

ADR-0182 는 "표가 그 판의 묶음을 이미 가지면 다시 조합하지 않는다"(스냅숏 id 와 무관)와 "한 판에 묶음이 둘이면 거부"를
정했다. 압축으로 스냅숏 id 가 바뀌어도 같은 판을 두 번 쌓지 않으려는 것이었다.

2026-10-11 이 규칙이 잘못된 데이터를 굳혔다. 공동주택가격 202609 판이 6배치 중 2배치만 들어간 채(원자 공개 ADR-0183
이전의 실패한 적재) `main` 에 남아 있었고, 그 사이 Gold 재생성이 그 표로 202609 세대 가격을 조합했다: 7,471만 행(완전한
판은 약 1.9억). 건물 패널은 다른 이유로 실패해 서빙되지 않았다. 그러나 표에 202609 묶음이 생겼으므로, 완전한 판이
실린 뒤에도 "이미 가짐"으로 다시 조합하지 않고, 패널은 반쪽 묶음을 계속 읽게 된다. append-only 이므로 지울 수도 없다.

## Decision

1. **묶음의 정체성은 그것을 만든 두 스냅숏이다.** 조합은 가격·전유부 표의 현재 스냅숏으로 만들 묶음 id
   (`price:<스냅숏>|exclusive:<스냅숏>|vintage:<월>`)가 이미 있을 때만 건너뛴다. 같은 판이라도 다른 스냅숏에서
   만든 묶음뿐이면 다시 조합한다. 압축이 스냅숏 id 를 바꾸면 한 번 더 조합하는 비용을 치른다(옳은 데이터가 우선).
2. **패널은 가장 새 판의 마지막 묶음을 읽는다.** 한 판에 묶음이 여럿이면 표의 `main` 계보에서 나중에 붙은 것을
   고른다(`batch_commit_order`: 적재 기록, 부모 사슬 순서). 그 순서를 알 수 없으면(Iceberg 가 아닌 입력) 고르지 않고
   거부한다.
3. 반쪽 묶음은 지우지 않는다. 기록으로 남고, 더 나중 묶음이 생기면 읽히지 않는다.

## Consequences

- 2026-10-11 의 반쪽 202609 묶음은 공동주택가격 재적재(원자 공개) 뒤의 다음 Gold 재생성에서 완전한 묶음으로 대체된다.
- 원자 공개(ADR-0183)로 반쪽 판이 `main` 에 보이는 일은 다시 없다. 이 결정은 이미 굳은 것을 바로잡고, 같은 판을 새 원천
  스냅숏으로 고쳐 실을 때(정정 재적재)의 규칙이다.
- 시험: `test_unit_official_price`(순서로 고름, 순서 없으면 거부), `test_unit_price_batch_order_iceberg`(실제 Iceberg
  에서 나중 묶음).
