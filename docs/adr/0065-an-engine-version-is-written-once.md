# ADR 0065: 엔진 판 번호는 한 곳에만 적는다

- Status: Accepted
- Date: 2026-08-29

## Context

레이크하우스 Spark 잡이 이틀 동안 JVM 크래시로 죽었다. 원인을 두 번 잘못 짚은 끝에 나온
답은 우리 코드가 아니었다.

```
apache/iceberg#12178  "Incorrect Results and SIGSEGV on Read"  →  1.8.0 에서 수정
우리                                                              1.6.1
```

같은 서버·같은 표·벡터화 켠 채로 **판만 바꿔** 확인했다.

```
iceberg 1.6.1   →  CRASH
iceberg 1.11.0  →  OK
```

**왜 1.6.1 이었나.** 아무도 게을러서가 아니다. 판 번호가 **열두 곳**에 적혀 있었다.

```
Spark 잡           7곳   (각 잡이 자기 DEFAULT_ICEBERG_PACKAGES 를 들고 있었다)
Rust 제출기         2곳
Spark 테스트        1곳
.env.example       1곳
운영 문서           1곳
```

올리려면 열두 곳을 고쳐야 하고, 하나라도 빠뜨리면 **같은 표를 서로 다른 판이 건드린다.**
그 위험을 감수할 이유가 매번 없었으므로 한 번도 올리지 않았다. 그 사이 다섯 판이 지나갔고,
그중 하나에 위 수정이 들어 있었다.

이 형태는 이 저장소에서 오늘만 세 번째다. [[mirrored-lists-are-the-defect]] 와 같은 뿌리다.

```
"이 묶음 넣었음"이 표 밖 파일과 표 안에 두 벌   →  필지 186만 건이 세 벌 (ADR-0062)
나누기 규칙이 Rust·JSON·테스트 세 곳          →  테스트가 옛 값을 물고 있었음 (ADR-0063)
판 번호가 열두 곳                            →  2년간 못 올림 (이 ADR)
```

## Decision

1. Iceberg 판 번호와 아티팩트 좌표는 `infra/lakehouse/contracts/lakehouse-engine.contract.json`
   에만 적는다. `config/` 가 아니라 여기인 이유는 Spark 컨테이너가 `infra/lakehouse/contracts`
   만 마운트하기 때문이다 — 정본이 읽히지 않는 자리에 있으면 사본이 다시 생긴다.

2. Python 은 `lakehouse_engine.iceberg_packages()`, Rust 는
   `lakehouse_engine_contract::iceberg_packages()` 로 읽는다. Rust 쪽은 `include_str!` 로
   **컴파일 시각에** 묻는다. 계약을 못 찾는 제출기는 빌드에서 죽어야지, 돌아가는 적재 앞에서
   죽으면 안 된다.

3. 계약은 `minimum_version` 과 **그 이유**를 함께 싣는다. 그 아래로 내려간 계약은 잡이 뜨기
   전에 거부한다. 이유 없는 최소값은 다음 사람이 지우기 때문이다.

4. 검사는 **"낡았는가"가 아니라 "사본이 생겼는가"를 본다.** 새 판이 나오는 시점은 우리가
   통제하지 않으므로, 최신이 아니면 실패하는 검사는 남의 일정에 우리 CI 가 빨개지는 것이다.
   사본이 생기는 것은 우리가 통제한다.

## Consequences

판을 올리는 일이 한 줄 수정이 된다. 1.6.1 → 1.11.0 이 이 결정의 첫 적용이다.

**두 검사가 붙었고 둘 다 위반을 심어 거부를 확인했다.** 계약 파일과 그것을 읽는 두 모듈
밖에서 판 번호를 적으면 거부되고, 계약이 최소 판 아래로 내려가면 잡이 시작조차 못 한다.

**판을 올린 것 자체는 위험을 남긴다.** 1.6 에서 1.11 은 다섯 단계이고 그 사이 동작이 바뀐 것이
있을 수 있다. 표 전부를 새 판으로 읽고 쓰는 확인을 거쳐 채택했다.

**최신을 자동으로 따라가지는 않는다.** 결정 4가 그것을 의도적으로 배제한다. 판을 올릴지는
사람이 정하고, 이 결정이 보장하는 것은 정할 때 한 곳만 고치면 된다는 것뿐이다. 다음에 또
2년이 지나는 것을 이 ADR 은 막지 못한다 — 막으려면 정기적으로 뒤처짐을 **보고하는** 별도
장치가 필요하며, 그것은 여기서 정하지 않았다.

**적용되지 않은 곳이 있다.** Spark 자체의 판(3.5.6)과 Docker 이미지 태그는 여전히 compose
파일과 이미지 이름에 흩어져 있다. 같은 결정을 적용해야 하지만 이번 변경의 범위가 아니다.
